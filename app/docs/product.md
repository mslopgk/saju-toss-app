# 제품

## 한 줄 가치

사주·MBTI·혈액형·별자리를 한 번에 합쳐 보는 나의 종합 운세.

## 문제

네 체계가 각각 다른 앱·사이트에 흩어져 있어 사용자는 같은 생년월일을 네 번 입력하고 네 개의 결과를 스스로 종합해야 한다. 결과끼리 충돌할 때 해석해 주는 곳이 없다.

## 대상 사용자

`미정` — 리서치(`../../docs/research/08-운세시장-규모와-사용자-트렌드.md`)는 국내 온라인 운세 이용층이 2030 여성 중심이라고 정리했으나, 본 제품의 1차 타깃 세그먼트는 아직 확정하지 않았다.

## 핵심 흐름 (구현됨)

```text
1. 생년월일 + 출생시각 + 성별 + 출생지 입력          → OnboardingPage
   MBTI 유형 + 혈액형 (선택, "모름" 허용)             → 같은 화면 하단
2. computeChart() 동기 계산 (순수함수 · 1ms 미만)
3. 결과 + 규칙 기반 리포트 열람                       → ResultPage
4. [궁합 보기] → 상대방 생년월일시·성별만 입력       → CompatPage (지연 청크)
   computeCompatibility() 동기 계산 (0.035 ms/쌍)
   궁합 점수·등급 + 규칙 기반 궁합 리포트
```

4단계는 **첫 사람을 다시 묻지 않는다** — 3단계에서 이미 만든 `Chart` 와 자기신고 값을 그대로 쓴다.
상대방 화면에는 토스 프리필 버튼이 **없다**(그 경로가 채우는 것은 사용자 본인의 생년월일이다).

1·2 를 한 화면으로 합쳤다. MBTI·혈액형은 **계산에 쓰이지 않는 선택 입력**이라 별도 단계로 끊으면
사주 결과를 보려는 사용자가 필요 없는 화면을 하나 더 지나야 한다.

생년월일은 **양력·음력(윤달 포함)** 을 모두 받는다. 국내 사주 이용층에서 음력 생일은 소수 경로가 아니다.
달력은 날짜 시트 안에서 고른다 — 폼 본문에 토글을 따로 두면 "양력을 골라 둔 채 음력 날짜"가 잠깐 존재한다.
음력을 고르면 월 휠이 **그 해에 실제로 있는 달만** 보여 주고(2023년이면 `1월 2월 윤2월 3월 …`),
행과 시트에 **환산된 양력 날짜를 함께** 적는다. 윤달을 잘못 골랐는지 사용자가 확인할 단서가 그것뿐이다.

### 원터치 경로 (토스 정보로 채우기)

같은 화면 상단에 CTA 를 하나 둔다. 누르면 토스 동의 데이터로 **생년월일·성별**을 채운다.

```text
[토스 정보로 채우기] → 생년월일·성별 프리필
                     → "이 날짜가 양력이 맞나요?" 확인      ← 건너뛸 수 없다
                     → 남은 필수 입력은 출생시각 하나뿐
                       ("시간을 모르겠어요" 를 고르면 그 자리에서 [결과 보기] 가 열린다)
```

결과까지의 조작 (시각을 모르는 경우):

| 경로 | 조작 |
|---|---|
| 수동 | 태어난 날 행 → 양력/음력 → **휠 3열 스크롤**(년 201개·월·일) → 선택 완료 → 시각 행 → "시간을 모르겠어요" → 성별 → 결과 보기 |
| 원터치 | 토스 정보로 채우기 → 양력 확인 → 시각 행 → "시간을 모르겠어요" → 결과 보기 |

원터치가 없애는 것은 탭 수보다 **휠 조작**이다. 1995년을 고르려면 201칸짜리 년도 휠을 굴려야 하고,
그게 이 화면에서 가장 오래 걸리는 동작이다. 성별 선택도 함께 사라진다.
양력 확인은 탭 1회를 **일부러** 쓴다 — 아래 이유로 건너뛸 수 없는 단계다.

확정 사항:

- **가져오는 것은 생년월일·성별뿐이다.** 이름·연락처·이메일·주소는 요청하지 않는다. 특히 `USER_ADDRESS`
  는 **거주지**라 출생지로 쓰면 진태양시 보정 경도가 틀린다 — 출생지는 계속 사용자가 고르고 기본값은 서울이다.
- **양력 확인은 건너뛸 수 없다.** 토스 데이터에는 그 날짜가 양력인지 음력인지 알려주는 필드가 없고,
  음력 날짜도 대개 실재하는 양력 날짜라 어느 쪽으로 읽어도 거절되지 않은 채 **다른 사주가 조용히 나간다**.
  엔진이 음력을 지원해도 이 문제는 그대로다 — 달력 종류를 아는 것은 사용자뿐이다.
  확인 전에는 `결과 보기` 를 잠근다. "아니요(음력이에요)"를 고르면 **같은 날짜를 음력으로 읽는다**
  (등록할 때 음력을 적었다는 뜻이므로 그 세 숫자가 곧 음력 날짜다). 날짜를 버리지 않으므로 다시 입력할
  필요가 없다. 다만 **윤달 여부는 토스 데이터로 알 수 없어** 평달로 두고, 폼이 윤달 확인을 요청한다.
  음력에 없는 날짜(31일 등)면 그때만 날짜를 비우고 수동 입력으로 되돌린다.
- **프리필된 값도 그대로 고칠 수 있다.** 잠그지 않는다.
- **버튼은 쓸 수 있을 때만 보인다.** 토스 앱 버전이 낮거나(5.264.0 미만) 동의 항목 키가 설정되지 않았으면
  버튼 자체를 그리지 않는다. 실패를 토스트로 알리지 않는다. 현재는 콘솔 키가 미발급이라 **보이지 않는다.**
- 결정 기록: [decisions/0004-toss-prefill-boundary.md](./decisions/0004-toss-prefill-boundary.md)

확정된 입력 요구사항:

- **출생시각은 시주(時柱)와 달별자리·상승궁에 필수**다. 모르면 삼주(三柱) 모드로 축소하고 상승궁은 산출하지 않는다. 근거: 상승궁은 시각 미상 시 정답률이 무작위와 같다(`C19`).
- **출생지 좌표가 필요하다.** 진태양시 보정에 경도를 쓴다. 기본값은 서울.
- **MBTI 검사는 제공하지 않는다.** 사용자가 이미 아는 유형을 16개 중에서 고른다. 상표권 리스크를 낮추는 선택이기도 하다(`../../docs/research/05-MBTI-데이터와-상표권-리스크.md`). 16유형 별칭(16Personalities 계열)은 화면에 노출하지 않는다 — NERIS 저작물이다.
- **혈액형은 성격 판정에 쓰지 않는다.** 리포트 **문장의 말투**만 정한다. 근거: `C18`(縄田健悟 2014, n=11,729)이 반증을 확정했다. 입력 화면과 리포트 본문, 면책 문구 세 곳에서 이 사실을 밝힌다.

## MVP 범위 (현재 구현 상태)

과금 방향은 `미정` — 리서치 브리프가 3안(무료+광고 / 유료 단건 리포트 / 구독)을 비교했으나 확정하지 않았다.
확정 전에는 과금 관련 화면을 만들지 않는다. 아래는 **코드로 존재하는 것**이다.

| 범위 | 상태 | 근거 |
|---|---|---|
| 입력 온보딩 (생년월일시·성별·출생지) | ✅ | `features/onboarding` |
| MBTI·혈액형 선택 입력 ("모름" 허용) | ✅ | 같은 폼 하단 · `MbtiSheet` |
| 토스 정보로 생년월일·성별 프리필 | ⏸ | 코드는 완성(`shared/api/tossUser` + `tossPrefill`). **동의 항목 키 미발급**이라 버튼이 노출되지 않는다 |
| 계산 엔진 S0~S8 전 구간 | ✅ | `shared/lib/saju` · 골든셋 회귀 통과 |
| 결과 화면 (4기둥·십신 이름·납음·절기·대운표·경고배지) | ✅ | `pages/ResultPage` |
| **규칙 기반 리포트** (LLM·서버 없이 동작) | ✅ | `features/report` + `shared/interpret/template.ts` |
| **신강신약 · 격국 · 용신** (오행 점수·SI·등급·용신 오행) | ✅ | 엔진 S5 `strength.ts` → 리포트 `strength` 섹션 |
| LLM 리포트 | ⏸ | 서버(`../../server`)·실호출 검증 완료(claude-opus-5, 6섹션·카드 14장 인용·캐시 히트). **서버 미배포**라 앱은 규칙 기반으로 폴백 중 |
| **궁합(2인 비교)** | ✅ | 엔진 S8 `shared/lib/compat` + `features/compat` + `pages/CompatPage`. 배점 전량 `compat-params.json`(C18). 10만 쌍 홀드아웃 분포 검증 통과 — [compat.md](./compat.md) |
| 신살 · 별자리 | ✅ | 엔진 S4-2 `sinsal.ts` / S7 `astro.ts` → 리포트 `sinsal`·`zodiac` 섹션 |
| **음력 입력** (양력·음력·음력 윤달) | ✅ | C00 A7 음력 표 1899~2100 자체 생성(430 B). 왕복 전수 검증 통과 |

### 규칙 기반 리포트가 내는 섹션

엔진 v1 이 실제로 내는 값만으로 채운다. 근거 카드가 없는 섹션은 **만들지 않는다**(빈 섹션을 숨기는 게 아니라
애초에 생성하지 않는다).

렌더러가 낼 수 있는 섹션은 **11개**이고 순서는 `template.ts` 의 `SECTION_ORDER` 가 고정한다.

| 섹션 id | 제목 | 근거 | 자기신고 필요 |
|---|---|---|---|
| `saju` | 일간(日干)과 여덟 글자 | `ilgan:*` 카드 + S3 일간 | — |
| `sipsin` | 십신 배치 | `sipsin:*` 카드 + S4-1 기둥별 룩업 | — |
| `jiji` | 지지에 담긴 기운 | `jiji:*` 카드 + S3 일지·월지 | — |
| `sinsal` | 여덟 글자에 붙은 이름표(신살) | S4-2 신살 + `sinsal:*` 카드 | — |
| `strength` | 신강신약과 용신 | S5 오행 점수·SI·등급·격국·용신 + `unseong:*`·`yongsin:*` 카드 | — |
| `luck` | 대운의 흐름 | S6 대운 간지·나이·방향 + `daewoon:방향:*` 카드 | — |
| `zodiac` | 별자리 | S7 태양궁 + `zodiac:*` 카드 | — |
| `mbti` | MBTI | `mbti:{코드}` 카드 | MBTI |
| `blood` | 혈액형(말투) | `blood:문체:{형}` 카드 | 혈액형 |
| `intersection` | 네 체계가 공통으로 가리키는 당신 | 체계 간 **합치**가 실제로 잡힐 때만 | — |
| `conflict` | 그런데 딱 하나, 어긋나는 지점 | 체계 간 **불일치**가 실제로 잡힐 때만 | — |

`intersection`·`conflict` 는 사람마다 나오기도 안 나오기도 한다 — 합치/불일치가 없으면 만들지 않는다.

실측(1990-05-15 14:30 서울 남, 이 사례는 `intersection` 이 잡히지 않았다):
자기신고 없음 **8섹션 3,265자 / 근거 카드 35장**, MBTI·혈액형 포함 **10섹션 4,029자 / 42장**.

신강신약 섹션의 **수치는 엔진 값을 그대로 옮긴다** — 오행 점수 5개와 신강지수 1개뿐이고, 렌더러는
정렬도 임계값 판정도 하지 않는다(오행은 항상 木火土金水 고정 순서). 종세격·전왕격처럼 지식카드가 없는
특수격은 이름만 적고 설명을 지어내지 않는다. 이 두 규율은 실제 사주 약 2,200건 스윕으로 고정돼 있다
(`template.test.ts` 의 "전 구간 스윕").

## 반드시 지킬 고지

운세 콘텐츠이며 과학적 예측이 아니라는 면책, 그리고 혈액형 성격론에 과학적 근거가 없다는 사실을 명시해야 한다. 후자는 리서치에서 학술적으로 확인됐다(`C18`: Nawata 2014 η²<0.003 등). 법적 요건은 `../../docs/research/09-법률-규제-개인정보-면책.md` 참고.

구현 위치. 1인 리포트 쪽은 전부 `shared/interpret/copy.ts` 의 `DISCLAIMERS` 한 곳에서 나오고,
궁합 쪽은 `features/compat/copy.ts` 의 `COMPAT_DISCLAIMERS` 한 곳에서 나온다 — 문구가 화면마다
달라지면 안 되기 때문이고, 두 파일로 나뉜 이유는 **말하는 내용이 다르기** 때문이다(궁합은
"관계를 예측하지 않는다" 를 말해야 한다).

| 화면 | 문구 |
|---|---|
| 온보딩 CTA 위 | "운세 콘텐츠예요. 과학적 예측이 아니에요." |
| 온보딩 혈액형 입력 아래 | "혈액형과 성격의 관계는 확인된 근거가 없어요. 이 앱에서 혈액형은 문장의 말투만 정해요." |
| 리포트 혈액형 섹션 본문 | 같은 사실을 문장으로 다시 밝힌다 |
| 상대방 입력 혈액형 아래 | "혈액형 궁합은 과학적 근거가 없어요. 배점에는 넣되 비중을 10%로 두고, 결과 화면에서 그 사실을 다시 밝혀요." |
| 궁합 결과 면책 | **"혈액형 궁합은 과학적 근거가 없습니다."** — 이 문구는 혈액형을 배점에 남긴 제품 결정(BL-3)의 **조건**이다. 지우려면 매트릭스를 균등으로 바꾸는 것이 먼저다([decisions/0005](./decisions/0005-compat-blood-and-ecdf.md)) |
| 궁합 결과 면책 | "점수가 낮다고 해서 함께하기 어렵다는 뜻이 아닙니다." |
| 결과 화면 하단 "알아두실 점" | `DISCLAIMERS` 4줄 전문 + 엔진 버전 |

리포트 본문에는 면책 문구를 **넣지 않는다** — 앱이 고정 위치에 붙인다(문서10 §9: 문구가 생성기마다 달라지면 안 된다).
같은 이유로 규칙 렌더러의 출력도 `guard.ts` 의 금지 표현 목록으로 검사한다(`template.test.ts`).
