# 0003. 계산 진실값은 DE440s 사전계산 테이블

- 날짜: 2026-08-12
- 상태: 확정
- 원 명세: `../../../docs/research/calc/C00-계산엔진-통합명세서.md` §B

## 문제

절입(節入) 시각이 틀리면 월주·연주·대운수가 전부 틀어진다. 어느 구현을 진실값으로 삼을 것인가.

## 선택지

1. `manseryeok` npm 패키지 값
2. `lunar-javascript` 값
3. KASI 공표값 (공공데이터포털)
4. **Skyfield + DE440s 로 사전계산한 테이블**

## 결정

**4안.** 런타임 천문계산은 금지하고 사전계산 테이블을 이분탐색한다.

## 근거 (실측)

- `lunar-javascript` 의 절기는 **중국 표준시(UTC+8)** 기준이라 KST 입력 시 정확히 60분 어긋난다. 2024 입춘 16:27:07 vs KASI 17:27.
- `manseryeok` 은 절입시각을 **분 단위로 반올림 저장**한다. 골든셋 회귀에서 실패 13건이 전부 "절입이 속한 분" 케이스였다(2024 입춘 실절입 :07초, 청명 :17초 등). 통과율 244/257 = 94.94%.
- KASI 미러 데이터셋(`distbe/holidays`)은 2020 춘분이 `03:20` 으로 오기돼 있고(실제 12:49), 일부 연도의 `sunLng` 가 전부 null 이다.
- 자체 오라클(DE440s 테이블 + `ref.mjs`)은 골든셋 **280/280 = 100%**, 프로덕션 축 **321/321**.

## 부수 효과

- 테이블 커버리지 밖(현재 1851~2145)의 입력은 **거부**한다. 폴백 계산을 두지 않는다 — 폴백은 조용한 오답을 만든다.
- 절기 테이블은 태양궁(12궁) 판정에도 그대로 쓴다. 12궁 경계 황경 {0,30,…,330}이 24절기 중 12중기와 정확히 같기 때문에 **추가 데이터가 필요 없다**(`C19` 30만 표본 대조 불일치 0).

## 주의

`manseryeok` 을 쓰더라도 `trueSolarTime` 옵션을 넘기지 않으면 경도·균시차·표준시 이력·서머타임이 **전부 꺼진다**. 1954~61 코호트에서 시주 오류 15.2%, 1987~88 에서 22.8%. 기본값 의존은 선택지가 아니다.
