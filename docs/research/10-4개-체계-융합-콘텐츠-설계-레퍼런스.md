## 0. 이 문서의 결론 먼저 (TL;DR)

1. **4체계 중 "별자리"는 사실상 독립 축이 아니다.** 별자리(12분할, 태양황경 기준)와 사주 월지(12분할, 절기 기준)는 같은 태양년을 12로 나눈 것이며 약 15일 정도만 어긋난다. 즉 생년월일만 받으면 별자리는 월지의 재표현(re-expression)에 가깝다. → 콘텐츠 설계상 **별자리는 "월지의 서양식 번역 레이어"로 쓰는 것이 정직하고 저렴하다.** [창작 필요 / 논리적 도출]
2. **입력 독립성이 실제로 있는 축은 3개**: (a) 생년월일시 → 사주 + 별자리, (b) MBTI 4글자(사용자 자기신고), (c) 혈액형(사용자 자기신고). 즉 사용자 입력 폼은 3필드면 충분하다.
3. **경우의 수는 4.6만 ~ 3.98억.** 전수 집필은 불가능. → **부품(fragment) 조합 + 규칙 기반 슬롯 + LLM 윤문**의 하이브리드가 유일한 현실 해법. (§5)
4. **학술적으로 "근거 있음"이라 말할 수 있는 매핑은 딱 두 갈래뿐**이다: ①오행 목·화↔외향(E) / 금·수↔내향(I) ②Keirsey 기질↔MBTI 중간 2글자(이건 정의 자체). 나머지는 전부 창작이다. 그래서 **UI 카피에서 "과학적 근거" 워딩을 쓰면 안 된다.**
5. 혈액형↔성격은 대규모 연구에서 **사실상 무효과**로 결론났다(§3.4). → 혈액형은 "성격 판정 축"이 아니라 **말투/톤 조미료(flavor)** 로만 써야 리스크가 없다.

**제품 구현용 정규화 공식 (창작)**
```
E_score = (목 개수 + 화 개수) / 8        # 사주팔자 8글자 중 비율
I_score = (금 개수 + 수 개수) / 8
S_score = (화 개수 + 금 개수) / 8        # A2 근거
EI_saju = E_score - I_score              # -1.0 ~ +1.0
```
→ 이 값을 사용자가 자기신고한 MBTI의 E/I와 **일치/불일치**로 비교하는 것이 §4의 "교집합/충돌" 서사의 핵심 재료.

**핵심 발견 3가지:**

1. **Keirsey 본인은 4원소와 대응시키지 않았다.** Wikipedia 「Four temperaments」에 따르면 Keirsey는 그리스 신 이름을 썼다: **Promethean(Technological)→Rational(NT), Apollonian(Soulful)→Idealist(NF), Dionysian(Artful)→Artisan(SP), Epimethean(Dutiful)→Guardian(SJ)**. 4원소 대응은 **후대 블로거/2차 저작의 창작**이다. **[중요 — 창작 필요]**

## 3. 4체계를 하나로 합치는 계산 모델

### 3.1 공통 잠재 축(Common Latent Axes)으로 사영

4체계를 직접 곱하지 말고, **공통 6축 벡터**로 각각 사영한 뒤 합산한다.

```
공통 축: [EI, SN, TF, JP, 활력(Yang), 안정(Stability)]   // 각 -1.0 ~ +1.0

사주   → f_saju(사주팔자)   : 오행 개수/월지/일간/십신 → 6축      (가중치 w1)
MBTI   → f_mbti(4글자)      : EI/SN/TF/JP 직접 매핑, 활력/안정은 파생 (가중치 w2)
별자리 → f_zodiac(원소)     : 융 매핑 (불=N, 흙=S, 공기=T, 물=F)  (가중치 w3)
혈액형 → f_blood(A/B/O/AB)  : 6축 기여 0, 문체 파라미터만 반환      (가중치 w4=0)

최종 = normalize(w1*f_saju + w2*f_mbti + w3*f_zodiac)
```

**권장 가중치 [창작 필요]**
| 축 | 가중치 | 근거 |
|---|---|---|
| 사주 | 0.45 | 앱의 핵심 자산이자 입력 정보량이 가장 큼(8글자) |
| MBTI | 0.40 | 사용자 자기신고 = 자기인식과 가장 일치 → 체감 정확도 방어선 |
| 별자리 | 0.15 | 월지와 정보 중복 → 낮게 |
| 혈액형 | 0.00 (톤만) | A3/A4 반증 |

> **MBTI 가중치를 낮추면 안 되는 이유**: 사용자가 스스로 입력한 값과 결과가 어긋나면 즉시 "안 맞네"로 이탈한다. 자기신고 축은 **정확도 체감의 앵커**다.

### 3.2 일치도 점수(Coherence Score) — 화면의 주인공

4체계가 같은 방향을 가리키는 정도를 0~100으로 계산해 **"당신의 4체계 일치도 78%"** 를 리포트 최상단 히어로로 쓴다.

```
axis_agreement(a) = 1 - (표준편차(saju_a, mbti_a, zodiac_a) / 최대표준편차)
Coherence = round(100 * mean(axis_agreement(a) for a in [EI, SN, TF, JP]))
```

| 구간 | 라벨 | 서사 전략 |
|---|---|---|
| 85~100 | "한 방향형" | "네 체계가 모두 같은 말을 합니다" → 강한 단정 톤 허용 |
| 65~84 | "주도형+보조" | 다수 축 서술 후 소수 축을 "숨은 면"으로 |
| 45~64 | "이중구조형" | "겉과 속이 다른 사람" 서사 (사용자 만족도 높음) |
| 0~44 | "다면체형" | "한 단어로 규정되지 않는" 서사, 희소성 강조 |

> 핵심: **일치도가 낮아도 부정적으로 읽히지 않게 라벨링**해야 한다. 낮은 점수가 "당신은 특이하다 = 희소하다"로 번역되면 오히려 공유 유인이 커진다. [창작 필요]

### 3.3 충돌(Conflict) 처리 서술 전략

| 충돌 패턴 | 예시 | 서술 전략 | 문장 템플릿 |
|---|---|---|---|
| 사주 vs MBTI 상충 | 사주 금수 강함(I) vs 자기신고 ENFP | **"타고남 vs 만들어진 나"** 프레임 | "타고난 기운은 {A}인데, 지금의 당신은 {B}로 살고 있어요. 그건 당신이 스스로 만든 부분이에요." |

1. **모순을 결함이 아니라 "층(layer)"으로 번역한다.** "A인데 B다" ❌ → "겉은 A, 안은 B" ⭕
2. **시간축으로 분리한다.** "평소엔 A, 중요한 순간엔 B"
3. **상황축으로 분리한다.** "일에서는 A, 관계에서는 B" — 이건 Forer 진술문 #3("At times you are extroverted... while at other times you are introverted, wary, reserved")의 구조 그대로다. **바넘 효과가 가장 강하게 작동하는 문장 형식이 바로 충돌 서술 형식**이라는 점이 중요하다.

### 4.2 조합 폭발 해결 4단계

**Step 1 — 축 추상화 (차원 축소)**
```
사주 60갑자 → 오행 5 × 음양 2 = 10 (일간)  → 더 줄이면 오행 5
MBTI 16    → Keirsey 기질 4 (SP/SJ/NF/NT)
별자리 12  → 4원소
혈액형 4   → 문체 4 (본문에는 미기여)

핵심 조합 = 5(오행) × 4(기질) × 4(원소) = 80
문체 변주 포함 = 80 × 4 = 320
```
→ **80개 본문 코어**만 만들면 4체계 융합의 뼈대가 완성된다.

**Step 2 — 부품 조합(Fragment Composition)**
전체 문장을 통째로 쓰지 않고 슬롯 단위로 조립.
```
단일 부품:   일간 10 + MBTI 16 + 혈액형 4 + 별자리 12          =    42
쌍(pair) 부품: 10×16 + 10×4 + 10×12 + 16×4 + 16×12 + 4×12
             =  160 +  40 +  120 +  64 +  192 +  48            =   624
삼중은 만들지 않음 (조합 폭발의 시작점)
총 자산                                                        =   666 조각
```
666개 조각으로 46,080 조합을 커버한다 (**압축률 약 69배**).
> 참고: 일간을 60갑자로 확장하면 단일 92 + 쌍 2,224 = **2,316 조각**.

**Step 3 — 결정론적 시드 + 변주(Variant Pool)**
같은 사용자가 같은 날 두 번 보면 같은 글이 나와야 한다(신뢰). 다른 날엔 달라야 한다(재방문).
```js
// 결정론적 선택: 같은 입력+같은 날짜 → 항상 같은 결과
const seed = hash(`${birthISO}|${mbti}|${blood}|${zodiac}|${dateKey}`);
const variant = fragmentPool[key][ seed % fragmentPool[key].length ];
// dateKey: 'daily' → YYYY-MM-DD, 'weekly' → YYYY-Www, 'monthly' → YYYY-MM
```

| **A. 순수 규칙 기반 템플릿** | 0원, <10ms, 100% 결정론적, 검열 리스크 0, 오프라인 가능 | 문장이 딱딱함, 티가 남(같은 구문 반복), 조합 티어 늘리면 자산 폭증 | ₩0 | 데일리 운세에 최적 |
| **B. 순수 LLM 생성** | 자연스러움, 자산 제작 부담 최소 | 매 호출 과금, 지연 1~5초, 비결정론(같은 입력 다른 답 → 신뢰 훼손), 환각(없는 십신 언급), 안전성 리스크 | 호출당 과금 | 단독 사용 비권장 |

### 5.1 권장 파이프라인

```
[1] 계산 레이어 (규칙, 결정론)
    생년월일시 → 만세력 → 사주팔자 → 오행 개수/일간/월지/십신
    + MBTI 4글자 + 혈액형 + 별자리
    → 공통 6축 벡터 + Coherence Score + 충돌 패턴 ID
    ※ 이 레이어에서 LLM 절대 사용 금지 (환각 = 서비스 신뢰 붕괴)

[2] 부품 선택 레이어 (규칙, 시드 결정론)
    축 값 + 패턴 ID → fragment key 목록 → 시드로 변주 선택
    → 구조화된 "사실 팩(fact pack)" JSON 생성

[3] 문장 조립 레이어 (템플릿)
    fact pack + 혈액형 문체 파라미터 → 초벌 텍스트

[4] 윤문 레이어 (LLM, 선택적/오프라인)
    "아래 사실을 바꾸지 말고 {문체}로 자연스럽게 다듬어라. 
     새로운 사실을 추가하지 마라." 
    → 결과를 캐시에 저장(조합 키 기준)
    → 런타임에는 캐시 히트만 사용 → 실시간 LLM 비용 0
```

### 5.2 프리컴퓨트 캐시 전략

정적 콘텐츠(성격 리포트)는 **조합 키 단위로 미리 생성해 CDN/KV에 박아둔다.**
```
캐시 키:  {일간}|{MBTI}|{혈액형}|{별자리원소}  →  10 × 16 × 4 × 4 = 2,560 엔트리
          (별자리 12 전부 쓰면 10×16×4×12 = 7,680 엔트리)
1엔트리 2KB 가정 → 7,680 × 2KB ≈ 15MB   ← 앱 번들/KV에 통째로 넣어도 됨
```
→ **성격 리포트는 완전 오프라인/무과금 처리 가능.** LLM 실시간 호출이 필요한 곳은 "AI 추가 질문" 같은 유료 상위 기능뿐이다.

동적 콘텐츠(오늘의 운세)는 날짜 축이 붙어 캐시가 커지므로 **일 단위 배치 생성**:
```
일별 캐시 = 오행5 × 기질4 × 원소4 = 80 엔트리/일  (혈액형은 문체 → 런타임 치환)
365일 × 80 = 29,200 엔트리/년 → 배치로 미리 생성 가능
```

### 5.3 LLM 사용 시 프롬프트 가드레일 (필수)

```
[SYSTEM]
너는 운세 텍스트 윤문기다. 다음 규칙을 반드시 지켜라.
1. 입력 fact_pack에 없는 사실(십신, 대운, 신살, 궁합 등)을 새로 만들지 마라.
2. 질병/사망/임신/투자수익/법적결과/시험합격 여부를 단정하지 마라.
3. "과학적으로 증명된", "연구 결과" 같은 표현을 쓰지 마라.
4. 부정 서술 뒤에는 반드시 행동 제안 1개를 붙여라.
5. 출력은 {문체}로, {글자수}자 ±10% 이내.
6. 2인칭 "당신/○○님"을 사용하고 단정형과 완곡형을 7:3으로 섞어라.
```

## 6. 바넘 효과 기반 카피라이팅 원칙

### 6.1 검증된 사실 (Wikipedia Barnum effect 확인)

- Forer(1948): **n=39**, 전원 동일한 13개 진술문, 정확도 평균 **4.30/5.0**.
- 효과를 강화하는 **3대 조건**:
  1. 피험자가 **분석이 자신에게 개인화되었다**고 믿을 것
  2. 평가자의 **권위**에 대한 신뢰
  3. **긍정 특성의 높은 비율**
- 추가 강화 요인: **"at times" 같은 양가적(hedging) 표현**, 승인 욕구가 높은 개인에게서 더 강함.
- 반대로, **바넘 효과가 인지 편향임을 사전 고지하면 정확도 평가가 떨어진다** → 앱 내 "재미로 봐주세요" 문구의 배치 위치가 체감 정확도에 영향을 준다. (법적 안전 vs 몰입도의 트레이드오프)

**Forer 원문 진술 예시 (영문 원문)**
```
"You have a great need for other people to like and admire you."
"You have a tendency to be critical of yourself."
"At times you are extroverted, affable, sociable, 
 while at other times you are introverted, wary, reserved."
```

### 6.2 좋은 운세 문구의 4단 구조 [창작 필요 / 위 근거에서 유도]

```
① 구체적 관찰 (Specific Hook)   — 사주/MBTI에서 나온 "계산된" 사실을 먼저 던진다
② 양가 서술 (Hedged Duality)    — "~한 편이지만, 때로는 ~"  ← Forer #3 구조
③ 긍정 재해석 (Positive Reframe) — 약점을 자원으로 번역
④ 행동 제안 (Actionable)        — 오늘/이번 주 할 수 있는 1가지
```

**실제 문구 예시 (병화 일간 × ENFP × O형 × 사자자리)**
```
① 당신의 일간은 병화(丙火), 사주 8글자 중 불의 기운이 3개예요.
② 사람들 앞에서는 누구보다 밝게 타오르지만, 
   혼자 있는 밤에는 그 불이 얼마나 빨리 식는지 스스로 알고 있죠.
③ 그건 에너지가 부족해서가 아니라, 당신의 불이 '연료'가 아니라 
   '순간의 온도'로 타는 종류이기 때문이에요.
④ 오늘은 하루를 시작하는 30분보다 '끝내는 30분'을 정해두세요. 
   불은 끄는 법을 아는 사람 손에서 가장 오래 갑니다.
```

### 6.3 카피 금지어 / 권장어 대응표

| 금지 | 이유 | 대체 |

> 포스텔러 사례(B2)가 **"2026 병오년 신년운세" + "매일 업데이트 오늘의 운세" + "월별 신규 콘텐츠"** 3층 구조를 쓰고 있음이 확인된다. 이 3층은 사실상 업계 표준으로 보인다.

### 7.2 재방문 훅 설계 [창작 필요]

1. **미완결 슬롯(Open Loop)**: 오늘 리포트 하단에 "내일은 당신의 {십신} 기운이 바뀝니다" 예고 → 다음 날 확인 유인.
2. **연속 출석 스트릭**: 7일 연속 확인 시 "심층 리포트 1회 무료" — 운세는 습관 상품이므로 스트릭 궁합이 좋다.
3. **일진 변화 알림**: 사용자 일간과 **충(沖)/합(合)** 관계인 날에만 푸시 → 연 평균 60~90일. 매일 푸시보다 반응률이 높고 스팸 인식이 낮다.
4. **친구 궁합 초대**: 4체계 궁합은 조합 수가 커서 공유 유인이 강하다. 궁합 계산은 두 사람의 6축 벡터 코사인 유사도로 처리.
   ```
   궁합 = 0.5 * cosine(vecA, vecB) + 0.3 * saju_relation(일간A, 일간B) + 0.2 * mbti_pair_table
   ```
5. **연말/신년 압축 회고**: "2026년 당신의 4체계 리포트" — 연 1회 최대 매출 구간.

### 7.3 주기 콘텐츠의 결정론 규칙

```
daily   : seed = hash(userKey + 'D' + YYYY-MM-DD)   // 하루 안엔 불변
weekly  : seed = hash(userKey + 'W' + ISOweek)
monthly : seed = hash(userKey + 'M' + YYYY-MM)      // 절입일 기준 권장
yearly  : seed = hash(userKey + 'Y' + 입춘기준년)
```
**중요**: 월간/연간은 **양력 1일/1월 1일이 아니라 절입일/입춘 기준**으로 갱신하는 것이 명리학적으로 정합하다. 다만 UX상 혼란이 있으므로 "입춘(2/4)부터 새 해의 기운이 시작됩니다" 같은 설명 카드를 함께 노출한다.
