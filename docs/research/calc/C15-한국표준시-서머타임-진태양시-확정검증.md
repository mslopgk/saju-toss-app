## 2. 표준시 전환 — 전수 실측

### 2.1 실행: 1900~2000 전 구간 오프셋 전환 이분탐색

```javascript
// scan2.mjs 핵심
const fmt=new Intl.DateTimeFormat('en-CA',{timeZone:'Asia/Seoul',/*...*/hour12:false});
function offsetSec(t){                                     // t: 초 정렬된 ms
  const p=Object.fromEntries(fmt.formatToParts(new Date(t)).map(o=>[o.type,o.value]));
  let h=+p.hour; if(h===24)h=0;
  return (Date.UTC(+p.year,+p.month-1,+p.day,h,+p.minute,+p.second)-t)/1000;
}
// 1시간 격자 스캔 → 변화 감지 시 1초 정밀 이분탐색
```

### 2.3 ⚠️ C01 정정 — ~~오류 2건~~ → **오류 1건 (1954 건은 C15 자신이 오류였다)**

| C01 기재 | 실측 확정값 | 영향 |
|---|---|---|
| §1.2 #1: 1908-03-31 **15:30Z**, LMT → +8:30 | **1908-03-31T15:32:08Z** (LMT = `8:27:52` = 507.8667분) | 1908-04-01 00:00:00~00:02:07 벽시계가 **부재**. C01은 이 갭을 놓침. ✅ **C15 판정 유지** (C20의 1차 사료도 시각을 규정하지 않아 舊 시계 00:00 관례가 유지됨) |
| ~~§1.2 #4: 1954-03-20 **15:30Z**, 로컬 `1954-03-21 00:30 → 00:00`~~ | ~~**1954-03-20T15:00:00Z**~~ → 🔴 **C01이 옳았다. C15의 이 행은 오답이다.** 대통령령 제876호 `午前零時三十分부터` → **1954-03-20T15:30:00Z**, 로컬 `1954-03-21 00:30 → 00:00` | **C15가 C01을 잘못 정정했다.** C20 §2 참조 |

> **요약**: 본 절이 C01의 1954 관련 기재를 「오류」로 정정했으나, C20이 대통령령 제876호 원문을 확보한 결과 **C01의 원래 값이 정확했고 본 절의 정정이 오류였다.** 1908 건(#1)만 유효한 정정으로 남는다.

## 6. 균시차(EoT) — 고정밀 기준 대비 실측

### 6.1 [E-0] 기준(REFERENCE) 구현 — `astronomy-engine` v2.1.19 (MIT, Don Cross)

NOAA/Meeus 저정밀식 자체를 검증하려면 **더 정확한 독립 구현**이 필요하다. 겉보기 항성시(GAST)와 태양 겉보기 적경(α)에서 직접 유도:

```javascript
import * as A from 'astronomy-engine';
const norm180=x=>{x=((x%360)+360)%360; return x>180?x-360:x;};
export function eotReference(dateUTC){
  const gastH = A.SiderealTime(dateUTC);                        // 겉보기 그리니치 항성시 [h]
  const obs = new A.Observer(0,0,0);
  const eq  = A.Equator(A.Body.Sun, dateUTC, obs, true, true);  // ofdate=true, aberration=true
  const utHh = ((dateUTC.getTime()/3600000) % 24 + 24) % 24;
  return 4*norm180(gastH*15 - eq.ra*15 + 180 - utHh*15);        // [분]
}
```

유도: 진태양시 AST = GHA☉ + 180°, GHA☉ = GAST − α_app, 평균태양시 = UT. ⇒ `EoT = (GAST − α_app + 180°) − UT`. 4를 곱해 분 단위.

### 9.2 벽시계 → UTC 후보 해석기 (갭/오버랩 판정)

```typescript
/** 벽시계(ms, UTC 필드로 표현) → 가능한 UTC 후보 전부. 0개=GAP, 2개=OVERLAP */
export function resolveKR(wallMs:number){
  const cands:{utc:number,std:number,dst:number}[]=[]; const seen=new Set<number>();
  for(const s of KR_TIMELINE){
    const off=s[1]+s[2];
    const utc=wallMs-off*60000;
    const a=krOffsetAt(utc);
    if(a.std+a.dst===off && !seen.has(utc)){ seen.add(utc); cands.push({utc,std:a.std,dst:a.dst}); }
  }
  cands.sort((a,b)=>a.utc-b.utc);
  return cands;
}
```

  else if(mode==='LONGITUDE')tMs = utcMs + 4*lon*60000;          // 지방평균태양시 LMT

> **버그 회피 노트**: 초기 구현은 `T = W − dst + L + E` (C01 §0.2 식 (4))를 그대로 썼는데, **갭 SHIFT_FORWARD 케이스에서 60분 틀렸다**. 항등식 `W − dst + L = UTC + 4λ` 는 `W` 가 **실제 시계판독**일 때만 성립한다. 갭에서는 `W` 가 존재하지 않는 판독이므로 반드시 `UTC + 4λ + E` 로 유도해야 한다. `manseryeok` v2.0.0 `true-solar-time.js` 도 동일하게 `apparentMs = instantUTCms + (longitude*4 + eotMin)*MINUTE_MS` 로 구현되어 있다.

**총 불일치 780분 / 48,255,840분 = 0.001616%**, 그리고 **전부 갭 구간(정답이 존재하지 않는 구간)** 이다.

**확정 판정**
- ✅ `manseryeok` 의 표준시 전환 4개 epoch, DST 12구간, 1955~1960 `+9:30` 처리 모두 **tzdb와 완전 일치**.
- ✅ **오버랩 750분 전부에서 tzdb의 `FIRST` 정책과 동일한 결과**를 낸다(별도 코드 없이 자연스럽게).
- ⚠️ 갭 780분에서는 **후행(전환 後) 오프셋을 적용** → 결과적으로 전환 **前** 순간으로 매핑(§5.2 ③열). 우리 `SHIFT_FORWARD` 와 최대 60분 차이. **일주가 하루 어긋나는 케이스 4건**(1912/1948/1955/1961).
- ⚠️ 1908-04-01 이전 LMT(`+8:27:52`) 미지원 → 1908-03-31 이전 출생은 **32.13분 오차**.
- ⚠️ `DEFAULT_LONGITUDE = 127.5` 는 λ_std(135°) 기준 `L = −30.0분`. 서울(126.9784°, −32.09분)과 **2.09분** 차이.

**대응**: 우리 `normalizeBirthTime()` 이 UTC 순간을 확정한 뒤 `manseryeok` 에는 이미 정규화된 값을 넘긴다(또는 `applyHistoricalDst:false` + 직접 계산). 갭·1908 이전만 우리 로직이 우선한다.
