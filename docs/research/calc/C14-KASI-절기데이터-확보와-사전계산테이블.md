## 1. 데이터 확보

### 1.1 원천 확인 — KASI 공공데이터포털 API

미러 저장소의 소스를 직접 읽어 원천을 확정했다.

`https://raw.githubusercontent.com/distbe/holidays/main/api.ts` (실제 열람):

```ts
interface RawDateInfo {
  dateKind: "01" | "02" | "03" | "04"; // 01: 국경일 02: 기념일 03: 24절기 04: 잡절
  dateName: string;
  isHoliday: "Y" | "N";
  remarks?: string;
  locdate: number;                     // YYYYMMDD
  seq: number;
  kst?: string;                        // only dateKind === "03"  한국표준시간
  sunLongitude?: number;               // only dateKind === "03"  태양황경(도)
}
// ...
const url = new URL(
  `http://apis.data.go.kr/B090041/openapi/service/SpcdeInfoService/${type}`,
);
url.searchParams.append("_type", "json");
url.searchParams.append("solYear", year.toString().padStart(4, "0"));
url.searchParams.append("ServiceKey", apiKey);
url.searchParams.append("numOfRows", "100");
```

→ `kind=3` / `time` / `sunLng` 필드의 정체가 확정됐다.
- `time` = KASI 원본 `kst` 필드를 `"HHmm"` → `"HH:mm"` 로 치환한 것.
- `sunLng` = KASI `sunLongitude`. **단 `raw.sunLongitude || null` 로 변환하므로 `0`(춘분)이 `null` 로 소실된다.**

**판정**: 엔드포인트는 실재하나 인증키 필수. 오류코드 20(키 없음)/30(미등록 키)이 게이트웨이에서 반환된다.

**신청 절차** (문서 기재용, 실제 신청은 미수행 `[미검증]`):
- 서비스 ID: `B090041` / 서비스명 `SpcdeInfoService` (한국천문연구원 특일 정보)
- 오퍼레이션 5종: `getHoliDeInfo`(국경일) `getRestDeInfo`(공휴일) `getAnniversaryInfo`(기념일) **`get24DivisionsInfo`(24절기)** `getSundryDayInfo`(잡절)
- 파라미터: `solYear`(필수) `solMonth`(선택) `numOfRows` `pageNo` `_type=json` `ServiceKey`
- 공공데이터포털(data.go.kr) 회원가입 → 활용신청 → 일반 인증키(Encoding/Decoding) 발급. 개발계정 즉시 승인, 운영계정은 별도 신청.

```ts
const year = new Date().getFullYear();
await generateDateFile(year);
await generateDateFile(year + 1);
```

→ **작업 지시의 "1990~2035 전 연도"는 이 원천으로 달성 불가능하다.** 확보 가능한 최대치가 2004~2026 이다.

### 3.7 부수 확인 — C09 §11.5 미검증 항목 해소

`dist/index.js` 소스에서 직접 확인:

```js
if (birthInfo.trueSolarTime !== undefined) {
  const { trueSolarTime } = birthInfo;
  // trueSolarTime.longitude          : -180 ~ 180
  // trueSolarTime.applyEquationOfTime : boolean (균시차 보정)
  // trueSolarTime.applyHistoricalDst  : boolean (과거 표준시·서머타임 보정)

```

- **진태양시는 옵트인**이다. `trueSolarTime` 을 안 주면 경도·균시차 보정이 **적용되지 않는다** → C09 §11.5 의 관찰("기본값에서는 경도 보정이 시주에 적용되지 않은 것으로 보인다")이 **확정**됐다.
- **한국 표준시 이력·서머타임을 라이브러리가 처리한다** (`applyHistoricalDst`). C09 §8/§11.6 의 "어떤 라이브러리도 해주지 않음 → 자체 구현 필수"는 **정정 필요**. 단 그 구현이 C01 확정안과 일치하는지는 본 문서 범위 밖 `[미검증]`.
- `dayBoundary` 옵션 존재 → 야자시 유파를 인자로 고를 수 있다. 기본 `'midnight'`. `[미검증]` 다른 허용값.

### 4.2 ⚠️ "2000-01-01T00:00Z 기준 분 단위 uint32" 는 성립하지 않는다

실측:

```

min = -52587716  max = 53106951

| epoch | 최소값 | 최대값 | uint32 | int32 | 바이트/레코드 | 4,824 레코드 총계 |
|---|---|---|---|---|---|---|
| 2000-01-01T00:00Z | **−52,587,716** | 53,106,951 | ❌ (음수) | ✅ | 4 | **19,296 B** |

**답**: 4 바이트/레코드 × 4,824 = **19,296 바이트**. 단 2000 epoch 은 uint32 로는 담을 수 없고 **int32** 여야 한다. epoch 을 1900-01-01T00:00Z 로 옮기면 uint32 로 담기며 크기는 동일하다.

```

간격이 **21,188 ~ 22,661분**(range 1,473)이므로 **uint16(2 B)** 로 delta 를 담을 수 있다. `(delta − 21188)` 은 0~1473 이라 11비트면 되지만 uint8(255)에는 안 들어간다.

### 4.7 프로덕션 인코더/디코더 (검증된 코드)

**인코더** (빌드 타임, Node):

```js
const EPOCH = Date.UTC(1900, 0, 1, 0, 0, 0);   // 1900-01-01T00:00:00Z
const DMIN  = 21188;                            // 실측 최소 간격(분)

// terms: [{utcMs}] 시간 오름차순, 분 단위로 반올림된 값
function encodeText(terms) {
  const m = terms.map(t => (t.utcMs - EPOCH) / 60000);
  let s = String(m[0]);                          // base (10진)
  for (let i = 1; i < m.length; i++) {
    s += '|' + String(m[i] - m[i-1] - DMIN).padStart(4, '0');
  }
  return s;                                       // 포맷 P 변형
}

// 이진 (포맷 G) — 로컬 캐시/IndexedDB 용
function encodeBinary(terms) {
  const m = terms.map(t => (t.utcMs - EPOCH) / 60000);
  const b = Buffer.alloc(4 + (m.length - 1) * 2);
  b.writeUInt32LE(m[0], 0);
  for (let i = 1; i < m.length; i++) b.writeUInt16LE(m[i] - m[i-1], 4 + (i-1)*2);
  return b;                                       // 9,650 B @ 4,824 레코드
}
```

**디코더** (런타임):

```js
const EPOCH = Date.UTC(1900, 0, 1);
const MIN_YEAR = 1900, TERMS_PER_YEAR = 24;

/** 이진(포맷 G) → Int32Array(분) */
function decodeBinary(buf) {
  const n = (buf.byteLength - 4) / 2 + 1;
  const dv = new DataView(buf);
  const a = new Int32Array(n);
  a[0] = dv.getUint32(0, true);
  for (let i = 1; i < n; i++) a[i] = a[i-1] + dv.getUint16(4 + (i-1)*2, true);
  return a;
}

/** 절대시각(UTC ms) → 직전 절기 인덱스. 없으면 -1 */
function findTerm(a, utcMs) {
  const minutes = Math.floor((utcMs - EPOCH) / 60000);
  let lo = 0, hi = a.length - 1, r = -1;
  while (lo <= hi) {
    const mid = (lo + hi) >> 1;
    if (a[mid] <= minutes) { r = mid; lo = mid + 1; } else hi = mid - 1;
  }
  return r;
}

/** 인덱스 → {year, termIndex, name, sunLng} */
const NAMES = ['소한','대한','입춘','우수','경칩','춘분','청명','곡우','입하','소만','망종','하지',
               '소서','대서','입추','처서','백로','추분','한로','상강','입동','소설','대설','동지'];
function termMeta(i) {
  const year = MIN_YEAR + Math.floor(i / TERMS_PER_YEAR);
  const idx  = i % TERMS_PER_YEAR;
  return { year, termIndex: idx, name: NAMES[idx],
           sunLng: (285 + 15 * idx) % 360, isJeol: idx % 2 === 0 };
}
```

**포맷의 결정적 이점**: 테이블이 `year*24 + termIndex` 로 **밀집 인덱싱**되므로 인덱스에서 연도·절기명·황경이 산술로 복원된다. 이름·황경을 저장할 필요가 없다.

### 5.2 판정: **(a) 클라이언트 번들 인라인**

근거:

1. **3,333 바이트**는 논쟁 대상이 아니다. 아이콘 하나보다 작다. 앱인토스 미니앱 번들 예산(문서 01·11 참조)에서 무시 가능하다.
2. 서버 API는 **RTT가 조회 시간의 10만 배**다 (30 ms vs 0.234 µs). 사주 계산 1건에 절입 조회가 최소 3회(연주 입춘 판정, 월주 직전 節, 대운수 다음/직전 節) 필요하므로 왕복이 누적된다.
3. 절기 데이터는 **불변**이다. 2004~2026 KASI 공표값은 확정된 과거이고, 미래분은 천문 계산으로 결정된다. 서버에 둘 이유(=동적 갱신)가 없다.
4. manseryeok 런타임(c)은 dist brotli 21.5 KB 로 **테이블 방식의 6.4배**이면서 §3.4 의 22건 월주 오차를 그대로 안는다.

### 5.4 확장: 1900 미만 / 2100 초과

- 하한: 1900 미만 출생자는 실서비스 대상이 아니다. 필요 시 astronomy-engine 으로 재생성만 하면 되며 크기는 연간 24 레코드 × 0.7 B ≈ **17 B/년**.
- 상한: 대운은 최대 10운 × 10년 = 100년. 2026년생 + 100년 = 2126년까지 세운/대운 간지가 필요하다. **테이블 상한을 2100 → 2150 으로 늘려도 brotli 증가분은 약 850 B** (50년 × 24 × 0.691). 상한 2150 채택 권고.
- ⚠️ ΔT 예측 불확실성: 2100년 이후 ΔT 는 외삽이며 astronomy-engine 과 다른 ΔT 모델을 쓰면 절입이 수 분 어긋난다. 원거리 미래는 "표시용"이지 "확정값"이 아님을 명시할 것.

### 6.2 절입 분 경계 처리 (경계 포함 여부)

| 선택 | 2018-02-04 06:28:00 정각 출생 |

### 6.3 반올림 vs 절사

| 선택 | 근거 | 526건 중 KASI 재현률 |
|---|---|---|
| `floor(초 → 분)` | "아직 도달 안 함" 해석 | 308 / 526 (58.6%) |
| **`round(초 → 분)`** | KASI 공표 관행 | **424 / 526 (80.6%)** |

채택: **round**. 나머지 102건 차이는 AE 와 KASI 의 초 단위 편차(median +6.3 s)에서 오며, 2004~2026 은 어차피 KASI 값으로 덮어쓴다.
