### 2.2 명식 기준시

```
tzMode = raw_kst      : localMs = wallMs                              (offset 무시)
tzMode = historical
   longitude = null   : localMs = utc + std·60000                     (DST 제거, +8:30기는 +8:30 유지)
   longitude = λ      : localMs = utc + std·60000 + round((L + E)·60000)
                        L = 4·(λ − std/4)   [분]          ← 경도보정
                        E = eotMinutes(utc) [분]          ← 균시차 NOAA/Meeus
```

`std/4` 가 표준자오선 경도다: 540분→135°, 510분→127.5°, 507.8667분→126.9667°.

## 3. 절기 오라클 확정 — Skyfield + JPL DE440s

C13 은 Skyfield/DE440s 를 기준으로 삼았지만 **사전계산 테이블을 남기지 않았다.** C10 에서는
DE440s 로 1851~2145 × 24절기 = **7,080 레코드**를 생성해 `proto/solarterms-de440s.json` 에 고정했다.

생성 방법: astronomy-engine 으로 초기값을 만들고 Skyfield 로 뉴턴 3회 반복.

```
iter0 max|err| 3.227e-03 deg
iter1 max|err| 8.359e-09 deg
iter2 max|err| 2.370e-10 deg      ← 0.02 ms 수준으로 수렴
records 7080
{'year': 2024, 'name': '입춘', 'sunLng': 315, 'utc': '2024-02-04T08:27:07.593Z'}
```

KST 로는 `2024-02-04 17:27:07.593` — C13 XT-01 의 DE440s 값 `17:27:08` 과 일치한다.

### 3.1 ⚠️ astronomy-engine 은 절기 오라클로 부적합 (신규 발견)

C02 는 `astronomy-engine` 을 "독립 오라클" 로 채택했고 C14 §부록B 도 이를 유지했다.
**1851~2145 전수(4,824건, 1900~2100 구간) 대조 결과 이 판단은 철회되어야 한다.**

`AE시각 − DE440s시각` (초):

|---|---|---|---|---|
| 1900~1949 | 1200 | **−25.50** | — | 80.67 |
| 1950~1999 | 1200 | −7.42 | — | 59.06 |
| 2000~2049 | 1200 | +1.59 | — | 56.04 |
| 2050~2099 | 1200 | **+72.24** | — | 175.31 |
| 2100 | 24 | **+136.77** | — | 150.32 |
| **전체** | **4824** | +10.86 | **19.92** | **175.31** |

```
|Δ| > 30 s : 1673 건 (34.68 %)
|Δ| > 60 s :  752 건
표준편차   : 44.01 s
```

원인은 천체력이 아니라 **ΔT(TT−UT) 모델 차이**다. 근거: AE 자신의 `SunPosition` 을
DE440s 해에 넣으면 `elon = 315.000211°`, AE 해에 넣으면 `elon = 314.999993°` 로
**AE 는 내부 정합적**이다. 즉 황경 계산이 아니라 UT 환산이 어긋난다.
미래로 갈수록 편차가 단조 증가하는 것도 ΔT 외삽의 특징이다.

또한 `Astronomy.SearchSunLongitude(target, start, limitDays)` 는 **탐색창 폭에 따라 `null` 을 반환**한다.

```
start = 1989-11-01, limitDays = 500 : 315°→OK  345°→OK  15°→OK  45°→NULL  75°→NULL  105°→OK
start = 1989-11-01, limitDays = 400 : 45°→NULL  75°→OK  105°→OK  135°→OK
```

→ 반드시 **황경으로 근사 날짜를 추정한 뒤 좁은 창(±12~45일)으로 탐색**해야 한다.
`ref.mjs` 는 `est = UTC(baseY,3,20) + λ/0.98564736 일` 로 추정하고 창을 12→25→45 일로 넓힌다.

### 3.2 manseryeok / lunar-javascript 의 절기 정확도 (vs DE440s)

`ref.mjs` 가 아니라 각 라이브러리가 **스스로 반환한 절기 시각**을 DE440s 와 비교했다.
lunar-javascript 값은 UTC+8 벽시계이므로 `−8h` 하여 UTC 로 환산했다.

정확히는 **시간대만 문제였고 절기 알고리즘 자체는 2000~2049 구간에서 DE440s 와 max 4.9초로
가장 정확하다.** manseryeok(분 단위 저장, max 31.9초)보다 정밀하다.
따라서 lunar-javascript 는 `−1h` 보정만 하면 절기 산출용으로 쓸 수 있다.

manseryeok 은 **분 단위로만 저장**한다(`getSolarTerm` 반환 Date 의 초가 항상 0).
2000~2049 의 max 31.9초는 사실상 반올림 오차 그 자체다.

### 3.3 KASI 공표값의 분 단위 처리 규칙 판별 (C14 정정)

C14 는 "KASI 공표값 = 절사, manseryeok = 반올림" 을 전제로 TV-B 를 세웠다.
DE440s 기준으로 526 레코드(2011 오염 등 결함 26건 제외)를 분류한 결과:

| DE440s 초 | KASI = floor(분) | KASI = ceil(분) | 기타 |
|---|---|---|---|
| 초 < 30 | **265** | 1 | 0 |
| 초 ≥ 30 | 30 | **222** | 0 |
| 초 = 0 | 8 (구분 불가) | — | — |

| DE440s 초 | manseryeok = floor | manseryeok = ceil | 기타 |
|---|---|---|---|
| 초 < 30 | **254** | 12 | 0 |
| 초 ≥ 30 | **0** | **252** | 0 |
| 초 = 0 | 8 (구분 불가) | — | — |

```
KASI − DE440s :  |Δ| 중앙 15.7 s   p95 31.0 s   max 38.4 s   |Δ|>60s 0 건
```

**→ KASI 도 manseryeok 도 "반올림"이다. 절사가 아니다.**
KASI 는 487/526 = 92.6 %, manseryeok 은 506/526 = 96.2 % 가 순수 반올림과 일치하고,
나머지는 각자의 내부 계산값이 DE440s 와 수십 초 다르기 때문에 반올림 방향이 갈린 것이다.

따라서 **"KASI 공표 분값 == 절입 순간" 은 성립하지 않는다.** 실제 절입은 그 분의
`−30 초 ~ +30 초` 어딘가다. C14 TV-B 의 "KASI 기준 기대" 열은 이 잘못된 전제 위에 있다(§4).

## 6. 대운수 — 한국식 공식 확정

C06 TV-3 은 「한국식 / 반올림 / 버림」 3열을 제시했지만 한국식 공식을 명시하지 않았다.
6개 벡터 + TV-7-1 계단점프 케이스를 전부 만족하는 유일한 식은 다음이다.

```
Δ = 순행이면 (다음 節 − 출생), 역행이면 (출생 − 직전 節)      [ms]
days = Δ / 86400000
daewoonNumber(한국식) = round( floor(days) / 3 )              // 0 이면 1로 보정
반올림안 = round(days / 3)          버림안 = floor(days / 3)
```

`floor` 를 **먼저** 적용하는 것이 핵심이다(정수 일수로 환산 후 3분법).
