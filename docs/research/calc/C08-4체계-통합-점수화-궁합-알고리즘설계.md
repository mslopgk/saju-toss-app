
> **[C18 정정 1 — 이 매트릭스는 독립 출처가 아니다]**
> npm `mbti-matrix@0.0.4` `src/mbtiMatrix.ts` 의 16×16 과 대조하면, 사상 `{-2:0, -1:1, 0:2, 1:2, 2:3}` 아래 **256칸 중 255칸이 일치**(유일 불일치 = INFJ×ENTJ). Pearson r = **+0.9644**.
> → `Pomettini/mbti` 와 `mbti-matrix` 는 **동일 원본 차트의 두 구현**이며, MBTI 궁합의 독립 출처는 (Pomettini 계열) + (`mycompatibility.org`) **2계통뿐**이다. 상세: `C18-궁합-배점-근거확보와-검증.md` §3.1.

> **[C18 정정 2 — "제한했다"는 서술의 범위]**
> 실측 분산분해(η²) 결과 **본 설계 v1(+12/−8) 의 S/N 설명력은 93.6%** 로 `Pomettini`(49.5%)·`mbti-matrix`(37.3%)·`mycompatibility`(48.2%) 보다 **오히려 크다**.
> 위 문장의 "제한" 은 **고유값 수(33종 vs 5종)** 와 **N×S 블록 내 변별(17종·범위 25~54 vs 4종·48.4%가 최저값)** 에 한정된 이야기이고, S/N **주효과** 자체는 증폭됐다.
> → C18 이 외부 2계통 평균상관 최대화 그리드서치로 **S/N `+6/−4`, T/F `+6/+3`(v3)** 를 확정했다(평균 r 0.7656 → 0.8049). 상세: C18 §3.5~§3.8. 파라미터: `compat-params.json` `mbti.preferenceAxis.v3_adopted`.

### 3.4 S3 — 오행 상보성 (20점)

정의: 두 사람의 **지장간 가중 오행 벡터**를 합쳤을 때 균형이 얼마나 개선되는가.

```python
w(chart)[e] = Σ_천간 1.0·[EL(gan)==e] + Σ_지지 Σ_지장간 hw·[EL(hidden)==e]
              (hw = 3개면 [0.3,0.5,1.0], 2개면 [0.5,1.0], 1개면 [1.0])

CV(v) = stdev(v) / mean(v)                       # 변동계수 = 불균형도
improve = (CV(wA)+CV(wB))/2 - CV(wA+wB)          # >0 이면 합쳐서 균형 개선
fill    = #{ e : (wA[e]<0.5 ∧ wB[e]≥1.5) ∨ (wB[e]<0.5 ∧ wA[e]≥1.5) }   # 결핍보완 건수

S3 = clamp( 8 + improve*22 + fill*2.5 , 0, 20 )
```

- `improve` 계수 22 / `fill` 계수 2.5 는 시뮬 상 S3 평균이 배점의 60% 근처(12.11/20 = 60.6%)가 되도록 캘리브레이션한 값.
- 시뮬 실측: **평균 12.11 / sd 2.99 / min 7.34 / max 20.00**.

## 4. 별자리 궁합 — 12×12 전체 점수표

### 4.1 규칙 (각거리 기반 4항 합성)

```python
k  = min(|i-j| mod 12, 12 - (|i-j| mod 12))     # 0..6
A  = ASPECT[k]                                   # 어스펙트 점수
E  = +18 if (i%4)==(j%4)                         # 동일 원소
     +12 if ((i%4)-(j%4)) mod 4 == 2             # 상보 원소(火↔風, 土↔水)
     -8  otherwise                               # 인접 원소(火↔水, 土↔風)
M  = -4 if (i%3)==(j%3) else +4                  # 양태 — ❌ C18 에서 부호 정정됨. 아래 참조
P  = +3 if (i%2)==(j%2) else -3                  # 극성(양/음)
score = clamp(50 + A + E + M + P, 0, 100)
```

> **[C18 정정 3 — M(양태) 항의 부호가 반대였다]**
> PyPI `kerykeion` 5.12.9 `relationship_score_factory.py` 의 Ciro Discepolo 시나스트리 배점은 **동일 양태(quality)에 `DESTINY_SIGN_POINTS = +5`** 를 준다(`_evaluate_destiny_sign`). 위 `-4` 는 근거 없는 반대 부호였다.
> 정정: **`M = +5 if (i%3)==(j%3) else 0`**
> 검증: mybias.app 144칸과의 Pearson r 이 **+0.9869 → +0.9927** 로 개선되고, k=0(합) 88·k=3(스퀘어) 32 를 **정확히 재현**한다. 최종 점수 등급이 바뀌는 비율 9.42%.
> 상세: C18 §4.2 / 파라미터: `compat-params.json` `zodiac.modality.adopted = "M-B"`, `zodiac.matrix_MB`.
>
> **[C18 보강 — 어스펙트 오브(orb) 확보]**
> C08 은 오브를 다루지 않았다. kerykeion `settings/config_constants.py` 의 Discepolo 세트를 그대로 채택한다(evidenceGrade **A**):

- 옵션 1(본 설계): 그대로 20. 사주 항목이 월지를 거의 안 쓰므로 실질 중복 낮음.
- 옵션 2: 사주 S2/S6에 **월지 항목을 추가**할 경우 별자리 가중을 20→12로 내리고 그 8을 사주로 이관.
- 옵션 3: 별자리 점수에서 월지 기여분을 residualize (`z_zodiac - E[z_zodiac | 월지]`). 계산 가능하나 설명 불가능한 점수가 나와 미니앱에 부적합.

### 6.2 생성 규칙 (실행 코드)

```python
POSW    = [4, 3, 2, 1]                      # dom, aux, tert, inf
PARTNER = {"Ne":"Ni","Ni":"Ne","Se":"Si","Si":"Se",
           "Te":"Ti","Ti":"Te","Fe":"Fi","Fi":"Fe"}
TEMP_M  = {("NF","NF"):6, ("NF","NT"):5, ("NF","SP"):-1, ("NF","SJ"):0,
           ("NT","NT"):5, ("NT","SP"):1,  ("NT","SJ"):1,
           ("SP","SP"):4, ("SP","SJ"):3,  ("SJ","SJ"):6}

def mbti_raw(a, b):
    # (1) 선호지표 항 L
    L  = 3 if a[0]==b[0] else 6      # E/I : 보완 우대
    L += 12 if a[1]==b[1] else -8    # S/N : 일치 강하게 우대 (세계관 축)
    L += 4 if a[2]==b[2] else 5      # T/F : 보완 소폭 우대
    L += 3 if a[3]==b[3] else 5      # J/P : 보완 소폭 우대

    # (2) 공유 인지기능 (위치가중 오버랩) 0~10
    wa = {f: POSW[i] for i, f in enumerate(STACK[a])}
    wb = {f: POSW[i] for i, f in enumerate(STACK[b])}
    shared = sum(min(wa.get(f,0), wb.get(f,0)) for f in set(wa) | set(wb))

    # (3) 보완(듀얼) 항 : A의 f 와 B의 짝기능이 마주보는 정도, 0~1 정규화
    comp = sum(w1 * wb.get(PARTNER[f], 0) for f, w1 in wa.items()) / 40.0

    # (4) dom-aux 미러 보너스
    if STACK[a][0]==PARTNER[STACK[b][1]] and STACK[a][1]==PARTNER[STACK[b][0]]:
        mirror = 10                  # 완전 미러 (INFP↔ENFJ, ENFP↔INFJ 등)
    elif STACK[a][0]==PARTNER[STACK[b][0]]:
        mirror = 6                   # 주기능 짝
    else:
        mirror = 0

    return 50 + L + 1.6*shared + 14*comp + mirror + TEMP_M[sorted_pair(a,b)]

# raw 범위 [59.00, 101.35] → 25~95 로 선형 재스케일
score(a,b) = round((raw - 59.00) / (101.35 - 59.00) * 70 + 25)
```

### 7.1 대칭 기저 (성별 무시)

> **[C18 정정 4 — 이 표는 evidenceGrade D 로 확정됐고, 균등화를 권고한다]**
> 1. **학술 근거 부재**: Nawata(2014, N>10,000, 68문항 중 65문항 비유의) **η² < 0.003** — 혈액형이 성격분산의 0.3% 미만 설명. Tsuchimine et al.(2015, PLoS ONE, N=1,427) partial η² 0.006~0.010, 저자 스스로 "preliminary … relatively weak".
> 2. **출처 자체가 부인**: `jaypromax` 원문 — *"혈액형 궁합은 과학적으로 검증된 이론이 아니며"*. 게다가 같은 페이지에서 Love/Friendship/Work 별점 순위가 서로 다르다(A×A: Love 4, Friendship 5).
> 3. **독립 2출처 불일치**: `jaypromax` ↔ `Gangnamhaha/cheonmyeong` `src/data/bloodtype-compatibility.ts` 의 비순서쌍 10칸 Pearson r = **+0.6447**(n=10). 최대 불일치 B-AB (본 표 82 vs cheonmyeong 67.5).
> 4. **본 표는 jaypromax 에서 유도됐으므로** r(본표, jaypromax)=+0.9549 는 독립 검증이 아니다.
> 5. 위 §1.7 이 인용한 threads 카드뉴스는 **[미검증]** 이며 C18 은 배점 근거에서 제외했다.
>
> **권고 BL-1**: 4×4 를 **전칸 동일(70)** 로 교체. 최종 점수 **분포·등급 비율 변화 0.00%p**(C18 §6.4 분포 불변 정리), 등급 배치만 20.45% 이동.

### 8.2 정규화 (모집단 상수 확정)

각 체계는 스케일·분산이 전혀 다르므로 **z정규화 → 로지스틱 매핑**한다.

```python
POP = {                      # sim.py N=100,000 실행 결과로 확정 (하드코딩 상수)
  "saju":   (mu=60.268, sd= 8.909),
  "zodiac": (mu=58.655, sd=27.764),
  "mbti":   (mu=58.270, sd=24.178),
  "blood":  (mu=70.973, sd=16.036),
}
def z2p(x, mu, sd):
    z = (x - mu) / sd
    return 100 / (1 + exp(-0.82 * z))     # sd 1개당 약 ±19점
```

로지스틱을 쓰는 이유: 이산값이 소수인 별자리(7종)·MBTI(33종)를 선형 min-max 하면 양 끝단이 0/100에 붙어 가중합 분포가 다봉(multi-modal)이 된다. 로지스틱은 극단값을 25~75 근처로 압축해 봉우리를 합쳐 준다(실측: 보정 전 가중합이 단봉 정규형 — §8.4).

### 9.2 부동소수 규칙 (필수)

```
- S3(오행), S4(용신)만 실수 연산. 나머지는 정수.
- 각 서브점수는 소수 3자리 반올림 후 상위 단계로 전달  → round(x*1000)/1000
- 최종 점수는 정수 (round half-up. JS Math.round 는 half-up 이므로 그대로 사용 가능,
  단 음수는 나오지 않으므로 Math.round 안전)
- exp() 사용 지점(z2p)은 1곳뿐. IEEE754 double 이면 플랫폼 무관 동일.
- 절대 금지: Date.now(), Math.random(), toLocaleString(), Intl 정렬, Object 키 순서 의존
```

### 9.3 입력 정규화 (캐시 키 생성 전 필수)

```python
def normalize(raw):
    return {
      "v": 1,                                        # 정규화 스키마 버전
      "birth": f"{y:04d}-{m:02d}-{d:02d}T{hh:02d}:{mm:02d}",  # 항상 양력·분 단위
      "cal":   "solar",                              # 음력 입력은 여기 오기 전에 변환
      "unknownHour": bool,                           # 시간 모름 → hour=12, 플래그 true
      "gender": "M" | "F" | "N",                     # N = 미입력
      "birthPlace": {"lon": round(lon, 2), "tz": "Asia/Seoul"},  # 경도 소수 2자리 고정
      "mbti": upper(mbti) or None,                   # "INFP" | None
      "blood": upper(blood) or None,                 # "A"|"B"|"O"|"AB" | None
    }
```

정규화 규칙 (모두 필수):
1. 음력 → 양력 변환은 **정규화 이전** 단계에서 끝낸다. 캐시 키에는 양력만 들어간다.
2. 경도는 소수 2자리 반올림(약 1.1km). 같은 동네는 같은 키.
3. 시간 미상은 `hour=12, unknownHour=true` — 12시 고정이므로 결정론 유지.
4. MBTI/혈액형 미입력은 `null`. 미입력 체계는 가중치를 나머지에 **비례 재분배**한다.
   예: 혈액형 미입력 → 사주 0.50/0.90, 별자리 0.20/0.90, MBTI 0.20/0.90 로 재정규화.
5. JSON 직렬화는 `sort_keys=True, separators=(",",":")`, 유니코드 이스케이프 금지.

### 9.4 캐시 키 2계층

```python
# L1 : 계산 결과 캐시 (점수·구조 데이터)
def cache_key(inputA, inputB, engine="C08", ver="1.0.0"):
    a, b = normalize(inputA), normalize(inputB)
    # A/B 순서 무관하게 만들려면 canonical 문자열로 정렬 (단, 성별 비대칭 항목 주의)
    payload = {"A": a, "B": b}
    s = json.dumps(payload, sort_keys=True, separators=(",",":"), ensure_ascii=False)
    return sha256(f"{engine}|{ver}|{s}").hexdigest()

# L2 : LLM 서사 캐시 (구조 동치류로 축약 → 히트율 극대화)
def narrative_key(A, B, final):
    reduced = {
      "dg":    sorted([A.dayStem,   B.dayStem]),      # 일간쌍   (55 조합)
      "dz":    sorted([A.dayBranch, B.dayBranch]),    # 일지쌍   (78 조합)
      "yz":    sorted([A.yearBranch,B.yearBranch]),   # 띠쌍     (78 조합)
      "mbti":  sorted([A.mbti, B.mbti]),              # MBTI쌍   (136 조합)
      "zk":    min(d, 12-d) where d=|zA-zB| mod 12,   # 별자리 각거리 (7 조합)
      "blood": sorted([A.blood, B.blood]),            # 혈액형쌍 (10 조합)
      "band":  grade_tag(final),                      # 등급 (8)
    }
    return sha256(canonical(reduced)).hexdigest()[:32]
```

**버전 정책**: 배점표·앵커·POP 상수 중 하나라도 바꾸면 `ver` 를 올린다 → 전 캐시 자동 무효화. `ver` 를 안 올리고 상수를 바꾸면 같은 입력에 다른 점수가 나가 D1 위반.

### 10.5 규칙기반 + LLM 하이브리드 설계

```
┌─────────────────────────────────────────────────────────────┐
│ 계층 0  결정론 엔진 (순수함수, 서버·클라 동일 구현)         │

│   latency < 3ms, 100% 결정론, 캐시 불필요(계산이 더 쌈)     │
├─────────────────────────────────────────────────────────────┤
│ 계층 1  규칙기반 문장 슬롯 (사전 작성된 템플릿)             │
│   tags[] 를 문장 조각으로 치환. 조각 수 = 유한:             │
│     S1 6종 × S2 태그 9종 × S5 십신 10종 × 등급 8종 ≈ 4,320  │
│   즉시 렌더. 오프라인/LLM 장애 시 폴백. 항상 이 계층까지는  │
│   결과가 나온다.                                             │
├─────────────────────────────────────────────────────────────┤
│ 계층 2  LLM 서사 (narrative_key 로 캐시)                    │
│   프롬프트 입력 = 계층0 출력 JSON + 계층1 문장 조각          │
│   temperature=0, top_p=1, seed 고정 → 같은 키면 같은 문장    │
│   캐시 미스 시에만 호출. TTL 무한(엔진 ver 바뀌면 전체 무효)│

└─────────────────────────────────────────────────────────────┘
```

핵심 규칙:
1. **점수는 절대 LLM이 만들지 않는다.** LLM은 계층0이 만든 숫자를 설명만 한다.
2. LLM 출력은 캐시 키 단위로 고정 → 같은 구조의 두 커플은 같은 문장을 본다. 이는 버그가 아니라 **결정론 요구사항의 결과**다. 개인화가 필요하면 이름·호칭만 계층1에서 치환한다(캐시 키에 이름 미포함).
3. LLM 호출 실패 → 계층1 문장으로 폴백. 사용자에게는 항상 결과가 나간다.

## 12. 미해결/후속 과제

1. 실제 사용자 생일 분포는 균등하지 않다(3월·10월 출생 과다, 요일 편향). 현재 POP 상수는 **원국 공간 균등 가정**으로 산출됐다. 서비스 오픈 후 실사용 로그 10만 건으로 POP·ANCHOR 재캘리브레이션 필요.
2. MBTI 입력 분포도 균등하지 않다(한국 앱 사용자는 I·N 편중). MBTI 정규화 상수는 실사용 분포로 교체해야 sd가 맞는다.
3. 별자리와 월지 중복(§5)의 정량 보정은 residualize 외에 "별자리 점수를 월지 조건부 백분위로 변환"하는 방법이 있다. 설명가능성 손실과 트레이드오프.
4. 대운(大運) 반영: 현재 모델은 원국만 본다. "지금 시기" 궁합(대운·세운 교차)은 시간 의존 → 결정론 위반. 반영하려면 `asOfDate` 를 입력에 포함해 캐시 키에 넣어야 한다(키 공간 ×365).
5. 동성 커플 처리: §7.2 성별 보정과 §3.6 십신(정재=처, 정관=남편) 해석이 이성애 전제. 중국 자료에는 `同性恋八字合婚的特殊算法` 논의가 있으나 [미검증]. 현재는 성별 `N` 폴백(대칭표 + 중립 십신 문구)으로 처리.
6. **[C18 에서 해소됨]** 15항목 배점의 evidenceGrade D 문제 → `C18-궁합-배점-근거확보와-검증.md` + `compat-params.json`. 결과 요약:
   - S1 일간 순위 **D→B**(독립 5개 구현 Spearman ρ=+1.0000), S2 일지 순위·크기 **D→B**(idolSCORING 과 비례상수 1.773±0.195), S6 띠 **D→B**
   - 별자리 M(양태) 부호 **정정**(−4 → +5), 어스펙트 오브 **신규 확보(등급 A)**
   - MBTI **D→B**, S/N `+12/−8`→`+6/−4`, T/F `+4/+5`→`+6/+3`
   - S3·S4 **D 유지**(외부 구현들이 정의부터 불일치), S5 **D→C**
   - 혈액형 **D 확정**: Nawata(2014) η²<0.003. 균등 매트릭스 전환 권고
