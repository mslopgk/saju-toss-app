# 상용 만세력 크로스체크 — 유파 판별 실측

> 조사 축: 시장 관행 판별 | 상태: 1차 완료(2개 서비스) | 검증도: 상(브라우저 실조작 + 방법론 원문)
>
> 실행: 2026-08-12, Chrome 자동화 + 로컬 manseryeok 대조
> 목적: C00 §9.1 의 `U2`(진태양시→일주 경계) · `U3`(서머타임) · 야자시 유파를 **시장 관행**으로 판별

---

## 0. 왜 이 조사가 필요했나

C00 명세는 유파를 이론적 타당성으로 확정했다. 그러나 운세 서비스에서 "정확도"는 천문학적 정확도가 아니라 **사용자 기대와의 일치**다. 우리가 이론적으로 옳아도 네이버·상용 만세력과 다르면 "틀렸다"는 CS가 온다.

C00 §9.1 은 이를 `U2`/`U3` 로 등재하고 판별 입력을 설계해 두었으나 **실제 서비스에 넣어본 적이 없었다.**

---

## 1. 판별 입력 설계

### 1.1 통합 판별 입력: `1990-06-15 23:30 여자 서울`

로컬 manseryeok 으로 전 유파 조합을 산출한 결과, **이 입력 하나로 4가지가 갈린다**:

```
=== 1990-06-15 23:30 여자 · 유파별 기대값 ===
  진태양시 OFF / midnight   : 경오 임오 신해 무자
  진태양시 OFF / jasi       : 경오 임오 임자 경자
  진태양시 OFF / splitJasi  : 경오 임오 신해 경자
  진태양시 ON  / midnight   : 경오 임오 신해 기해
  진태양시 ON  / jasi       : 경오 임오 신해 기해
  진태양시 ON  / splitJasi  : 경오 임오 신해 기해
```

| 관측 결과 | 판정 |
|---|---|
| `己亥`시 (亥시) | **진태양시 적용** (23:30 − 32분 = 22:58 → 亥시). 야자시 유파는 판별 불가(전부 수렴) |
| `辛亥`일 `戊子`시 | 진태양시 OFF + 야자시 (a) |
| `壬子`일 `庚子`시 | 진태양시 OFF + 조자시 (b) |
| `辛亥`일 `庚子`시 | 진태양시 OFF + 분리형 (c) |

> **설계 노트**: 진태양시가 켜지면 23:30 출생이 아예 子시를 벗어나므로 야자시 유파가 무의미해진다. 진태양시 ON 서비스에서 야자시를 판별하려면 **23:32 이후**(= 진태양시로도 子시에 남는 시각)를 써야 한다. C00 §9.1 의 U2 판별 입력을 이 조건으로 보강할 것.

### 1.2 1클릭 진태양시 판별: `1990-06-15 15:00`

휠 피커 UI 에서 클릭 수를 최소화하기 위해 설계. 15:00 − 32분 = 14:28 이라 未/申 경계를 넘는다.

```
=== 1990-06-15 15:00 여자 ===
  진태양시 OFF          : 경오 임오 신해 병신   (15:00 → 申시)
  진태양시 ON 서울 경도 : 경오 임오 신해 을미   (14:28 → 未시)
```

계산 중 로딩 화면이 파이프라인을 그대로 노출한다:

→ **C00 §1 정규화 순서(경도 → 표준시 이력 → 서머타임)와 동일.**

### 2.4 ⭐ `전문가 설정` — 노출 정책이 명세와 동일

상단 `전문가 설정` 을 열면 **선택지가 딱 하나**다:

> **자시 (子時) 기준**
> 밤 11시~자정에 태어나신 분이라면 이 설정이 사주에 영향을 줄 수 있어요. **학자마다 의견이 다른 부분이에요.**
> - **야자시 (오늘 子時)** — 밤 11시 = 오늘로 봄 ← **기본 선택**
> - 조자시 (내일 子時) — 밤 11시 = 내일로 봄

**해석:**
1. **진태양시는 토글조차 주지 않고 항상 적용** → C00 A1 "TRUE_SOLAR 고정, 노출=없음" 과 동일 판단
2. **야자시만 사용자에게 노출** → C00 C1 이 야자시를 확정하되 "노출=없음" 으로 둔 것과 **갈림** (§5 참조)
3. **분리형(c)은 선택지에 아예 없음** → C09 §11.3 이 "(c)는 일주와 시주가 오서둔상 상호모순" 이라 지적한 것과 정합. lunar-javascript `sect=2` 가 내는 유파를 상용 서비스는 제공하지 않는다.

### 3.3 ⭐⭐⭐ U2 에 대한 직접 답변

진태양시 절의 결론 문장:

> "이 두 보정을 합산하여 입력된 표준시를 실제 태양시로 환산한 후 **시주를 결정하므로**, 시주 경계에서 보다 정확한 계산이 가능합니다."

**진태양시를 `시주` 결정에만 쓴다고 명시한다. 일주 경계 이동은 언급이 없다.**

야자시 절도 같은 방향이다 — "일주는 **전날 것을 유지**하고 시주만 자시로 계산" 은 일주 경계를 **벽시계 자정**으로 잡는다는 뜻이다. 진태양시로 −32분 밀린 경계가 아니다.

→ **C00 §3 A2("진태양시를 일주 경계 + 시주 둘 다 적용")는 이 서비스와 반대다.**

### 3.4 자기 한계 고지

> "진태양시 적용 여부와 야자시 해석은 **학파마다 다르므로, 하나의 정답이 아닌 다양한 계산 방식을 제공하는 것이 사주만세의 접근 방식**입니다."

## 5. C00 에 반영해야 할 사항

### 5.1 A2(진태양시 → 일주 경계) — 위험도 상향

C00 §9 U2 는 이 항목을 "한국 상용 만세력 다수와 반대일 가능성" 으로 등재했다. **sajumanse 원문이 그 우려를 실증했다.**

- sajumanse: 진태양시 = **시주 전용**, 일주 경계는 벽시계 자정
- C00 A2: 일주 경계 + 시주 **둘 다**
- 영향: 2.14~2.25% (C00 §9 실측)

⚠️ **주의**: manseryeok 은 `trueSolarTime` 을 켜면 일주 경계까지 자동으로 밀린다(C12 발견, 분리 옵션 없음). sajumanse 는 manseryeok 을 쓰면서도 "시주만" 이라고 서술하므로, **자체 추가 로직에서 일주를 되돌리거나, 혹은 서술과 구현이 다르거나** 둘 중 하나다. → `1990-06-15 00:10` 류 입력으로 sajumanse 실측 필요 (미완).

**권고**: A2 를 `일주 경계 미적용`(시주 전용)으로 뒤집는 것을 검토하라. 근거는 (a) 상용 관행 1건 명시적 반대 (b) 야자시 규칙("일주는 전날 것 유지")이 벽시계 자정 경계를 전제로 성립 (c) 진태양시로 일주가 밀리면 야자시 창 자체가 23:31~00:35 로 이동해 "밤 11시" 라는 사용자 설명과 어긋남.

### 5.2 C1(야자시) 노출 정책 — 노출 쪽으로 변경 권고

C00 은 야자시를 `노출=없음` 으로 확정했으나, **bareunsaju 는 이것만 유일하게 노출한다.** 그리고 이것이 합리적이다:

- 영향 사용자 4.17%(23시대 출생) — 결코 작지 않다
- 결과가 **일간부터 바뀌어** 십신 전체가 재배치된다 (C09 §7)
- "학자마다 의견이 다른 부분" 이라고 솔직히 고지하면 CS 가 논쟁이 아니라 설명으로 끝난다

**권고**: 기본 야자시 + `고급 설정`에 조자시 토글. 분리형(c)은 제공하지 않는다(상용 2곳 모두 미제공).

### 5.3 절기 정밀도 — 우리가 더 정밀한 것은 유지하되 배지 필요

sajumanse 는 날짜 단위라 **절입 당일 출생자(연 12일, 3.3%)에서 우리와 결과가 갈린다.** 우리가 옳지만 사용자는 "다르다" 고 느낀다.

**권고**: 절입 당일 ±N시간 출생자에게 `절기 경계 출생` 배지와 설명을 노출. C00 §S1-6 의 `DAY_SHIFTED` 배지와 같은 패턴.

### 5.4 U2 판별 입력 보강

C00 §9.1 U2 의 판별 입력 `2024-06-15 00:10` 은 유효하나, **야자시 판별용 입력은 진태양시 ON 서비스에서 무력화된다**(§1.1 설계 노트). 야자시 판별에는 `23:32` 이후 시각을 쓰도록 U2/C1 판별표를 보강할 것.
