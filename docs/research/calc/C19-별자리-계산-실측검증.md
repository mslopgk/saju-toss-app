### 1.1 ASC 4중 검증 — 세 번째 경로는 "기하학적 정의"

C07 §4.4 는 `atan2` 형과 `Asc1` 형을 대조했으나 **두 식이 같은 입력(RAMC, ε)을 공유**하므로 공식 오타만 잡을 수 있다.
본 문서는 **완전히 다른 정의**로 세 번째 값을 만든다 — "황도(β=0) 위에서 지평고도가 0 이고 방위각이 동쪽 반구인 점".
astronomy-engine 의 `Rotation_ECT_EQD` × `Rotation_EQD_HOR` 회전행렬 체인을 쓰므로 세차·장동·항성시가 **AE 자체 계산**이다.

```js
function altOfEclLon(time, observer, lam) {
  const rot = A.CombineRotation(A.Rotation_ECT_EQD(time), A.Rotation_EQD_HOR(time, observer));
  const v = A.VectorFromSphere(new A.Spherical(0, mod360(lam), 1), time);
  const hs = A.SphereFromVector(A.RotateVector(rot, v));   // AE HOR 기저: +x=north, +y=west, +z=up
  return { alt: hs.lat, az: mod360(-hs.lon) };
}
// 고도 0 근 2개 중 방위각 0<az<180 (동쪽) 인 해 = ASC, 나머지는 DSC
```

## 2. 3자 대조 — astronomy-engine vs Skyfield(DE440s) vs 자체구현

### 2.1 ★ 발견 1 — JS `new Date('...T...')` 는 Z 없으면 **로컬시각**으로 파싱된다

최초 실행에서 AE−SF 편차가 태양 1330″, 달 17,809″, GAST **487,331″** 로 나왔다. 원인:

```js
new Date('2020-01-02T04:33:18.000')      // ← Z 없음 = 로컬시각(KST) 해석 → UTC 로 9시간 밀림
new Date('2020-01-02T04:33:18.000' + 'Z')// ← 올바름
```

**9시간 오차의 물리적 크기**: GAST 9 × 15.041°/h = 135.37° = 487,332″ (관측 487,331″ 일치),
달 9h × 0.549″/s = 17,788″ (관측 17,810″), 태양 9h × 0.041″/s = 1,329″ (관측 1,331″).
→ **프로덕션 체크리스트 항목.** ISO 문자열에 타임존 지정자가 없으면 절대 `new Date()` 에 넣지 말 것.

### 2.2 ★ 발견 2 — 1972 이전 출생은 **UTC 가 아니라 UT1** 로 해석해야 한다

Skyfield 를 `ts.utc(...)` 로 호출하면 1972 이전 구간에서 윤초표 상수(TAI−UTC=10s)를 외삽하므로
`UT1 − UTC = 32.184 + 10 − ΔT` 라는 **가짜 오프셋**이 생긴다. 항성시는 UT1 기반이므로 그대로 GAST 에 실린다.

```js
// 태양궁 = 절기 테이블 이분탐색. 런타임 천체계산 없음.
const MID = SOLAR_TERMS.filter(r => r.sunLng % 30 === 0)
                       .map(r => [Date.parse(r.utc), r.sunLng / 30])
                       .sort((a, b) => a[0] - b[0]);   // 3,540 행 (1851~2145)
function sunSign(instantMs) {
  let lo = 0, hi = MID.length - 1;
  if (instantMs < MID[0][0]) return (MID[0][1] + 11) % 12;
  while (hi - lo > 1) { const m = (lo + hi) >> 1; MID[m][0] <= instantMs ? lo = m : hi = m; }
  return MID[lo][1];
}
```
