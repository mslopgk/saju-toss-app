### 1.1 節/中氣 판별 공식 (결정적)

```
k = λ / 15            (k = 0..23, λ는 15의 배수)
節(jie)  ⟺  k 가 홀수   ⟺  λ mod 30 == 15
中氣(zhongqi) ⟺ k 가 짝수 ⟺ λ mod 30 == 0
```

검증: 입춘 315° → 315 mod 30 = 15 → 節 ✔ / 춘분 0° → 0 mod 30 = 0 → 中氣 ✔
(중국 문헌은 동지(270°)를 1번으로 두고 "홀수번=中氣, 짝수번=節"로 번호를 매기기도 한다.
`λ mod 30` 판별식은 번호 기준과 무관하게 항상 같은 결과를 준다 — 이 식을 쓸 것.)

## 2. 월주(月柱) 결정 규칙 — 결정적 의사코드

```
입력: birthInstant (UTC epoch ms), tzOffsetMinutes (출생지 표준시 오프셋)
출력: sajuMonthIndex(0..11), monthBranch, prevJie, nextJie

1. localMs   = birthInstant                       // 비교는 절대시각(UTC)으로 한다. 로컬변환 불필요
2. jieList   = 절입시각(UTC epoch ms) 오름차순 배열, 출생년 ±1년 범위(총 36개)
3. i         = max{ k : jieList[k].ms <= localMs } // 이분탐색
4. prevJie   = jieList[i];  nextJie = jieList[i+1]
5. sajuMonthIndex = prevJie.sajuMonth - 1
6. 연주 전환: yearForSaju = (localMs >= 해당연도 입춘.ms) ? year : year-1
   (즉 1/1 ~ 입춘 직전 출생은 전년도 간지)
```

**경계 규칙(확정)**: 절입시각 **정각을 포함**한다. `birth >= jieTime` 이면 새 월지.
`>` 로 구현하면 절입 정각 출생자가 전월로 들어가 1분 오차가 아닌 **한 달 오차**가 난다.

실측 경계 테스트 (2025 입춘 = 2025-02-03 23:10:29 KST):

```
생시 2025-02-03 23:09 KST -> 월지 丑 (직전節 소한)
생시 2025-02-03 23:10 KST -> 월지 丑 (직전節 소한)   ← 23:10:00 < 23:10:29
생시 2025-02-03 23:11 KST -> 월지 寅 (직전節 입춘)
생시 2025-02-04 00:00 KST -> 월지 寅 (직전節 입춘)
```

⚠️**유파차이 (분 단위 절사)**: KASI 공표값은 분 단위(23:10)라서 "23:10 출생"을 寅으로 보는 만세력도 있다.
초 단위 절입시각을 쓰면 丑, 분 단위 절사값(23:10)을 쓰면 寅. **초 단위 값을 저장하고 `>=` 비교**를 권장.

## 3. 율리우스일(JD) ↔ 그레고리력 (Meeus Ch.7) — 전체 공식

### 3.1 달력 → JD

```
if (M <= 2) { Y = Y - 1; M = M + 12 }
A = INT(Y / 100)
B = 2 - A + INT(A / 4)          // 그레고리력. 율리우스력(1582-10-04 이전)이면 B = 0
JD = INT(365.25 * (Y + 4716)) + INT(30.6001 * (M + 1)) + D + B - 1524.5
```
- `D` 는 **소수 포함 일**(day + 시각/24).
- `INT()` 는 **바닥함수(floor)**. 음수 연도(BC)에서 truncate 로 구현하면 틀린다.

### 3.2 JD → 달력

```
JD += 0.5
Z = INT(JD);  F = JD - Z
if (Z < 2299161) { A = Z }
else {
  alpha = INT((Z - 1867216.25) / 36524.25)
  A = Z + 1 + alpha - INT(alpha / 4)
}
B = A + 1524
C = INT((B - 122.1) / 365.25)
D = INT(365.25 * C)
E = INT((B - D) / 30.6001)

day   = B - D - INT(30.6001 * E) + F      // 소수 포함
month = (E < 14) ? E - 1 : E - 13
year  = (month > 2) ? C - 4716 : C - 4715
```

### 3.4 파생 상수

```
T   = (JDE - 2451545.0) / 36525.0        // J2000.0 기준 율리우스 세기 (TT)
JDE = JD(TT) ;  JD(UT) = JDE - ΔT/86400
1 율리우스년 = 365.25 d ;  평균 회귀년 = 365.2421896698 d (Meeus 27.1)
태양 황경 평균 이동률 = 360 / 365.2422 = 0.98564736 °/day = 147.84 ″/hour
  ⇒ 황경 1″ 오차 ≒ 시각 24.35초 오차
```

## 4. 태양 겉보기 황경 — Meeus Ch.25 저정밀식 (계수 전체)

입력은 **JDE (TT 기준 율리우스일)**. 출력은 도(deg), [0,360).

```
T  = (JDE - 2451545.0) / 36525.0

(25.2) 기하평균황경 (평균 춘분점 기준)
L0 = 280.46646 + 36000.76983 · T + 0.0003032 · T²

(25.3) 태양(=지구) 평균근점이각
M  = 357.52911 + 35999.05029 · T - 0.0001537 · T²

(25.4) 지구 궤도 이심률
e  = 0.016708634 - 0.000042037 · T - 0.0000001267 · T²

중심차 (equation of center)
C  = (1.914602 - 0.004817·T - 0.000014·T²) · sin(M)
   + (0.019993 - 0.000101·T)              · sin(2M)
   + (0.000289)                           · sin(3M)

진황경 / 진근점이각
⊙true = L0 + C
ν      = M  + C

(25.5) 동경 (AU)
R = 1.000001018 · (1 - e²) / (1 + e·cos ν)
  (근사 대체식: R ≈ 1.00014 - 0.01671·cos M - 0.00014·cos 2M)

장동 + 광행차 → 겉보기 황경
Ω      = 125.04 - 1934.136 · T
λapp   = ⊙true - 0.00569 - 0.00478 · sin(Ω)
```

- `-0.00569°` = −20.4898″ 상당의 **광행차** 상수항(R≈1 가정).
- `-0.00478·sin Ω` = **황경 장동** Δψ 의 주항.
- `Ω` 는 달 궤도 승교점 평균황경.

### 4.1 Meeus 예제 25.a 재현 (1992-10-13.0 TD)

| 값 | 책 | 실행 결과 | 판정 |
|---|---|---|---|
| JDE | 2448908.5 | 2448908.5 | OK |
| T | −0.072183436 | −0.072183436003 | OK |
| L0 | 201.80720° | 201.80720° | OK |
| M | 278.99397° | 278.99397° | OK |
| λapp | 199.90895° | **199.90894°** | OK (0.00001° = 0.036″) |
| R | 0.99766 (저정밀) | 0.99766195 | OK |

> 참고: 같은 순간에 대해 고정밀(VSOP87, 예제 25.b) R = 0.99760775, λ = 199.90988°(FK5/장동 전).
> **저정밀식과 고정밀식의 λ 차이가 이미 이 한 예제에서 0.001° = 3.6″ ≒ 88초** 수준이다.

### 4.2 실행 가능 구현 (발췌 — `meeus.js`)

```js
const D2R = Math.PI/180, sind = d => Math.sin(d*D2R);
const mod360 = x => ((x % 360) + 360) % 360;

function sunApparentLongitudeLow(jde) {
  const T  = (jde - 2451545.0) / 36525.0;
  const L0 = 280.46646 + 36000.76983*T + 0.0003032*T*T;
  const M  = 357.52911 + 35999.05029*T - 0.0001537*T*T;
  const C  = (1.914602 - 0.004817*T - 0.000014*T*T) * sind(M)
           + (0.019993 - 0.000101*T)                * sind(2*M)
           +  0.000289                              * sind(3*M);
  const trueLong = L0 + C;
  const Om = 125.04 - 1934.136*T;
  return mod360(trueLong - 0.00569 - 0.00478*sind(Om));
}
```

## 5. ΔT (TT − UT) — Espenak & Meeus 다항식 전체

절기 시각은 **TT(=JDE)** 로 나온다. 사용자가 보는 시각은 **UT/UTC 기반 지방시**이므로 반드시 빼야 한다.

```
UT = TT - ΔT
KST = UT + 9h  (1961-08-10 이후. 그 이전은 §11 참조)
```

`y = year + (month - 0.5) / 12` (십진 연도)

| 구간 | 치환 | ΔT (초) |
|---|---|---|
| 1800 ≤ y < 1900 | t = y − 1860 | 7.62 + 0.5737t − 0.251754t² + 0.01680668t³ − 0.0004473624t⁴ + t⁵/233174 |
| 1900 ≤ y < 1920 | t = y − 1900 | −2.79 + 1.494119t − 0.0598939t² + 0.0061966t³ − 0.000197t⁴ |
| 1920 ≤ y < 1941 | t = y − 1920 | 21.20 + 0.84493t − 0.076100t² + 0.0020936t³ |
| 1941 ≤ y < 1961 | t = y − 1950 | 29.07 + 0.407t − t²/233 + t³/2547 |
| 1961 ≤ y < 1986 | t = y − 1975 | 45.45 + 1.067t − t²/260 − t³/718 |
| 1986 ≤ y < 2005 | t = y − 2000 | 63.86 + 0.3345t − 0.060374t² + 0.0017275t³ + 0.000651814t⁴ + 0.00002373599t⁵ |
| 2005 ≤ y < 2050 | t = y − 2000 | 62.92 + 0.32217t + 0.005589t² |
| 2050 ≤ y < 2150 | — | −20 + 32·((y−1820)/100)² − 0.5628·(2150 − y) |
| y ≥ 2150 | u = (y−1820)/100 | −20 + 32u² |

> 분 단위 표기에서 74초는 1~2분 오차로 드러나므로 반드시 적용해야 한다.
> ⚠️ 2050년 이후는 예측 ΔT라 불확실성이 수 초~수십 초. 사주 앱은 실질적으로 과거 날짜만 다루므로 문제 없음.

## 6. VSOP87 vs 저정밀 근사식 — 오차 실측

### 6.1 저정밀식의 이론 오차

- Meeus 는 §25 저정밀식의 정확도를 **약 0.01°(=36″)** 로 명시.
- 36″ ÷ 147.84 ″/h = **0.244 h = 14.6 분**.

## 7. 절기 시각 역산 알고리즘 (λ = 목표값이 되는 JD 찾기)

목표: 주어진 `λtarget ∈ {0,15,…,345}` 에 대해 `λapp(JDE) = λtarget` 인 JDE.

### 7.1 초기 추정 (bracket)

```
baseYear = (λtarget >= 285) ? year - 1 : year        // 소한·대한·입춘·우수·경칩은 전년 춘분 기준
JDE0 = JD(baseYear, 3, 20.5) + λtarget / 0.98564736  // 춘분 기준 선형 외삽
오차 ±3일 이내 (지구 궤도 이심률 때문)
```

⚠️ `baseYear` 분기를 빠뜨리면 소한/대한/입춘/우수/경칩이 **1년 밀린다**. 실제로 첫 구현에서 이 버그가 났다.

### 7.2 방법 A — Meeus Ch.27 고정점 반복 (가장 단순, 실전 권장)

```
function findLongitude(target, jde0):
    jde = jde0
    repeat up to 60 times:
        λ    = apparentLongitude(jde)
        diff = normalize180(target - λ)          // [-180, 180)
        corr = 58.0 * sin(diff)                  // 단위: 일.  58 ≈ 365.25 / (2π)
        jde  = jde + corr
        if |corr| < 1e-8 : break                 // 1e-8 d ≈ 0.86 ms
    return jde
```
- 수렴차수 1차지만 계수 58이 도함수 역수(1/0.9856 ≈ 1.0146 d/°, ×57.2958 = 58.1)와 사실상 같아 **실질 뉴턴법**.
- pymeeus 는 임계값 `|corr| > 0.0000025` (≈0.2초) 를 쓴다.

### 7.3 방법 B — 수치미분 뉴턴법 (본 프로젝트 채택)

```js
function findLongitudeNewton(targetDeg, jdeGuess, lonFn) {
  let jde = jdeGuess;
  const h = 1 / 1440;                                   // 1분
  for (let i = 0; i < 50; i++) {
    const f    = mod360(lonFn(jde)     - targetDeg + 180) - 180;   // 부호 있는 오차
    const f2   = mod360(lonFn(jde + h) - targetDeg + 180) - 180;
    const dfdt = (f2 - f) / h;                          // ≈ 0.9856 deg/day
    const step = -f / dfdt;
    jde += step;
    if (Math.abs(step) < 1e-9) break;                   // 1e-9 d ≈ 86 µs
  }
  return jde;
}
```
- 실측 반복 횟수: **3~4회**에 1e-9 d 수렴.
- `mod360(x + 180) - 180` 트릭이 0°/360° 경계(춘분)에서의 랩어라운드를 자동 처리한다.

### 7.4 방법 C — 이분법 (안전망)

```js
function findLongitudeBisect(target, jdeLo, jdeHi, lonFn) {
  const g = t => mod360(lonFn(t) - target + 180) - 180;
  let lo = jdeLo, hi = jdeHi, flo = g(lo);
  if (flo * g(hi) > 0) throw new Error('bracket fail');
  for (let i = 0; i < 80; i++) {                 // 80회면 (hi-lo)/2^80, 사실상 기계정밀도
    const mid = (lo + hi) / 2, fm = g(mid);
    if (flo * fm <= 0) hi = mid; else { lo = mid; flo = fm; }
    if (hi - lo < 1e-9) break;
  }
  return (lo + hi) / 2;
}
```
- bracket: `[JDE0 - 3, JDE0 + 3]`. 이 구간에서 λ는 단조증가(태양 황경은 항상 순행)이므로 부호변화 1회 보장.
- 40회 반복이면 6일/2⁴⁰ ≈ 5.5e-12 d ≈ 0.5 µs.

### 7.5 astronomy-engine 사용 시

```js

// λtarget 도달 순간을 [start, start+limitDays] 에서 탐색

// t.date = JS Date (UTC). ΔT/장동/광행차는 라이브러리 내부에서 처리됨.
```
⚠️ `limitDays` 를 400 같이 크게 주면 **null 반환**(랩어라운드로 bracket 실패). 반드시 추정치 ±15일로 좁힐 것.

## 10. 사전계산 테이블 전략 — 크기 실측

### 10.1 레코드 수

```
12절  × 201년 (1900–2100) = 2,412 레코드
24절기 × 201년             = 4,824 레코드
```

### 10.2 인코딩별 실측 크기 (Node zlib, level 9 / brotli 기본)

| 인코딩 | raw | gzip | brotli |
|---|---|---|---|
| 1) JSON verbose — `{y, term, branch, utc(ISO)}` × 2412 | 164,017 B | 21,023 B | 10,639 B |
| 2) JSON flat int — 절대 분(1900 epoch) × 2412 | 21,583 B | 10,124 B | 9,055 B |
| 3) JSON delta — 직전 절기와의 분 차이 × 2412 | 15,075 B | 3,337 B | **2,015 B** |
| 4) **BIN int16 — 선형모델 잔차** × 2412 | **4,824 B** | 3,172 B | 2,304 B |
| 4b) 4)를 base64 로 JS 소스에 인라인 | 6,432 B | 3,404 B | 2,766 B |
| 5) BIN uint32 — 24절기 절대 분 × 4824 | 19,296 B | 17,815 B | 15,790 B |

### 10.3 권장: 선형모델 + int16 잔차 (인코딩 4)

```
t(j, y) [1900-01-01T00:00Z 기준 분] = round( A[j] + B * (y - 1900) ) + resid16[ (y-1900)*12 + j ]

B    = 365.2422 * 1440 = 525948.768   (분/년)
A[j] = 1900년 각 節의 EPOCH-분 (j = 입춘,경칩,청명,입하,망종,소서,입추,백로,한로,입동,대설,소한 순)
A = [49312, 92182, 135713, 179995, 224919, 270190,
     315411, 360197, 404293, 447640, 490376, 6844]
```

- 실측 잔차 범위: **−165 … +181 분** → int16(±32767) 로 여유 충분. int8은 불가.
- 무손실 왕복 검증: **PASS** (2,412건 전부 원값 복원)
- 분 단위 저장 = 최대 30초 절사 오차. **초 단위가 필요하면 int32 초-잔차(9,648 B)** 를 쓴다.
  → 잔차 범위 ±181분 = ±10,860초 이므로 초 단위도 int16 범위 초과. int32 또는 int16(분)+uint8(초) 하이브리드.

### 10.4 하이브리드 권장안 (초 정밀 + 소형)

```
레코드 = int16 residMinutes + uint8 seconds   → 3 B/레코드
12절 × 201년 = 2,412 × 3 B = 7,236 B  (gzip ≈ 4.5 KB)
```

### 10.5 런타임 라이브러리 대안 크기

| 파일 | raw | gzip | brotli |
|---|---|---|---|
| astronomy-engine/astronomy.browser.js | 422,170 B | 110,173 B | 86,978 B |

### 10.6 빌드 파이프라인


## 11. 시간대 — 절입시각과 출생시각의 정합 (⚠️유파차이 집중 구역)

### 11.1 절대시각으로 비교하라

절기는 **천문 사건**이므로 시간대와 무관한 절대순간(UTC)이다.
출생시각도 UTC로 환산한 뒤 비교하면 시간대 문제가 전부 사라진다.

```
monthBranch = lookup(birthUTCms)     // 절입 테이블도 UTC로 저장
```

### 11.2 한국 표준시 변경 이력

| 기간 | 오프셋 | 비고 |
|---|---|---|
| ~1908 | 지방 평시 | |
| 1908 ~ 1912 | **UTC+8:30** | 대한제국 표준시 (127.5°E) |
| 1912 ~ 1954 | **UTC+9:00** | 일제강점기, 일본 표준시(135°E)에 통합 |
| 1954 ~ 1961 | **UTC+8:30** | 이승만 정부 환원 |
| 1961 ~ 현재 | **UTC+9:00** | 박정희 군사정부 재변경 |
| 1988-05-08 ~ 1988-10-09 | +1h DST | 서울올림픽 서머타임 |

⚠️ 정확한 전환 **일자**(1908-04-01 / 1912-01-01 / 1954-03-21 / 1961-08-10)와
1948~1951, 1955~1960 서머타임 구간은 **IANA tz database `Asia/Seoul` 을 원본으로 삼아야 한다.**
[미검증 — 위키백과 요약에는 연도만 있고 일자가 없음. tzdata 원본 확인 필요]

**영향**: 사용자가 "1955-05-06 03:20 출생" 이라고 입력하면 그 로컬시각은 **UTC+8:30 + 서머타임** 일 수 있어
UTC 환산이 최대 1시간 30분 어긋난다. 절입시각이 아무리 정확해도 여기서 월주가 뒤집힌다.
→ **tzdata 기반 로컬→UTC 변환이 절입 정밀도보다 훨씬 큰 오차원이다.**

### 11.3 진태양시 / 지방시 보정 (유파차이)

| 유파 | 규칙 | 결과 차이 |
|---|---|---|
| A. 표준시 그대로 | 입력 시각을 KST(135°E)로 간주 | 기준 |
| B. 지방 평시 보정 | 경도차 보정: `Δ = (경도 − 135) × 4분`. 서울(126.978°E) → **−32.1분** | 시주 경계(2시간)에서 약 27% 확률로 시주 변동 |
| C. 진태양시 | B + 균시차(Equation of Time, ±16분) | B 대비 최대 ±16분 추가 |

균시차 계산식 (Meeus 28.3, 분 단위 = deg/15 × 60):

```
E [도] = L0 - 0.0057183 - α_app + Δψ·cos ε
      (근사) E [분] ≈ 9.87·sin(2B) - 7.53·cos(B) - 1.5·sin(B),  B = 360·(N-81)/364
```

⚠️**월주에 대한 영향**: B/C 보정은 최대 48분. 절입 자정 근처(2.07%) 케이스에서 **날짜가 바뀔 수 있다.**
대부분의 한국 만세력은 **월주에는 보정 안 함, 시주에만 적용**한다(선택 A+B 혼용).
→ 프로덕트 결정 필요: `useLocalMeanTime: 'none' | 'longitude' | 'trueSolar'` 로 옵션화하고 기본값 `'none'`.

### 11.4 중국 vs 한국

중국 八字 자료(GB/T 33661-2017 기준)는 **동경 120°(UTC+8)** 로 절기 시각을 공표한다.
KASI는 UTC+9. **동일 순간이지만 표기가 1시간 다르다.** 중국 표를 그대로 쓰면 절입시각이 1시간 틀린다.
GB/T 33661-2017 은 절기·삭 시각을 **약 1초 정확도**로 계산할 것을 요구한다.

## 12. 대운수(大運數) — 절기 의존 계산

```
입력: birthUTCms, 성별(M/F), 년간 음양(陽=甲丙戊庚壬, 陰=乙丁己辛癸)
방향: forward = (陽男 or 陰女)      // 순행
      backward = (陰男 or 陽女)     // 역행

순행: Δd = (nextJie.ms - birthUTCms) / 86400000    [일]
역행: Δd = (birthUTCms - prevJie.ms) / 86400000    [일]

대운수 = Δd / 3
```

⚠️**유파차이 (반올림 규칙)** — 결과가 1 차이남:

| 유파 | 규칙 | 1990-05-20 14:30 KST 陽男 예시 (Δd=16.719756일 → 5.5733) |
|---|---|---|
| A. 반올림 | `round(Δd/3)`, 0이면 1 | **6** |
| B. 버림 | `floor(Δd/3)`, 0이면 1 | **5** |
| C. 3일=1년, 1일=4개월, 1시간=5일 | 5년 + 2일×4개월 + … = 5년 2.4개월 | **5세 2개월** |

실행 검증:
```
1990-05-20 14:30 KST 출생
  직전節 = 입하 1990-05-06 03:35 KST
  다음節 = 망종 1990-06-06 07:46 KST
  順行(陽男): 다음節까지 16.719756일 → /3 = 5.573252 → 반올림 6 / 버림 5
  逆行(陰男): 직전節부터 14.454448일 → /3 = 4.818149 → 반올림 5 / 버림 4
```

**요구 정밀도 역산**: 대운수가 1 바뀌려면 Δd 가 3일의 절반(1.5일) 근처 경계를 넘어야 한다.
절입시각 오차 ε 가 대운수를 바꿀 확률 ≈ `2ε / 259200 s` (3일 주기).
```
ε = 60 s  → 0.046 %
ε = 859 s → 0.66 %       (Meeus 저정밀 최악값)
```
월주(1.99%)보다는 완만하지만 여전히 무시 불가.

## 13. 최종 구현 코드 (전체)

### 13.1 `solarTerms.ts` — 런타임(테이블 방식)

```ts
// ── 상수 ────────────────────────────────────────────────
const EPOCH_MS = Date.UTC(1900, 0, 1);        // 1900-01-01T00:00:00Z
const B_MIN_PER_YEAR = 365.2422 * 1440;       // 525948.768
const A_MIN = [49312, 92182, 135713, 179995, 224919, 270190,
               315411, 360197, 404293, 447640, 490376, 6844];
const JIE_LON  = [315, 345, 15, 45, 75, 105, 135, 165, 195, 225, 255, 285];
const JIE_KO   = ['입춘','경칩','청명','입하','망종','소서','입추','백로','한로','입동','대설','소한'];
const JIE_BR   = ['寅','卯','辰','巳','午','未','申','酉','戌','亥','子','丑'];
const Y0 = 1900, Y1 = 2100;

// resid: Int16Array(2412) 분 잔차,  sec: Uint8Array(2412) 초
declare const RESID: Int16Array;
declare const SEC:   Uint8Array;

/** j: 0..11 (입춘..소한), year: 1900..2100 → UTC epoch ms */
export function jieTimeMs(year: number, j: number): number {
  const i = (year - Y0) * 12 + j;
  const min = Math.round(A_MIN[j] + B_MIN_PER_YEAR * (year - Y0)) + RESID[i];
  return EPOCH_MS + min * 60000 + SEC[i] * 1000;
}

export interface JieHit { j: number; year: number; ms: number; ko: string; branch: string; sajuMonth: number; }

/** 출생 절대시각(UTC ms) → 직전/다음 節 */
export function findJie(birthMs: number): { prev: JieHit; next: JieHit } {
  const y = new Date(birthMs).getUTCFullYear();
  const list: JieHit[] = [];
  for (const yy of [y - 1, y, y + 1]) {
    if (yy < Y0 || yy > Y1) continue;
    for (let j = 0; j < 12; j++)
      list.push({ j, year: yy, ms: jieTimeMs(yy, j),
                  ko: JIE_KO[j], branch: JIE_BR[j], sajuMonth: j + 1 });
  }
  list.sort((a, b) => a.ms - b.ms);
  // 이분탐색: 마지막 ms <= birthMs
  let lo = 0, hi = list.length - 1, k = 0;
  while (lo <= hi) {
    const mid = (lo + hi) >> 1;
    if (list[mid].ms <= birthMs) { k = mid; lo = mid + 1; } else hi = mid - 1;
  }
  return { prev: list[k], next: list[k + 1] };
}

/** 월지 인덱스(0=寅) */
export function monthBranchIndex(birthMs: number): number {
  return findJie(birthMs).prev.j;
}

/** 사주 연도(입춘 기준) */
export function sajuYear(birthMs: number): number {
  const y = new Date(birthMs).getUTCFullYear();
  return birthMs >= jieTimeMs(y, 0) ? y : y - 1;   // j=0 = 입춘
}

/** 대운수 */
export function daeunNumber(birthMs: number, forward: boolean,
                            rule: 'round' | 'floor' = 'round'): number {
  const { prev, next } = findJie(birthMs);
  const days = (forward ? next.ms - birthMs : birthMs - prev.ms) / 86400000;
  const n = rule === 'round' ? Math.round(days / 3) : Math.floor(days / 3);
  return n === 0 ? 1 : n;
}
```

### 13.2 `build-table.ts` — 빌드 타임 생성기

```ts
import * as AE from 'astronomy-engine';
const JIE_LON = [315, 345, 15, 45, 75, 105, 135, 165, 195, 225, 255, 285];

function jieUTCms(year: number, lon: number): number {
  const base  = lon >= 285 ? year - 1 : year;                   // ← 필수 분기
  const guess = Date.UTC(base, 2, 20) + (lon / 0.98564736) * 86400000;
  const t = AE.SearchSunLongitude(lon, new Date(guess - 15 * 86400000), 30);
  if (!t) throw new Error(`search failed ${year} ${lon}`);
  return t.date.getTime();
}

const EPOCH = Date.UTC(1900, 0, 1), B = 365.2422 * 1440;
const A: number[] = JIE_LON.map(lon => Math.round((jieUTCms(1900, lon) - EPOCH) / 60000));
const resid = new Int16Array(201 * 12), sec = new Uint8Array(201 * 12);

for (let y = 1900; y <= 2100; y++) for (let j = 0; j < 12; j++) {
  const ms   = jieUTCms(y, JIE_LON[j]);
  const tmin = Math.floor((ms - EPOCH) / 60000);
  const tsec = Math.round((ms - EPOCH - tmin * 60000) / 1000);
  const pred = Math.round(A[j] + B * (y - 1900));
  const i = (y - 1900) * 12 + j;
  resid[i] = tmin - pred;              // 실측 범위 −165..+181 → int16 OK
  sec[i]   = tsec;                     // 0..59
}
```

### 13.3 폴백 (테이블 범위 밖: 1899 이하 / 2101 이상)

```js
// Meeus 저정밀식 + 뉴턴법. 정확도 ±14분 → UI에 "근사값" 배지 표시
function jieTimeFallback(year, lon) {
  const base = lon >= 285 ? year - 1 : year;
  const jde0 = gregorianToJD(base, 3, 20.5) + lon / 0.98564736;
  const jde  = findLongitudeNewton(lon, jde0, sunApparentLongitudeLow);   // TT
  const cal  = jdToGregorian(jde);
  const jdUT = jde - deltaTSeconds(cal.year, cal.month) / 86400;
  return (jdUT - 2440587.5) * 86400000;   // UTC epoch ms
}
```
