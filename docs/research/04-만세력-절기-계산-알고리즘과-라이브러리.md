## 1. 사주 4기둥의 계산 기준 — 무엇이 무엇에 의존하는가

사주 계산은 "달력 변환"이 아니라 **태양 황경(黃經) 기반 절기력** 계산이다. 음력은 사실상 필요 없다.

| 기둥 | 기준 | 필요한 입력 | 음력 필요? |
|---|---|---|---|
| 연주(年柱) | **입춘(立春) 절입 순간** | 절대 시각(UTC) | ✗ |
| 월주(月柱) | **12개 절(節)의 절입 순간** | 절대 시각(UTC) | ✗ |
| 일주(日柱) | 60갑자 순환 (율리우스일) | **지방 진태양시** 기준 날짜 | ✗ |
| 시주(時柱) | 일간(日干) + 시진(時辰) | **지방 진태양시** 기준 시각 | ✗ |

핵심 구분 (`manseryeok/src/time/true-solar-time.ts` 주석에서 확인):

```
- 연주/월주: 절기(절입)는 천문학적 절대 순간이므로 instantUTCms 로 판정한다.
- 일주/시주: 태양의 실제 위치(지방 진태양시)로 판정하므로 apparentMs 를 사용한다.
```

즉 **연/월주와 일/시주는 서로 다른 시간축을 쓴다.** 이걸 뭉뚱그려 하나의 보정 시각으로 처리하는 구현이 흔한데, 절입 경계 ±30분 케이스에서 오답이 난다.

음력은 "음력 생일 입력" UX와 띠(생초) 표시용으로만 필요하다.

## 2. 24절기 — 황경 기준 정확 계산

### 2.1 절기 = 태양 황경 15° 간격

춘분(황경 0°)을 기점으로 황도를 15°씩 24등분한다. (ko.wikipedia 「절기」, 검색 결과 확인)

`manseryeok/src/astro/solar-terms.ts` 원문:

```
절기 인덱스는 0=소한 … 23=동지 순서이며, 각 인덱스의 황경은 (285 + 15*index) mod 360.
짝수 인덱스가 '절(節)'로 월(月)의 시작을 결정한다 (예: index 2 = 입춘 = 인월 시작).
```

### 2.3 절입 시각을 구하는 실제 절차

목표: "황경이 정확히 L°가 되는 순간(분 단위)"을 찾는 것. 순서는 **황경 → 시각(역방향)** 이라 해석해가 없고 수치해법이 필요하다.

블로그 「정확한 24절기 시각을 계산하는 방법」(cal20000.blogspot.com)에서 확인한 저정밀 근사 공식:

```
d = 기준일(2012-12-31 00:00 UT)로부터 경과 일수

평균황경   L = 279.827287 + 0.98564736 × d
평균근점이각 M = 356.666444 + 0.98560028 × d
중심차      E = 1.919°·sin(M) + 0.020°·sin(2M) - 0.005°·sin(M·T)     (T=1, 2000년대)

진황경 = (L + E) mod 360
```

상수: 회귀년 365.242190일, 근점년 365.259636일, 이심률 ≈ 0.016703.

시각 탐색은 **이진탐색**:
1. 목표 황경을 사이에 두는 두 날짜 d₀, d₁을 잡는다
2. 시(hour) 단위로 좁힌다 (최대 23회)
3. 분(minute) 단위로 좁힌다 (최대 59회)
4. 이진탐색을 쓰면 총 15~16회 반복으로 수렴 (선형 탐색은 약 88회)

**정확도 한계**: 이 근사식은 춘분 기준 약 **7.5분** 오차 수준. 절입 경계에 태어난 사람의 월주가 통째로 바뀔 수 있으므로 **프로덕션에는 부족하다.**

더 정확한 접근(검색 결과에서 언급): VSOP87(평균황경) + DE404(진황경) 조합으로 **오차 1분 미만** 달성 가능. `[미검증]` — 원 논문/구현체를 직접 확인하지 못함.

### 2.4 실전 해법 — 사전계산 보정표

`manseryeok`이 택한 방식이 실용적이다. `src/astro/solar-terms-data.ts` 헤더 원문:

```
24절기 절입 보정표 (1800~2300).
출처: 6tail/lunar-javascript 의 천문 계산값을 개발 시점에 추출(tools/gen-solar-terms.mjs).
저장값은 런타임 Meeus 근사 대비 '분(minute) 보정'을 base64 1글자(-31..31)로 패킹한 것이다.
실제 절입 분 = round(Meeus 분) + 보정. 범위 밖 연도는 보정 0(=Meeus 근사, 오차 ≈ 수 분).
```

- `SOLAR_TERM_DATA_MIN_YEAR = 1800`, `SOLAR_TERM_DATA_MAX_YEAR = 2300`
- 패킹: `(year-1800)*24 + index` 위치에 1문자, ALPHABET = `A-Za-z0-9+/`, OFFSET = 31 (즉 -31~+31분)
- 501년 × 24절기 = **12,024 문자** ≈ 12KB. 압축 전 문자열로도 매우 가볍다

**이 패턴을 그대로 채택 권장**: 런타임에 Meeus 근사만 돌리고, 서비스 대상 연도(예: 1900~2060 = 3,840자 ≈ 3.8KB)만 분 단위 보정표로 덮어쓴다. 토스 미니앱 번들 부담이 사실상 0에 수렴한다.

## 3. 연주 — 입춘 기준

- 연주는 **1월 1일도, 음력 설날도 아니고 입춘 절입 순간**을 경계로 한다 (namu.wiki 「사주팔자」: "The year changes at Lichun (입춘, Feb 3-5), not at Lunar New Year")
- 입춘 절입 **시각 이전** 출생이면 전년도 간지
- 예: 2026-02-04 10:00 입춘이라면, 2026-02-04 09:59 출생 = 2025년(을사) 연주 / 10:01 출생 = 2026년(병오) 연주

### 연간 공식 (manseryeok `src/pillars.ts` 원문)

```ts
function getYearPillar(sajuYear: number): Pillar {
  return {
    heavenlyStem: HEAVENLY_STEMS[mod(sajuYear - 4, 10)],
    earthlyBranch: EARTHLY_BRANCHES[mod(sajuYear - 4, 12)],
  };
}
```

즉 `천간 = (년 - 4) mod 10`, `지지 = (년 - 4) mod 12` (0=갑/자).
en.wikipedia 「Sexagenary cycle」의 `(year - 3) mod 60` 과 동치다 (1-based vs 0-based 차이).

검산: 2026 → (2026-4) mod 10 = 2022 mod 10 = 2 = 병, (2026-4) mod 12 = 2022 mod 12 = 6 = 오 → **병오년** ✓

## 4. 월주 — 절기 기준 + 월두법(五虎遁)

월지는 §2.2 표대로 절입으로 정해지고, **월간은 연간에서 유도**한다.

### manseryeok 실제 구현

```ts
function getMonthPillar(sajuYear: number, monthNumber: number): Pillar {
  const yearStem = mod(sajuYear - 4, 10);
  const yearStemMod5 = yearStem % 5;
  // 오호둔(五虎遁): 인월(1)부터 월간 전개
  const monthStemIndex = (yearStemMod5 * 2 + monthNumber + 1) % 10;
  return { heavenlyStem: HEAVENLY_STEMS[monthStemIndex], earthlyBranch: MONTH_BRANCHES[monthNumber] };
}
```

`MONTH_BRANCHES = {1:'인', 2:'묘', 3:'진', 4:'사', 5:'오', 6:'미', 7:'신', 8:'유', ...}`

### 월두법(月頭法) = 오호둔월(五虎遁月) 표

이름 유래: "한 해는 인월(寅月)에 시작하는데, 인(寅)은 호랑이이므로 호랑이 호(虎) 자를 써서 오호둔월"

전통 구결: **갑기지년병작수(甲己之年丙作首), 을경지세무위두(乙庚之歲戊爲頭), 병신지세심경상(丙辛之歲尋庚上), 정임임위순행류(丁壬壬位順行流), 무계하방발갑인지상호추구(戊癸何方發 甲寅之上好追求)**

| 연간 | 인월(1월) 월간 | 이후 |
|---|---|---|
| 갑(甲)·기(己) | **병(丙)인월** | 정묘 → 무진 → 기사 … |
| 을(乙)·경(庚) | **무(戊)인월** | 기묘 → 경진 … |
| 병(丙)·신(辛) | **경(庚)인월** | 신묘 → 임진 … |
| 정(丁)·임(壬) | **임(壬)인월** | 계묘 → 갑진 … |
| 무(戊)·계(癸) | **갑(甲)인월** | 을묘 → 병진 … |

코드 검산: 갑년(yearStem=0) → (0×2 + 1 + 1) % 10 = 2 = 병 ✓ / 무년(yearStem=4) → (4%5×2 + 1 + 1) = 10 % 10 = 0 = 갑 ✓ — **구결과 완전히 일치.**

### 5.2 통합 공식 (직접 계산으로 교차검증)

JDN(정오 기준 정수 율리우스일)을 다음 표준식으로 구한 뒤:

```
a  = (14 - month) / 12          (정수 나눗셈)
y  = year + 4800 - a
m  = month + 12a - 3
JDN = day + (153m + 2)/5 + 365y + y/4 - y/100 + y/400 - 32045
```

**60갑자 인덱스 (0 = 갑자):**

```
gapjaIndex = (JDN + 49) mod 60
천간 = gapjaIndex mod 10      // 0=갑 1=을 2=병 3=정 4=무 5=기 6=경 7=신 8=임 9=계
지지 = gapjaIndex mod 12      // 0=자 1=축 2=인 3=묘 4=진 5=사 6=오 7=미 8=신 9=유 10=술 11=해
```

lunar-javascript의 `(JDN - 11) mod 10 / mod 12` 와 동치다 (-11 ≡ +49 mod 60).

**실제 검산 (Python으로 직접 수행):**

| 날짜 | JDN | (JDN+49) mod 60 | 간지 | 대조 |
|---|---|---|---|---|
| 1992-10-24 | 2,448,920 | 9 | 계유(癸酉) | manseryeok 앵커값 9와 일치 ✓ |
| 2000-01-01 | 2,451,545 | 54 | 무오(戊午) | 국내 만세력 자료 "2000-01-01 = 무오일"과 일치 ✓ |
| 1900-01-01 | 2,415,021 | 10 | 갑술(甲戌) | — |
| 2026-08-11 | 2,461,264 | 53 | 정사(丁巳) | — |

세 개의 독립 출처(6tail 코드 / manseryeok 앵커 / 한국 만세력 자료)가 일치 → **이 공식은 신뢰 가능.**

### 5.3 주의: en.wikipedia의 SB 공식은 쓰지 말 것

en.wikipedia 「Sexagenary cycle」이 제시하는

```
SB = (y + c + m + day) mod 60
y  = (year mod 400 mod 80 mod 12 × 5 + ⌊year mod 400 mod 80 / 4⌋) mod 60
c  = ⌊year/400⌋ - ⌊year/100⌋ + 10   (그레고리력)
m  = (month+1) mod 2 × 30 + ⌊0.6×(month+1) - 3⌋ - i   (i = 5 평년 / 6 윤년 1·2월)
```

은 결과는 맞지만 분기가 많고 버그 유발 지점이 많다. **JDN 방식이 압도적으로 단순하고 안전하다.**

## 6. 시주 — 시두법(五鼠遁) + 시진 경계

### 6.1 12시진 시각표 (표준시 기준, namu.wiki)

| 시진 | 시간 | 시진 | 시간 |
|---|---|---|---|
| 자(子) | 23:00–01:00 | 오(午) | 11:00–13:00 |
| 축(丑) | 01:00–03:00 | 미(未) | 13:00–15:00 |
| 인(寅) | 03:00–05:00 | 신(申) | 15:00–17:00 |
| 묘(卯) | 05:00–07:00 | 유(酉) | 17:00–19:00 |
| 진(辰) | 07:00–09:00 | 술(戌) | 19:00–21:00 |
| 사(巳) | 09:00–11:00 | 해(亥) | 21:00–23:00 |

manseryeok 구현 (지방 진태양시 기준):

```ts
function shichenForApparent(apparentMs: number): number {
  const d = new Date(apparentMs);
  const totalMinutes = d.getUTCHours() * 60 + d.getUTCMinutes();
  return Math.floor(((totalMinutes + 60) % 1440) / 120);   // 0=자 … 11=해
}
```

검산: 23:00(=1380분) → (1440 mod 1440)/120 = 0 = 자 ✓ / 01:00(=60분) → 120/120 = 1 = 축 ✓

### 6.2 시두법(時頭法) = 오서둔시(五鼠遁時)

이름 유래: "하루는 자시(子時)에 시작하는데, 자(子)는 쥐이므로 쥐 서(鼠) 자를 써서 오서둔시"

```ts
function getHourPillar(dayStemIndex: number, shichen: number): Pillar {
  const hourStemBase = (dayStemIndex % 5) * 2;
  const hourStemIndex = (hourStemBase + shichen) % 10;
  return { heavenlyStem: HEAVENLY_STEMS[hourStemIndex], earthlyBranch: EARTHLY_BRANCHES[shichen] };
}
```

| 일간 | 자시 | 축시 | 인시 | 묘시 | 진시 | 사시 | 오시 | 미시 | 신시 | 유시 | 술시 | 해시 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|

| 병(丙)·신(辛) | **무자** | 기축 | 경인 | 신묘 | 임진 | 계사 | 갑오 | 을미 | 병신 | 정유 | 무술 | 기해 |

## 7. 진태양시 / 균시차 / 표준시 보정 — 가장 논쟁적인 부분

### 7.1 경도 보정 (핵심 수치)

| 항목 | 값 |
|---|---|
| 한국 표준시(KST) 기준 자오선 | **동경 135°** (UTC+9, 실은 일본 아카시 통과) |
| 서울 경도 | **동경 126.98°** |
| 경도차 | 135 − 126.98 = **8.02°** |
| 시간 환산 | 8.02° × 4분/° = **약 32.1분** → 서울은 표준시보다 태양시가 **약 32분 늦음** |
| 한반도 평균 자오선(대체 관법) | **동경 127.5°** → 보정 **-30분** |

`manseryeok/src/time/true-solar-time.ts` 상수:

```ts
const KST_STANDARD_MERIDIAN = 135;
const KST_OFFSET_MIN = 540;
/** 한반도 평균 자오선 (기본 출생 경도) */
export const DEFAULT_LONGITUDE = 127.5;
```

→ **manseryeok 기본값은 -30분 관법**(127.5°). 서울 정밀값(-32분)을 쓰려면 `longitude: 126.98` 을 명시해야 한다. **이 1~2분 차이가 시진 경계에서 결과를 바꾼다.**

sajumanse.com도 "서울(동경 약 127도)의 경우 표준시보다 태양시가 약 32분 늦습니다"라고 기술.

### 7.2 균시차(Equation of Time)

- 태양의 남중 시각은 계절에 따라 **최대 약 16분**까지 차이 (sajumanse.com)
- 실제 연중 범위는 대략 -14분 ~ +16분 `[미검증 — 정확한 극값은 별도 확인 필요]`
- manseryeok은 `equationOfTimeMinutes(instantUTCms)` 로 계산하며 `applyEquationOfTime` 옵션(기본 true)으로 on/off

### 7.3 최종 환산식 (manseryeok 원문)

```ts
const longitude     = options.longitude ?? DEFAULT_LONGITUDE;      // 127.5
const civilOffsetMin = applyDst ? koreaCivilOffsetMin(y, m, d, h) : KST_OFFSET_MIN;

const instantUTCms = wallMs - civilOffsetMin * MINUTE_MS;                    // 절대 순간 → 연/월주
const eotMin       = applyEoT ? equationOfTimeMinutes(instantUTCms) : 0;
const apparentMs   = instantUTCms + (longitude * 4 + eotMin) * MINUTE_MS;    // 지방 진태양시 → 일/시주
```

옵션 미지정 시 하위호환 동작: `longitude=135, 균시차=0, 서머타임 미적용` → 입력 벽시계 = KST 그대로.

## 8. 야자시(夜子時) / 조자시(朝子時) 논쟁

### 8.1 세 가지 관법

23:00~23:59 출생 시 일주와 시주가 갈린다.

| 관법 | 일주(日柱) | 시주(時柱) 천간 기준 | manseryeok 옵션값 |
|---|---|---|---|
| **정자시(正子時)** / 자정 기준 | 당일 | 당일 | `'midnight'` |
| **조자시(朝子時)** / 23시 일 전환 | **다음날** | 다음날 | `'jasi'` |
| **야자시(夜子時)** / 분리 | 당일 | **다음날** | `'splitJasi'` |

`manseryeok/src/pillars.ts` 원문 주석:

```
23:00~23:59 자시의 관법(dayBoundary)에 따라 일주와 시주 천간의 기준일이 갈린다.
- midnight: 일주·시주 모두 당일
- jasi: 일주·시주 모두 다음날
- splitJasi: 일주는 당일, 시주 천간만 다음날
```

### 8.2 lunar-javascript의 sect 옵션

`EightChar` 객체의 `setSect(1|2)` / `getSect()` — **기본값 sect=2**.

```js
_p: { sect: 2, lunar: lunar },
setSect: function(sect){ this._p.sect = (1===sect) ? 1 : 2; },
getDayGanIndex: function(){ return 2===this._p.sect ? ...ExactExact2() : ...Exact(); }
```

`_computeDay` 원문에서 확인한 차이:
- `dayGanIndexExact2` : 23:00~23:59에도 **날짜를 넘기지 않음** → sect=2 (기본)
- `dayGanIndexExact` : `hm >= '23:00' && hm <= '23:59'` 이면 간·지 인덱스를 **+1** → sect=1
- 단, **시주 천간은 sect와 무관하게 항상 `dayGanIndexExact`(넘긴 값) 사용**:
  ```js
  o['timeGanIndex'] = (o['dayGanIndexExact'] % 5 * 2 + timeZhiIndex) % 10;
  ```
  → lunar-javascript 기본 동작(sect=2)은 manseryeok의 **`'splitJasi'`(야자시)와 동일**하다.

### 8.3 국내 관행

- sajumanse.com: "밤 11시(23:30) 이후 출생 시 일주는 전날 것을 유지하고 시주만 자시(子時)로 계산" → **야자시(splitJasi)** 채택
- namu.wiki: 정자시 vs 야자시 논쟁 존재. "동양 전통 시간관은 시각(點)이 아니라 시간대(段)이므로 실제 자시는 23:30~01:30"이라는 주장도 있음
- 다수 자료가 "명리학계 최대 화두 중 하나"로 기술

### 8.4 제품 결정 권고

- **기본값: `splitJasi`(야자시)** — lunar-javascript 기본값 및 국내 주요 사이트와 일치 → "타 사이트와 다르다" 클레임 최소화
- 설정에서 3택1 노출 + "왜 사이트마다 다른가" 설명 문구 제공
- 23:00~23:59 출생자에게는 결과 화면에 관법 배지 표시

```python
monthCount = self.lunarMonth + 12 * (self.lunarYear - self.KOREAN_LUNAR_BASE_YEAR)

yearInx  = (((self.lunarYear + 6) - 1000) % 10, ((self.lunarYear + 0) - 1000) % 12)

dayInx   = ((absDays + 4) % 10, (absDays + 2) % 12)

### 11.1 3중 교차검증 체계

```
[1] 자체 엔진 (manseryeok vendored)

[2] lunar-javascript (sect=2)  ← 진태양시 미적용 조건에서만 일치해야 함
