## 0. 결론 요약 (사주 미니앱 관점 TL;DR)

| 항목 | 결론 |
|---|---|
| 런타임 선택 | **WebView SDK(`@apps-in-toss/web-framework` 3.0.3)** 로 간다. 사주/MBTI/혈액형/별자리 서비스는 텍스트·차트 위주라 RN 네이티브 성능이 불필요 |
| 번들 제한 | **압축 해제 기준 100MB 이하** (앱 번들 업로드 제한) |
| 만세력 데이터 | 100MB 안에 넣기보다 **서버 API로 분리**하는 게 안전 (번들에 최소 리소스만 권장) |
| 생년월일시 입력 | 사용자 직접 입력이 기본. `getConsentedUserData`로 `USER_BIRTHDAY` 취득 가능하나 **시(時)는 제공 안 됨** → 시주 계산에는 직접 입력 필수 |
| 사용자 식별 | 로그인 없이는 `User.getAnonymousKey()`, 로그인하면 `userKey` (앱 단위 고유) |
| 수익화 | 인앱결제(IAP) 수수료 **토스 5% + 앱마켓 15~30%**, 인앱광고 **토스 15%**. 상품가 **400원 ~ 1,400,000원** |
| 출시 리드타임 | 비게임 서비스 개발~출시 **1~3개월**, 출시 검수 **영업일 3~5일** |
| 치명적 제약 | **iframe 사용 불가**, **SSR 불가(CSR/SSG만)**, **다크모드 미지원**, **토스 로그인 외 자체 로그인 금지**, **토스페이 외 결제수단 금지**, **eval 등 외부 코드 실행 금지** |

## 2. 런타임 아키텍처 — 웹뷰인가 React Native인가?

**둘 다다.** 앱인토스는 3개 트랙을 제공한다.

| 트랙 | 패키지 | 최신 버전(2026-08-11 npm 확인) | 용도 |
|---|---|---|---|
| **WebView SDK** | `@apps-in-toss/web-framework` | **3.0.3** (BSD-3-Clause, unpacked 414,743 B) | 기존 웹 서비스를 토스 앱에서 빠르게 실행 |
| **React Native SDK** | `@apps-in-toss/framework` | **2.10.8** ("The framework for Apps In Toss", unpacked 399,988 B) | 네이티브 수준 성능/토스 앱 통합 필요 시 |
| **Unity** | (별도 유니티 패키지) | - | 게임 포팅 |

### 2.1 Granite — RN 트랙의 코어

- 저장소: `github.com/toss/granite` (문서 사이트 `granite.run`, `toss.github.io/granite`)
- 정체성: "Enterprise-grade React Native framework for microservice apps. Brownfield friendly, **200KB bundles**, AWS-ready infrastructure"
- 라이선스: **Apache 2.0**, © Viva Republica, Inc.
- 스타 472 / 포크 51 (조회 시점)
- 빌드: **ESBuild** 기반으로 JS 컴파일을 수초 내로 단축
- 배포 인프라: **Pulumi** 기반 AWS IaC (`@granite-js/pulumi-aws`), `npm run granite-forge deploy --bucket your-s3-bucket-name`
- 프로젝트 생성: `npx create-granite-app@latest`
- 빌드: `npm run granite build`

npm 확인:
- `@granite-js/react-native` **1.0.39** — bin: `granite → ./bin/cli.js`
- 의존: `@granite-js/cli`, `@granite-js/jest`, `@granite-js/mpack`(번들러), `@granite-js/video`, `@granite-js/blur-view`, `@granite-js/plugin-core`, `@granite-js/style-utils`, `@granite-js/brownfield-module`, `react-native-url-polyfill@3.0.0`, `es-toolkit`, `@standard-schema/spec`

> **"react-native-bedrock"** 이라는 npm 패키지는 이번 조사에서 직접 확인하지 못했다. 다만 개발자센터의 구 URL 경로가 `/bedrock/reference/framework/...` 형태였고, 그 경로의 문서 제목이 "Granite"였다. 즉 **Bedrock은 Granite의 구(舊) 내부 명칭**으로 보인다. 현재 문서 체계(llms.txt)에는 `/bedrock/` 경로가 없고 `/documentation/`으로 재편되었다. [일부 미검증]

### 2.4 TDS (Toss Design System) — 사실상 필수

- WebView용: `@toss/tds-mobile` **2.5.1** (peer: react ^16.8.3||^17||^18, react-dom, `@emotion/react` ^11), `@toss/tds-mobile-ait`
- RN용: `@toss/tds-react-native` (>=2.0.0)
- FAQ 원문: **"앱인토스 SDK와의 의존성을 위해 필수로 설치해야"** 한다.
- 단, "모든 컴포넌트를 반드시 TDS로 디자인해야 하는 것은 아니며, TDS로 해결 어려운 영역은 자체 개발" 가능.
- **지식재산권은 토스에 귀속**, 사용 권한 제한적, 위반 시 서비스 중단 가능. 피그마 UI Kit 별도 라이선스 문서 존재(`/design/prepare/figma-ui-license.md`).
- **Toss Product Sans 폰트는 별도 제공하지 않음** — TDS 컴포넌트를 통해서만 적용.

## 3. 개발 셋업 — 실제 명령어와 설정 파일

### 3.1 신규 프로젝트

```sh
# 개발자센터 메인에 노출된 원커맨드
npx create-ait-app <app-name>
```

### 3.2 기존 웹 프로젝트에 SDK 얹기 (우리가 쓸 경로)

```sh
# npm
npm install @apps-in-toss/web-framework
npx ait init

# pnpm
pnpm add @apps-in-toss/web-framework
pnpm ait init

# yarn
yarn add @apps-in-toss/web-framework
yarn ait init
```

TDS 추가:

```sh
npm install @toss/tds-mobile @toss/tds-mobile-ait @emotion/react@^11 react@^18 react-dom@^18
```

### 3.3 설정 파일 — SDK 2.x `granite.config.ts`

`ait init`이 생성하는 파일(2.x 기준):

```ts
export default defineConfig({
  appName: 'my-mini-app',
  brand: {
    displayName: '앱 이름',
    primaryColor: '#FF91D5',
    icon: 'console-url',
  },
  web: {
    host: 'localhost',
    port: 5173,
    commands: {
      dev: 'vite dev',
      build: 'vite build',
    },
  },
  permissions: [],
  outdir: 'dist',
});
```

> **`appName` 주의**: "appName은 각 앱을 식별하는 고유한 키로 사용되며, `intoss://{appName}` 형태의 딥링크로 활용"된다. FAQ 원문: "**앱 ID와 같은 개념**이므로 등록하고 **수정 및 삭제가 불가능**". → 우리 앱 이름은 처음에 확정해야 한다. (예: `saju`, `unse`, `fourpillars` 등 선점 이슈 있음 [미검증])

### 3.4 SDK 3.x 마이그레이션 — Breaking Changes

`/development/sdk-3.x.md` 확인 결과:

| 2.x | 3.x |
|---|---|
| `granite.config.ts` | **`apps-in-toss.config.ts`** 로 파일명 변경 |
| `brand: { displayName, primaryColor, icon }` | `brand`는 **`primaryColor`만** 유지 |
| `webViewProps` | **`webView`** 로 변경, `type` 속성 제거 |
| `outdir` | **`webBundleDir`** 로 변경 |
| `web.commands` (config 내부) | **`package.json` scripts로 이동** |
| CORS 허용 도메인 `*.apps.tossmini.com` | **`*.web.tossmini.com`** |

자동 마이그레이션:

```sh
npx ait migrate v3
```

package.json 빌드 스크립트에 `ait build`가 반드시 포함되어야 한다:

```json
{
  "scripts": {
    "build": "vite build && ait build"
  }
}
```

동반 업데이트 필요: `@toss/tds-mobile@2.4.1`, `@toss/tds-mobile-ait@2.4.1` 이상.

> ⚠️ **"SDK 3.x로 배포한 뒤에는 2.x로 롤백할 수 없다."** API 파라미터/반환값 호환성은 유지되나, 내부 처리가 클라이언트→서버로 이동했다.

### 3.5 React Native 트랙 셋업 (참고)

```sh
npm create granite-app@"^1"
npm install @apps-in-toss/framework
npm install @toss/tds-react-native
npx ait init
```

`granite.config.ts`:

```ts
import { appsInToss } from '@apps-in-toss/framework/plugins';
import { defineConfig } from '@granite-js/react-native/config';

export default defineConfig({
  appName: '<app-name>',
  plugins: [
    appsInToss({
      brand: {
        displayName: '앱 이름',
        primaryColor: '#3182F6',
        icon: null,
      },
      permissions: [],
    }),
  ],
});
```

앱 등록 진입점 (RN):

```tsx
import { AppsInToss } from '@apps-in-toss/framework';

function AppContainer({ children }: PropsWithChildren<InitialProps>) {
  return <>{children}</>;
}

export default AppsInToss.registerApp(AppContainer, { context });
```

`registerApp`이 기본 제공하는 것:
- **파일 기반 라우팅** (`/pages/home.ts` → `intoss://my-service/home`)
- 쿼리 파라미터 처리
- 뒤로 가기 제어
- 화면 가시성 감지

### 3.6 빌드 산출물

- 빌드 명령: `npm run dev` / `npm run build`
- 산출물: **`<서비스명>.ait`** 파일 (콘솔에 업로드하는 번들)
- 오류 `deploymentId를 찾을 수 없어요` → `.ait` 재빌드 필요 (deploymentId가 번들에 포함돼야 함)

## 4. 로컬 개발 · 디버깅 · 샌드박스

### 4.1 샌드박스(테스트앱)

- **브라우저 테스트로는 불충분.** FAQ 원문: "브라우저 환경에서는 정상적인 테스트가 어려워요. **검수 요청 전 반드시 샌드박스 앱에서 테스트**"
- 지원 OS: **Android 7 이상, iOS 16 이상** (실제 서비스 대상 사용자도 동일 기준)
- 사용자 연령: **만 19세 이상**

설치:

```sh
# Android
adb install -r -t {파일명}

# iOS 시뮬레이터: .app 파일을 시뮬레이터 화면에 드래그&드롭
# iOS 실기기: "앱인토스 샌드박스" QR → 앱스토어 설치
```

### 4.2 로컬 개발 서버 연결

**Android (포트 포워딩)**

```sh
adb reverse tcp:8081 tcp:8081     # Metro (RN)
adb reverse tcp:5173 tcp:5173     # Vite (WebView)

# 기기 여러 대일 때
adb -s {디바이스ID} reverse tcp:8081 tcp:8081

# 확인
adb version
adb devices
adb reverse --list

# 문제 시
adb kill-server
```

**adb PATH (macOS)**

```bash
export ANDROID_HOME=~/Library/Android/sdk
export PATH=$PATH:$ANDROID_HOME/tools:$ANDROID_HOME/tools/bin:$ANDROID_HOME/platform-tools
```

**iOS 실기기**
1. "로컬 네트워크" 권한 허용
2. 로컬 서버 IP 입력 (`ipconfig getifaddr en0`)
3. "스키마 열기" 클릭 → 상단 `Bundling {n}%...` 확인

**"서버에 연결할 수 없습니다" 해결**: `granite.config.ts`의 `web.commands.dev`에 `--host` 추가 + `web.host`에 실제 IP 입력

```ts
web: {
  host: '192.168.0.100',
  commands: {
    dev: 'vite --host',
    build: 'vite build',
  },
}
```

## 5. 인증 — 토스 로그인 & 사용자 식별키

### 5.1 두 가지 식별 체계

| 방식 | 함수 | 특징 | 사업자 등록 |
|---|---|---|---|
| 익명 식별키 | `User.getAnonymousKey()` | 로그인 없이 사용자 구분 | 불필요 |
| 토스 로그인 | `TossAuth.login()` / `appLogin()` | `userKey` + 개인정보 scope | **필수** |

> FAQ 확인: "사업자가 없으면 출시는 가능하지만 **토스 로그인, 비즈월렛, 프로모션, 광고, 토스페이, 결제** 등 일부 기능을 사용할 수 없다."

### 5.2 토스 로그인 흐름 (OAuth2 유사)

**Base URL: `https://apps-in-toss-api.toss.im`** / 인증: **mTLS** / `Content-Type: application/json`

**1단계 — 클라이언트에서 인가 코드 받기**

```ts
TossAuth.login(): Promise<AppLoginResponse>;

type AppLoginResponse = {
  authorizationCode: string;             // 10분 유효, 일회성
  referrer: "DEFAULT" | "SANDBOX";
};
```

```js
import { TossAuth } from "@apps-in-toss/web-framework";

const button = document.querySelector("#login-button");

button.addEventListener("click", async () => {
  try {
    const { authorizationCode, referrer } = await TossAuth.login();
    // authorizationCode, referrer를 우리 서버로 전달
  } catch (error) {
    console.error(error);
  }
});
```

> ⚠️ 토큰 교환·AccessToken 발급·사용자 정보 조회는 **반드시 서버에서** 처리해야 한다.

**2단계 — AccessToken 발급 (서버)**

```
POST /api-partner/v1/apps-in-toss/user/oauth2/generate-token
body: { authorizationCode, referrer }
→ { accessToken(1시간), refreshToken(14일), scope, expiresIn, tokenType: "Bearer" }
```

**3단계 — 토큰 갱신**

```
POST /api-partner/v1/apps-in-toss/user/oauth2/refresh-token
body: { refreshToken }
```

**4단계 — 사용자 정보 조회**

```
GET /api-partner/v1/apps-in-toss/user/oauth2/login-me
header: Authorization: Bearer ${accessToken}
→ {
    userKey,        // 앱 단위 고유 식별자, 암호화 아님
    scope,          // 동의한 권한 목록
    agreedTerms,    // 동의 약관 목록
    name, phone, birthday, ci, gender, nationality, email,  // 전부 암호화됨
    di              // 항상 null
  }
```

**5단계 — 연결 끊기**

```
POST /api-partner/v1/apps-in-toss/user/oauth2/access/remove-by-access-token
POST /api-partner/v1/apps-in-toss/user/oauth2/access/remove-by-user-key
```

**연결 해제 콜백 referrer 종류**: `UNLINK`(사용자 수동 해제), `WITHDRAWAL_TERMS`(약관 동의 철회), `WITHDRAWAL_TOSS`(토스 회원 탈퇴)

### 5.3 개인정보 Scope 목록

```
user_key, user_name, user_phone, user_birthday,
user_gender, user_nationality, user_ci
```

### 5.4 개인정보 복호화 스펙

- 알고리즘 **AES-256-GCM**
- **IV 12바이트**, 암호문 앞부분에 포함
- **AAD는 콘솔에서 별도 제공**
- 키는 콘솔에서 발급

### 5.5 익명 식별키 검증 API

```
POST https://apps-in-toss-api.toss.im/api-partner/v1/apps-in-toss/users/anon-key/verify
header: x-anon-key: <User.getAnonymousKey() 결과>
```

성공:
```json
{ "resultType": "SUCCESS", "success": true }
```

실패(HTTP 200 + 비즈니스 오류):
```json
{
  "resultType": "FAIL",
  "error": { "errorCode": "4010", "reason": "인증 정보를 찾을 수 없어요." }
}
```

| errorCode | 의미 |
|---|---|
| 4010 | 인증 정보를 찾을 수 없어요 |
| 4034 | 워크스페이스 접근 권한 없음 |
| 4095 | 요청 한도 초과 (기본 분당 3,000회) |
| 5004 | 승인되지 않은 메시지 템플릿 |

### 5.6 사용자 정보 동의 API — 사주 앱 핵심

`getConsentedUserData()` → `Promise<ConsentedUserData | undefined>`
- 동의가 필요하면 **약관 웹뷰를 자동 표시**
- **콘솔에서 사전 설정 필요**
- 제공 항목 8종: **이름, 성별, 생년월일, 전화번호, 주소, 이메일, 국적, 소비내역**
- `USER_ADDRESS`, `USER_EMAIL`은 토스 가입 시 선택 항목이라 **null 체크 필수**
- 사용자가 토스 앱 설정에서 동의 철회 가능

> 🔴 **사주 앱 관점 핵심 결론**: 제공되는 건 **생년월일(date)까지**다. **출생 시각(時)은 없다.** 시주(時柱) 계산에는 사용자 직접 입력 UI가 반드시 필요하다. 또한 양력/음력 구분, 윤달 여부, 출생지(진태양시 보정)도 전부 자체 입력이다.

관련 API: `User.getDeclaredAgeRange()` (연령대), `User.getAnonymousKey()`

## 7. 제약사항 (반드시 지켜야 할 것들)

### 7.1 절대 금지 — 검수 반려 사유

| 항목 | 원문/근거 |
|---|---|
| **iframe** | "iframe은 사용할 수 없어요. iframe을 사용하면 앱인토스 기능이 정상 동작하지 않고, **내부 보안 심사에서도 반려**돼요." (YouTube 콘텐츠는 예외) |
| **외부 코드 실행** | "외부에서 전달받은 코드를 실행하는 기능은 사용할 수 없어요" (eval 등) |
| **SSR** | "서버 사이드 렌더링(SSR) 미지원, **CSR/SSG만 허용**" → Next.js 쓰려면 `output: 'export'` 정적 빌드 [일부 미검증] |
| **비암호화 WebSocket** | `wss://`만 허용, `ws://` 불가 |
| **히스토리 조작** | "브라우저 히스토리를 조작해서 자사 사이트로 이동" 금지 |
| **자체 로그인** | "토스 로그인 외 자사/기타 로그인 방식 금지" |
| **외부 결제수단** | "**토스페이 외의 다른 결제 수단은 제공하지 않아요**" (+ IAP는 별도 허용) |
| **자사 서비스 유도** | 자사 서비스 이동이나 앱 설치 유도 금지 |
| **다크패턴** | 진입 시 바텀시트, 뒤로가기 시 시트 출현, 나갈 수 없는 구조, 예상 외 광고, 모호한 CTA 버튼 등 → 출시 불가 |
| **다크모드** | "현재 앱인토스 미니앱에서는 **다크 모드를 지원하지 않습니다**." 라이트 모드 기준 개발 |

### 7.2 허용되는 것

- **일반 웹 API는 허용**. FAQ 원문: "WebView 환경에서 일반적인 웹 API 사용은 제한하지 않습니다."
- 외부 링크: "서비스 이용에 **꼭 필요한** 외부 링크가 정상적으로 열려야" 함 → `Device.openURL()` 사용

```ts
function openURL(url: string): Promise<any>;
```
- 내부적으로 RN `Linking.openURL` 래핑
- WebView 환경에서는 새 브라우저 탭으로 열림
- `intoss://{appName}` 딥링크 트리거에도 사용
- 열 수 없는 스킴/네트워크 제한 시 reject

### 7.3 성능·UX 필수 기준

- **인터랙션 반응이 2초 이상 지연되지 않아야** 함
- 모든 화면에서 미니앱 종료 가능해야 함
- 모든 화면에서 뒤로가기 정상 작동
- 데이터 지속성: "미니앱을 종료했다가 다시 들어와도 필요한 데이터가 유지"
- **로그인 해제 시 사용자 데이터 삭제 필수**
- 비정상적 네트워크/메모리 사용 금지
- 광고: 인트로/로딩/팝업 등 일시적 화면 노출 금지, 배너는 스크롤 가능한 화면에만

### 7.4 스토리지 / 파일 시스템

**네이티브 Storage API**

| 메서드 | 시그니처 |
|---|---|
| `Storage.setItem(key, value)` | `Promise<void>` — 문자열만 |
| `Storage.getItem(key)` | `Promise<string \| null>` |
| `Storage.removeItem(key)` | - |
| `Storage.clearItems()` | 전체 초기화 |

- **RN `AsyncStorage`는 사용 불가** — 반드시 SDK `Storage` 사용
- 앱 삭제 시 데이터 함께 삭제 → 지속성 필요하면 자체 서버 연동
- 저장 용량 자체에 대한 별도 제한 명시는 없음

**웹 표준 스토리지 격리 (중요)**

`localStorage` / IndexedDB는 origin 기준으로 격리되며, 환경별 origin이 다르다:

| SDK 버전 | 출시 환경 origin | QR/테스트 환경 origin |
|---|---|---|
| 3.x | `https://<appName>.web.tossmini.com` | `https://<appName>.private-web.tossmini.com` |
| 1.x ~ 2.x | `https://<appName>.apps.tossmini.com` | `https://<appName>.private-apps.tossmini.com` |

→ **두 환경 간 데이터는 공유되지 않는다.** 테스트에서 저장한 값이 출시 환경에 없다.

- iOS는 **IndexedDB가 7일 미사용 시 자동 삭제** → **Cache API 사용 권장**

**파일**
- `File.saveBase64` — base64 데이터를 기기에 저장 (사주 결과 이미지 저장에 활용 가능)
- `File.openPDFViewer` — PDF 뷰어 (프리미엄 사주 리포트 PDF 제공에 활용 가능)

### 7.5 권한

`granite.config.ts`(3.x는 `apps-in-toss.config.ts`)의 `permissions` 배열에 선언:

```ts
permissions: [
  { name: 'camera',      access: 'access' },
  { name: 'photos',      access: 'read'   },
```

> 사주 앱은 **권한 선언 없이(빈 배열) 출시 가능**하다. 출생지 자동 입력용 `geolocation`은 UX 이득 대비 검수·동의 부담이 크므로 v1에서는 제외 권장.

### 7.6 CORS

- FAQ: "외부 API 호출 시 CORS 에러 → API 서버의 CORS 허용 목록에 **앱인토스 도메인 추가**"

- 1.x~2.x: `https://<appName>.apps.tossmini.com`, `https://<appName>.private-apps.tossmini.com`

## 8. 서버 API 연동 (mTLS · 방화벽)

### 8.1 기본

- Base URL: **`https://apps-in-toss-api.toss.im`** (결제는 별도 전용 엔드포인트)
- **mTLS(양방향 TLS) 필수.** 미적용 시 `ERR_NETWORK` 발생
- 목적: "통신 구간 암호화" + "허용된 서버만 API 호출 가능"
- 기본 **Rate Limit: 분당 3,000회** (상향 요청 가능)

### 8.2 방화벽 허용 IP (port 443)

**Inbound (앱인토스 → 파트너 서버, 콜백)**
```
117.52.3.11
211.115.96.11
106.249.5.11
+ 각 대역의 80~87
```

**Outbound (파트너 서버 → 앱인토스 API)**
```
117.52.3.192   ← 로그인 / 메시징
117.52.3.195   ← 결제
```

### 8.3 응답 포맷 (모든 서버 API 공통)

```json
// 성공
{ "resultType": "SUCCESS", "success": { /* data */ } }

// 실패 (HTTP는 200일 수 있음)
{ "resultType": "FAIL", "error": { "errorCode": "4010", "reason": "..." } }
```

→ **HTTP status가 아니라 `resultType`을 먼저 확인**하는 클라이언트를 작성해야 한다.

**클라이언트 코드 (실제 문서 예시)**

```tsx
import { IAP } from '@apps-in-toss/web-framework';
import { Button } from '@toss/tds-mobile';

function PurchaseButton({ sku }: { sku: string }) {
  const handleBuy = () => {
    const cleanup = IAP.createOneTimePurchaseOrder({
      options: {
        sku,
        processProductGrant: async ({ orderId }) => {
          try {
            await grantProductToUser(orderId);   // 우리 서버에서 지급 처리
            return true;                          // 반드시 true 반환
          } catch {
            return false;
          }
        },
      },
      onEvent: (event) => {
        console.log('결제 성공:', event.data.orderId);
        cleanup();
      },
      onError: (error) => {
        console.error('결제 실패:', error);
        cleanup();
      },
    });
  };

  return <Button onClick={handleBuy}>구매하기</Button>;
}
```

**타입**

```ts

  params: IapCreateOneTimePurchaseOrderOptions
): () => void;   // cleanup 함수 반환

}

  displayName: string;
  displayAmount: string;   // "4,900원"

  fraction: number;

}
```

**제약**
- **SDK 1.1.3 이상** 필요
- `processProductGrant`는 **30초 내 반환** 필수
- 상품 가격: **최소 400원 ~ 최대 1,400,000원**
- 환불: 콘솔 > 인앱결제 > 결제 내역에서 개별 환불 가능. Google Play는 48시간 이내 자동 처리 후 수동 요청 가능, App Store는 Apple이 직접 처리

### 9.2 수수료 / 정산

| 항목 | 수수료 |
|---|---|
| 앱인토스 플랫폼 자체 수수료 | 현재 **별도 없음** |
| 인앱 광고 | **15%** (토스) |
| 인앱 결제 | **토스 5%** + **앱마켓 15~30%** |
| 스마트 발송 | **건당 9.9원** |

- 정산 지급일: **익월 말(영업일 기준)**, 정산내역 **익월 5일 이내** 제공
- 비즈월렛 실시간 확인, 인보이스 **익월 1~2일 이내** 업데이트
- 세금계산서: 광고 수익은 파트너사 발행(매월 영업일 2일 이내), 앱인토스/인앱결제 수수료는 토스 발행. 역발행은 **팝빌** 통해 진행, 사업자용 공동인증서 필요
- 간이과세자도 정산 가능(세금계산서 대신 현금영수증)

### 9.3 토스페이

- Key 발급: 서류 제출 후 **영업일 7~14일**
- **테스트 Key로는 결제 생성까지만 가능, 승인 처리 불가**
- API: `TossPay.authorize`, `TossPay.authorizeSubscription`

### 9.4 인앱 광고

- 지원 유형: **전면형(interstitial)** + **보상형(rewarded)** + **배너**(WebView/RN 별도 문서)
- AdMob 연동 API 존재: `GoogleAdMob.loadAppsInTossAdMob` / `showAppsInTossAdMob` / `isAppsInTossAdMobLoaded`
- 자체 `TossAds`: `loadFullScreenAd` / `showFullScreenAd`
- **테스트용 ID 반드시 사용** (라이브 키와 분리)
- 광고 지면 승인에 **최대 24시간** 소요
- 샌드박스에서는 광고 테스트 불가

## 10. 마케팅 / 성장 기능 (사주 앱 바이럴 설계용)

### 10.1 공유 링크

```ts
function getTossShareLink(url: string, ogImageUrl?: string): Promise<string>;
```

- `url`: **`intoss://` 형식 딥링크 경로** (필수)
- `ogImageUrl`: SNS 미리보기 이미지, **반드시 `https://` 절대경로** (선택)
- 앱 미설치 시 iOS→앱스토어, Android→플레이스토어로 이동
- **출시 전 테스트는 `intoss-private://` 스킴 사용 + 발급된 `deploymentId`를 필수 파라미터로 포함**
- 검수 기준: 출시 시 공유 링크는 **`intoss://` 여야 함 (`intoss-private://` 금지)**
- 외부 플랫폼 OG 캐시 때문에 이미지 변경이 즉시 반영 안 될 수 있음

관련 API: `Share.createLink`, `Share.sendMessage`, 공유 리워드(`/documentation/common/growth/share/reward.md`)

### 10.2 푸시 / 알림 (서버 API)

| 엔드포인트 | 한도 |
|---|---|
| `POST /api-partner/v1/apps-in-toss/messenger/send-message` | 앱당 **분당 15,000회**, 사용자당 **분당 10회** |
| `POST /api-partner/v1/apps-in-toss/messenger/send-bulk-message` | **50~2,500건**/요청, 분당 3,000회 |
| `POST /api-partner/v1/apps-in-toss/messenger/send-test-message` | 분당 3,000회 |

- 필수 필드: `templateSetCode`(사전 등록·승인된 템플릿 코드), `context`(템플릿 변수 객체)
- 인증 헤더: `x-toss-user-key` 또는 `x-anon-key`
- **모든 메시지는 문구 검수 승인 후에만 발송 가능**, 검수 **영업일 2~3일**
- 광고성 푸시: **워크스페이스 기준 하루 최대 10만 명**
- 광고성 vs 기능성 구분: 광고성=할인/이벤트/신규상품, 기능성=주문/결제/배송 등 필수 정보
- **토스 라이팅 규칙 준수 필수** (토스 앱 자체에서 발송되므로)
- 알림 수신 동의 문구에 파트너사명 + 알림 내용 요약 + 동의/철회 방법 포함, `Notification.requestAgreement` SDK 연동 필요

### 10.3 프로모션 (토스 포인트)

- `Promotion.grantReward`, `Promotion.openContactsInvite`
- 노출 위치: **토스 > 혜택탭 > "새로운 서비스 써보고"** 리스트
- 지급 테스트 필수 (`TEST_{promotionCode}`)로 완료해야 '시작하기' 진행 가능
- ⚠️ **중복 지급 차단 로직은 직접 구현해야 함**

### 10.4 분석

- `Analytics.log` / `click` / `impression` / `screen`
- 대시보드 데이터는 **익일 오전 8시경 업데이트**
- 토스애즈 픽셀 연동 별도 문서 존재

## 11. 배포 · 심사 파이프라인

### 11.1 등록 절차

```
콘솔 가입 → 워크스페이스 생성 → 사업자 등록 → 앱 등록 → 검수 요청
```

**앱 등록 시 필요 정보 (비게임)**: 로고, 이름, **appName**, 이메일, 카테고리, 설명, 키워드
(게임은 추가로 등급, 썸네일, 리더보드 등)

### 11.2 검수 소요 시간

| 검수 종류 | 소요 |
|---|---|
| 앱 등록 검수 | **영업일 1~2일** |
| 사업자 등록 검수 | **영업일 1일** (변경 시 1~2일) |
| **앱 출시 검수** | **영업일 3~5일** (재검수도 동일) |
| 푸시 메시지 검수 | **영업일 2~3일** |
| 스마트발송 소재 검수 | **영업일 1~2일** (발송 최소 3영업일 전 등록 권장) |
| 토스페이 Key 발급 | **영업일 7~14일** |

주말·공휴일에는 검수 진행 안 됨.

### 11.3 배포 4단계

1. **사전 점검** — 게임/비게임 체크리스트 확인, 번들 100MB 이하 확인
2. **검토 요청** — 콘솔에서 요청. **테스트 1회 이상 완료해야 버튼 활성화**. 한 번에 **한 버전만** 제출 가능
3. **출시** — 승인 후 "출시하기" 버튼 → **즉시 전체 사용자에게 반영** (단계적 롤아웃 없음)
4. **출시 후 관리** — 버전 관리, 롤백, 모니터링

### 11.4 롤백

- "앱 출시" 메뉴에서 이전 버전 선택 후 "출시하기"
- 문서 경고: **"롤백도 사용자에게 즉시 반영되니, 버전을 신중히 선택해 주세요"**

### 11.5 번들 용량 정책

- **압축 해제 기준 100MB 이하**
- 문서 권장: 최소 리소스만 번들에 포함, **대용량 파일은 외부 CDN에서 로드**, **Lazy Loading으로 단계적 다운로드**

### 11.6 배포 CLI

- 출시 문서에는 **CLI 명령이 없다.** 모든 배포 작업은 **콘솔 UI 버튼**으로 수행
- 단, **콘솔 MCP(70+ 도구)로 번들 업로드/검수 요청을 자동화 가능** (§4.5)
- 긴급 점검(서비스 일시 중단) 설정: `/guide/operation/check.md`
- 서비스 종료: 채널톡으로 **최소 2주 전** 문의

### 12.1 기술 스택 결정안

```
런타임:  WebView SDK (@apps-in-toss/web-framework ^3.0.3)
빌드:    Vite + React 18 (SSR 금지 → 순수 CSR)
UI:      @toss/tds-mobile 2.5.1 + @toss/tds-mobile-ait + @emotion/react ^11

관측:    Sentry (@ai-vibe-coding/integration/sentry.md 가이드)
콘솔:    apps-in-toss-console MCP를 Claude Code에 연결
```

### 12.2 데이터 아키텍처 판단

| 데이터 | 위치 | 근거 |
|---|---|---|
| 만세력(60갑자 일진 테이블, 절입시각) | **서버 API** | 100MB 번들 제한 + "대용량 파일은 외부 CDN" 권장. 1900~2100년 절기 데이터는 압축 시 수 MB지만 로직까지 서버에 두는 게 업데이트 유리 |
| MBTI/혈액형/별자리 해석 텍스트 | 서버 또는 CDN JSON | 텍스트 볼륨이 크고 A/B 테스트·문구 수정 빈번 |
| 사용자 입력(생년월일시, 성별) | `Storage.setItem` + 서버 | Storage는 앱 삭제 시 소실 → 로그인 사용자는 서버 저장 |
| "오늘의 운세" 날짜 기준 | **`Environment.getServerTime()`** | 기기 시간 조작 어뷰징 방지 |
| 결과 이미지 | `File.saveBase64` | 갤러리 저장 → 공유 바이럴 |

### 12.3 반드시 피해야 할 구현

- ❌ Next.js SSR / App Router 서버 컴포넌트 → **CSR/SSG만**
- ❌ 광고나 외부 콘텐츠 `<iframe>` 임베드 (YouTube 제외) → **즉시 반려**
- ❌ 자체 카카오/구글/애플 로그인 → **토스 로그인만**
- ❌ 자체 PG/카드결제 → **IAP 또는 토스페이만**
- ❌ 다크모드 대응 CSS → 라이트 모드 고정
- ❌ 진입 즉시 바텀시트, 뒤로가기 시 이탈 방지 시트 → **다크패턴 반려**
- ❌ `AsyncStorage` (RN 트랙 시) → SDK `Storage` 사용
- ❌ 서버 응답 문자열 `eval`/`new Function` (해석 템플릿 동적 평가 유혹 주의)

### 12.4 수익화 설계 초안

| 상품 | 방식 | 가격대 |
|---|---|---|
| 무료 사주 요약 | 광고 (전면형/보상형) | - |
| 상세 사주 리포트 (PDF) | IAP 단건 | 2,900~4,900원 (400~1,400,000원 범위 내) |
| 궁합 분석 | IAP 단건 | 1,900~2,900원 |
| 프리미엄 구독 (매일 운세 + 무광고) | `IAP.createSubscriptionPurchaseOrder` | 월 3,900~9,900원 |

실수령: IAP 기준 **약 65~80%** (앱마켓 15~30% + 토스 5% 차감)

### 12.5 초기 마일스톤 리스크

- 사업자 등록 없이는 **토스 로그인·IAP·광고·프로모션 전부 불가** → 사업자등록증 확보가 최우선 선행 작업
