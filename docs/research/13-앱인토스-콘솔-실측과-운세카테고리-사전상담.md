## 0. 실행 요약 — 이 문서로 바뀐 것

이번 조사에서 **비가역 결정 4종 중 1종이 "실은 가역"으로 뒤집혔고, 2종의 원문 근거를 1차 소스로 확정했으며, 문서 간 수치 불일치 5건 중 4건을 해소**했다. 반면 콘솔 실물 확인과 채널톡 답변은 **환경적 제약으로 확보 실패**했고, 그 실패 사실을 §1.2에 그대로 기록한다.

| # | 기존 가정 | 이번 조사 결과 | 상태 변화 |
|---|---|---|---|
| 1 | appName 등록 후 변경 불가 | **확정** — 원문 "`appName`은 한 번 등록하면 바꿀 수 없어요" | 유지 (1차 근거 확보) |
| 2 | 워크스페이스 = 사업자당 1개, 법인 전환 시 재생성 | **확정** — 원문 2건 확보 | 유지 (1차 근거 확보) |
| 3 | SDK 3.x 배포 시 2.x 롤백 불가 | **확정** — 원문 "SDK 3.x 이상이 적용된 앱 번들을 출시하면 SDK 2.x 버전으로 롤백할 수 없어요" | 유지 (1차 근거 확보) |
| 4 | 카테고리는 등록 시 확정되는 비가역 결정 | **✅ 뒤집힘 — 가역**. 콘솔 MCP에 `miniapp_update_category` tool이 공식 문서에 명시되어 있음 | **비가역 목록에서 제외** |

> **가장 중요한 발견**: 착수 첫 액션의 비가역 결정은 4종이 아니라 **3종**이다. 카테고리는 사후 변경 가능하므로, "운세 카테고리가 콘솔에 있는지 몰라서 착수를 미룬다"는 병목은 **해소된다**. 다만 카테고리에 따라 검수 기간이 달라지는 문제(§5)는 그대로 남는다.

**추가로 새로 발견된, 기존 12개 문서에 없던 치명적 제약 3건:**

1. **SSR 전면 금지** — "서버 사이드 렌더링(SSR)은 사용할 수 없어요. 클라이언트 사이드 렌더링(CSR) 또는 정적 사이트 생성(SSG) 방식만 사용할 수 있어요." (`checklist/app-nongame.md`). 문서 11의 기술스택 선정에 직접 영향.
2. **부가가치세 면세사업자 등록 불가** — "부가가치세 면세 사업자는 앱인토스에 사업자 등록을 할 수 없어요." (`register-business.md`). 사업자 형태 결정표(§7)의 최상위 제약.
3. **외부 코드 실행 금지의 실제 범위 확정** — 원문은 "외부에서 전달받은 **코드**를 실행하는 기능은 사용할 수 없어요. (예: `eval` 등)". 즉 금지 대상은 **코드 실행**이지 **데이터 수신**이 아니다 → LLM 생성 운세 텍스트를 자체 서버 경유로 내려받아 렌더링하는 구조는 **저촉되지 않는다**(§6.3).

## 1. 조사 수행 기록 (투명성)

### 1.1 수행한 것

| 방법 | 대상 | 결과 |
|---|---|---|

| Bash | 콘솔 MCP 서버 등록 (`claude mcp add`) | 등록 성공 / **인증 실패** |
| WebFetch | 콘솔 `apps-in-toss.toss.im`, 채널톡 워크플로우 | **실패 (SPA·빈 응답)** |
| Chrome MCP | 콘솔·채널톡 브라우저 접근 | **실패 (브라우저 선택에 사용자 상호작용 필요)** |
| WebSearch | — | **불가 (세션 검색 예산 200/200 소진)** |

### 1.2 실패 기록 — 확인하지 못한 것 (추정 금지 원칙에 따라 그대로 남김)

**[B-1] 콘솔 MCP 인증 실패**

MCP 서버 등록 자체는 성공했다. `C:\Users\user\.claude.json` (project: `saju-toss-app`)에 로컬 스코프로 추가됨.

```
$ claude mcp add --transport http apps-in-toss-console \
    https://mcp.toss.im/adapters/apps-in-toss-console/mcp --client-id mcp-gateway
Added HTTP MCP server apps-in-toss-console with URL: https://mcp.toss.im/adapters/apps-in-toss-console/mcp to local config

$ claude mcp list
apps-in-toss-console: https://mcp.toss.im/adapters/apps-in-toss-console/mcp (HTTP) - ! Needs authentication
```

→ 상태가 `Connected`가 아니라 **`Needs authentication`**. 공식 문서(`guide/console-mcp.md`)가 지정한 인증 절차는 다음과 같고, **3~4단계가 대화형 UI 조작이라 자동화 세션에서 수행 불가**다.

> 1. 터미널에서 `claude` 또는 `Codex` 실행 → 2. `/mcp` 입력 → 3. `apps-in-toss-console` 선택 → 4. `Authenticate` 클릭하여 **Toss SSO 및 비즈 로그인** 완료 → 5. 상태가 `Connected`인지 확인

**→ 사용자 조치 필요 (5분 소요, 이후 §3.2의 tool로 전 항목 즉시 실측 가능).**

**[B-2] 콘솔 웹 UI 미확인**
`https://apps-in-toss.toss.im/`은 WebFetch로 본문이 비어 있는 SPA(로그인 게이트 추정). Chrome MCP는 계정에 Chrome 브라우저 2대(`71a66170-…`, `cf098df5-…`)가 연결되어 있어 **어느 브라우저를 쓸지 사용자가 직접 선택해야만** 동작한다. 서브에이전트 세션에서는 선택 불가 → 중단.

**[A] 채널톡 사전 상담 미발송 — 의도적 보류**

`https://apps-in-toss.channel.io/workflows/787658` 역시 SPA로 본문 추출 실패. 더 중요하게는, **채널톡 상담 발송은 사용자(사업 주체)를 대신해 토스에 공식 문의를 접수하는 행위**이므로 자동 실행하지 않았다. 대신 **§4에 그대로 복사해 붙여넣을 수 있는 질문지 완성본**을 준비했다.

> ⚠️ 따라서 이 문서에서 [A]의 **답변 원문 인용은 0건**이다. 질문 8종 중 5종은 공식 문서 1차 근거로 부분 대체했고(§6), 3종(카테고리 목록·운세 카테고리 검수일·법인 전환 시 앱 이관)은 **미확정으로 남는다**.

## 2. 비가역 결정 4종 — 원문 근거로 재판정

### 2.1 [비가역 ✅ 확정] appName

**원문 (`guide/operation/console-workspace.md`)**

> "appName은 한 번 등록하면 바꿀 수 없으니 신중하게 입력해주세요"
> "`intoss://` 형식으로 구성돼요"
> "앱 스킴을 호출하면, 이 ID를 기준으로 앱인토스 서비스로 이동"
> "규칙을 지키지 않으면 서버 인증서 발급에 실패할 수 있어요"

**appName이 각인되는 위치 (총 3곳, 전부 영구):**

| 위치 | 형식 | 출처 |
|---|---|---|
| 딥링크 스킴 | `intoss://<appName>` | `console-workspace.md` |
| 운영 도메인 (SDK 3.x) | `https://<appName>.web.tossmini.com` | `deploy.md`, `development/sdk-3.x.md` |
| 운영 도메인 (SDK 1.x~2.x) | `https://<appName>.apps.tossmini.com` | `deploy.md` |
| 콘솔 테스트 도메인 | `https://<appName>.private-web.tossmini.com` | `development/sdk-3.x.md` |

→ CORS 허용 origin 등록 시 위 도메인을 그대로 써야 하므로, appName 변경은 사실상 **인증서·CORS·딥링크 전부 재발급**을 의미한다. 문서가 "변경 불가"라고 못 박은 이유.

**❌ 확인 실패: appName 입력 규칙 (길이/문자셋/중복검사)**

GitBook 공식 AI가 직접 인정했다:

> "docs에서 `appName`에 대해 **정확한 '입력 길이', '사용 가능 문자 목록', '중복 검사 기준'**을 확인할 수 있는 내용은 찾지 못했어요."

→ **문서에 존재하지 않는 정보.** 콘솔 UI의 실시간 검증으로만 확인 가능. 후보 선점 여부 실측도 동일 이유로 불가(§8.1).

**서비스 종료 후 appName 재사용 가능 여부**: `service-termination.md`에 언급 없음. `[미검증]`

### 2.2 [비가역 ✅ 확정] 워크스페이스 / 사업자번호

**원문 (`guide/operation/console-workspace.md`)**

> "워크스페이스는 **사업자당 1개만** 만들 수 있어요"
> "이름은 다른 워크스페이스와 겹치게 정할 수 없어요"

**원문 (`guide/faq.md`)**

> "개인→법인 변경 시 사업자번호가 달라지면 **워크스페이스를 새로 만들어야 해요.**"

**원문 (`guide/operation/console-minor.md`)**

> "앱인토스 콘솔의 워크스페이스는 **만 19세 이상만 직접 만들 수 있어요.**"

**❌ 확인 실패: 워크스페이스 재생성 시 기존 미니앱 이관 가능 여부.**
`console-workspace.md`, `faq.md`, `service-termination.md` 어디에도 이관(migration) 절차가 없다. `service-termination.md`가 비사업자 관련해 "새로운 워크스페이스를 생성해서 미니앱을 **다시 등록**"이라고 표현한 것이 유일한 단서이며, 이는 **이관이 아니라 재등록**을 시사한다.

> 🔴 **재등록이라면 appName도 새로 잡아야 할 가능성이 있다** → 개인사업자로 시작 후 법인 전환하면 §2.1의 비가역 결정이 통째로 리셋될 수 있다. **채널톡 질문 7번이 가장 우선순위 높은 미해결 항목.**

### 2.3 [비가역 ✅ 확정] SDK 3.x

**원문 (`development/sdk-3.x.md`)**

> "**SDK 3.x 이상이 적용된 앱 번들을 출시하면 SDK 2.x 버전으로 롤백할 수 없어요.**"

**SDK 3.x를 선택해야 하는 결정적 근거 (원문):**

> "SDK 이슈가 발생해도 파트너사의 **재배포 없이 앱인토스 서버에서만 수정하고 반영할 수 있어요**"

→ 클라이언트 로직이 서버 처리로 이동했고 2.x와 파라미터 호환성은 유지된다. 운세 앱처럼 출시 검수가 3~7일 걸리는 서비스에서 **SDK 버그 하나로 재검수를 타지 않는다**는 건 매우 큰 이점.

**2.x → 3.x 마이그레이션 변경점 전체 (원문 표)**

| 항목 | 2.x | 3.x |
|---|---|---|
| 설정 파일 | `granite.config.ts` | `apps-in-toss.config.ts` |
| brand 설정 | 다수 속성 | `primaryColor` 만 |
| WebView 설정 | `webViewProps` (+ `type`) | `webView` (`type` 제거) |
| 출력 디렉터리 | `outdir` | `webBundleDir` |
| web 커맨드 위치 | 설정 파일 | `package.json` |

**자동 마이그레이션 명령**
```sh
npx ait migrate v3
```

**수동 마이그레이션 6단계 (원문 요지)**
1. 설정 파일명 변경 → 2. `brand`에 `primaryColor`만 남김 → 3. `webViewProps`→`webView` 및 `type` 제거 → 4. `outdir`→`webBundleDir` → 5. `web.commands`를 `package.json` scripts로 이동 → 6. build 스크립트에 `ait build` 추가

**리스크 완화 (원문)**: "Test thoroughly via QR code before release" — 출시 전 QR 코드 테스트로 충분히 검증할 것.

### 2.4 [🔄 가역으로 정정] 카테고리 — 비가역 아님

**근거 (`guide/console-mcp.md` — 콘솔 MCP tool 목록 원문에 포함)**

```
miniapp_update_basic_info, miniapp_update_category, miniapp_update_icon,
miniapp_update_screenshots, miniapp_update_age_rating, miniapp_update_privacy_policy
```

→ **`miniapp_update_category`가 공식 tool로 존재**한다. 카테고리는 등록 후 API/콘솔로 갱신 가능한 필드다. (`miniapp_create`와 별개로 존재하는 update tool이라는 점이 결정적.)

**카테고리 구조 (원문, `console-workspace.md`)**

- 게임: **장르별** 선택
- 비게임: **대분류 – 중분류 – 소분류** 3단 구조
- "중복 선택은 불가"
- GitBook AI 보강: 콘솔 내 섹션명은 **"카테고리 및 노출"**, 그리고 "이미 선택한 중분류와 같은 카테고리는 또 선택할 수 없어요" → **복수 개 선택은 가능하되 같은 중분류 반복만 금지**로 읽힌다. `[미검증]`

**❌ 확인 실패: 카테고리 전체 목록.** GitBook 공식 AI가 직접 부인:

> "비게임 미니앱 **카테고리(대분류/중분류/소분류) '전체 목록' 자체는** 현재 문서에서 제공되지 않아요."

→ 문서에 없는 정보이며 **콘솔 UI에서만 확인 가능**. `[B]` 항목 미해결.

## 3. 콘솔 MCP — 인증만 되면 즉시 실측 가능한 항목

### 3.1 설치 (완료됨)

```bash
# Claude Code (이미 실행 완료)
claude mcp add --transport http apps-in-toss-console \
  https://mcp.toss.im/adapters/apps-in-toss-console/mcp \
  --client-id mcp-gateway

# Codex
codex mcp add apps-in-toss-console \
    --url https://mcp.toss.im/adapters/apps-in-toss-console/mcp \
    --oauth-client-id mcp-gateway
```

### 3.3 인증 직후 실행할 실측 스크립트 (사용자 인증 후 그대로 사용)

| 순서 | 호출 | 확인 대상 | 대응 미해결 항목 |
|---|---|---|---|
| 1 | `workspace_list` | 기존 워크스페이스 유무 | §2.2 |

### 6.2 [1차] 민감 콘텐츠 7종 + 경고 화면 규정

`intro/caution.md` 원문 — 민감 콘텐츠는 **7개 항목 × 3단계**(경미 → 주의 → 출시 불가) 평가:

1. 선정성 / 2. 폭력성 / 3. 혐오·차별 / 4. 약물·도박 / 5. 범죄 조장 / 6. 공포·자살·자해 / 7. 기타 부적절

**경고 화면 규정 원문**:
> "미니앱이 민감 콘텐츠로 분류되면, 사용자가 미니앱에 **진입하기 전에 안내 화면이 노출**돼요. 사용자가 한 번 동의하면, 이후에는 민감 콘텐츠로 분류된 미니앱을 별도의 안내 UI 없이 이용할 수 있어요."

**'혐오·차별' 3단계 원문**

| 단계 | 기준 |
|---|---|
| 1단계(경미) | 가벼운 놀림 수준 / 의도가 명확한 유머 |
| 2단계(주의) | 특정 집단 조롱·비하 / 지속적 반복 |
| 3단계(출시 불가) | 인종·성별·장애 등 명시적 혐오 표현 / 폭력적 혐오 조장 |

**'기타 부적절' 3단계 원문**

| 단계 | 기준 |
|---|---|
| 1단계(경미) | 도전 영상·밈 등 경계 사례 |
| 2단계(주의) | 위험한 행동(불장난, 위험 운전 등) 묘사 |
| 3단계(출시 불가) | 불법행위 조장 / 허위정보·극단행동 유도 |

> 🔴 **운세앱 직결 리스크 2건**
> - **혐오·차별 2단계**: 혈액형 성격론과 MBTI 궁합 콘텐츠는 구조적으로 **"특정 집단(B형/특정 MBTI) 조롱·비하"**에 근접한다. "B형 남자는 …" 류의 카피는 2단계로 판정될 여지가 실재한다. → **콘텐츠 톤 가이드에 "특정 유형 비하 표현 금지"를 강제 규칙으로 넣어야 한다.**
> - **기타 부적절 3단계 '허위정보'**: 운세를 단정적 사실처럼 서술하면 "허위정보"로 읽힐 수 있다. → **전 화면 상시 면책 문구("엔터테인먼트 목적") 필수.**
> - **공포·자살·자해**: "죽음/사고/단명" 류 사주 해석 표현은 이 항목에 직접 저촉될 수 있다. → **부정 예언 표현 필터링 필수.**

### 6.3 [1차 ✅ 해소] 외부 코드 실행 금지 — LLM 구조는 저촉되지 않는다

`checklist/app-nongame.md` 비게임 출시 체크리스트 **원문** (기존 12개 문서에 없던 신규 확보):

**보안/구현 제약**
- "외부에서 전달받은 **코드를 실행하는 기능**은 사용할 수 없어요. (예: `eval` 등)"
- "브라우저 히스토리를 조작해서 자사 사이트로 이동시키는 방식은 사용할 수 없어요. (예: `window.location.replace` 등)"
- "**서버 사이드 렌더링(SSR)은 사용할 수 없어요. 클라이언트 사이드 렌더링(CSR) 또는 정적 사이트 생성(SSG) 방식만 사용할 수 있어요.**"
- "WebSocket을 사용하는 경우, 암호화된 `wss://` 연결만 사용해요."

**개인정보/사용자 식별**
- "사용자 식별자 값을 확인하여 저장하고, 미니앱이 정상적으로 시작돼요."
- "유저의 미니앱 사용 기록이 유지돼요."
- "**토스 앱에서 로그인 연결을 끊으면 사용자 데이터가 미니앱에 남아 있지 않아요.**"

**결제**
- "인앱 결제 주문 금액과 구글 또는 애플 결제창에 표시되는 금액이 일치해요."
- "**토스페이 외의 다른 결제 수단은 제공하지 않아요.**"

**콘텐츠**
- "불법성, 선정성 등 위법한 콘텐츠가 포함돼 있지 않아요."
- "미니앱 문구에 **비속어, 은어, 과도한 유행어**가 포함되지 않아요."

> ✅ **[A]질문 4 사실상 해소**: 금지 대상은 "**코드**를 실행하는 기능(`eval` 등)"으로 특정된다. LLM이 생성한 **운세 해석 텍스트를 JSON 데이터로 수신해 React가 렌더링**하는 구조는 코드 실행이 아니므로 저촉되지 않는다. 경계선은 명확하다 — **서버가 내려준 문자열을 `eval`/`new Function`/`dangerouslySetInnerHTML`+script로 실행하면 위반**, 데이터로만 취급하면 합법.
>
> 🔴 **신규 차단 요소 2건**
> - **SSR 금지**: Next.js App Router의 서버 컴포넌트/SSR을 쓸 수 없다. **CSR SPA 또는 SSG(`output: 'export'`)만 가능.** 문서 11의 기술스택 선정을 재검토해야 한다.
> - **토스페이 외 결제 수단 금지**: 별도 PG(카카오페이/네이버페이) 병행 불가.
> - **"과도한 유행어" 금지**: 운세 앱 카피 톤(밈·유행어 활용)에 직접 제약.

**❌ 미확정**: 체크리스트에 **서드파티 SDK(Amplitude/Sentry) 및 원격 CDN 스크립트에 대한 명시적 조항은 없다.** 다만 공식 문서에 Sentry 연동 가이드(`ai-vibe-coding/integration/sentry.md`, `documentation/unity/sentry.md`)가 존재하므로 **Sentry는 사실상 허용**으로 볼 여지가 크다. `[미검증]` — 채널톡 질문 5 유지.

### 6.4 [1차] 미성년자 정책 — 워크스페이스 vs 앱 연령제한은 별개

`guide/operation/console-minor.md` 원문:
- "앱인토스 콘솔의 워크스페이스는 **만 19세 이상만 직접 만들 수 있어요.**"
- 19세 미만은 **초대를 통해서만** 기존 워크스페이스에 참여 가능
- 접근 권한 부여 전 **관리자와 미성년자 양측의 별도 동의** 필요

> ✅ **판정**: 이 문서는 **콘솔 계정 운영자의 연령** 규정이지, **미니앱 이용자의 연령 제한**과 무관하다. 앱 이용자 연령은 앱 등록 폼의 선택 항목 "**사용 연령**"과 MCP tool `miniapp_update_age_rating`으로 별도 설정한다. 두 정책은 **완전히 별개**다. → 채널톡 질문 8의 절반은 해소.
> SDK에 `user.getDeclaredAgeRange` API가 존재하므로 앱 내부에서 연령대 확인도 가능하다(`documentation/sdk/domains-api/user/user.getdeclaredagerange.md`).

4. 🔴 **Amplitude / 원격 CDN 스크립트(gtag.js) 허용 여부** — 체크리스트에 조항 없음
5. 🔴 appName **길이/문자셋/중복검사 규칙** — 문서에 없음
6. 🔴 서비스 종료 후 **appName 재사용 가능 여부** — 문서에 없음
7. 🟡 간이과세자의 앱인토스 등록 가능 여부 (면세만 명시 배제됨) 및 역발행 세금계산서 처리
8. 🟡 CBT 종료 시점 (토스 수수료 0% → 5% 전환 시점), 인앱광고 15% 면제 프로모션 종료 시점
9. 🟡 카테고리 복수 선택 가능 여부 — "중복 선택은 불가"(1차) vs "이미 선택한 중분류와 같은 카테고리는 또 선택할 수 없어요"(AI) 의 정합성
10. 🟡 민감 콘텐츠 분류 시 경고 화면이 **전환율에 미치는 영향** — 측정 불가, 분류 회피가 최선
