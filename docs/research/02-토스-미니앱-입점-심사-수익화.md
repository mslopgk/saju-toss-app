## 1. 입점 절차 (Console → 출시)

### 1.1 전체 플로우

공식 순서 (`faq.md` 원문): **콘솔 가입 → 워크스페이스 생성 → 사업자 등록 → 앱 등록 → 검수 요청**

```
[1] 앱인토스 콘솔 회원가입   https://apps-in-toss.toss.im/
     ├ 조건: 만 19세 이상
     └ 조건: 본인 명의로 로그인된 토스 앱 보유
     └ 토스 비즈니스 회원 기반으로 가입 진행
         ↓
[2] 워크스페이스 생성
     ├ 사업자당 1개만 생성 가능 (★중요)
     ├ 이름 중복 불가 / 이름은 사후 변경 가능
     └ 생성자 = '대표관리자' 권한 자동 부여
         ↓
[3] 멤버 초대 (선택)
     ├ 관리자: 워크스페이스 전체 관리 + 정산 정보 조회
     └ 구성원: 권한 받은 앱 정보만 조회/관리
         ↓
[4] 사업자 등록  →  검수 영업일 1일
         ↓
[5] 앱 등록 (앱 이름 / appName / 앱 유형)
     └ 앱 정보 검수 영업일 1~2일
         ↓
[6] 개발 + 샌드박스(테스트앱) 테스트 1회 이상 필수
         ↓
[7] 콘솔에서 '검토 요청하기'  →  출시 검수 영업일 3~5일
         ↓
[8] 승인 → '출시' → 전체 사용자에게 즉시 반영
```

### 1.2 소요 기간 (공식 수치)

| 단계 | 소요 기간 | 출처 |

| 출시 검수 (deploy 문서 기준) | 영업일 **최대 3일**, 카테고리에 따라 **7일 이상** | `guide/operation/deploy.md` |
| 정산 정보 검토 | 영업일 **2~3일** | `in-app-ad.md` |

### 1.3 필요 서류 / 사업자 요건

**개인사업자 가능 여부: 가능.** 법인/개인 모두 등록 가능하다.

| 유형 | 등록 주체 | 필요 서류 |
|---|---|---|
| 개인사업자 | 대표자 본인 | 사업자 등록증 **(1건만)** |
| 개인사업자 | 대리인 | 사업자 등록증, 개인 인감증명서, 대리인 위임장, 대리인 신분증 사본 (4건) |
| 법인사업자 | 대표자 본인 | 사업자 등록증, 사업자 등기부등본 (2건) |
| 법인사업자 | 대리인 | 사업자 등록증, 등기부등본, 법인 인감증명서, 대리인 위임장, 대리인 신분증 사본 (5건) |

부가 조건:
- 등기부등본은 **발급일 기준 3개월 이내** 서류만 인정
- 공동대표의 경우 **모든 대표자**의 위임장 + 인감증명서 필요
- **개인 → 법인 변경 시 사업자번호가 달라지면 워크스페이스를 새로 만들어야 함** (`faq.md`) — 초기부터 최종 사업 형태를 정하는 편이 유리
- 통신판매업 신고 필요 여부는 공식 문서에 명시 없음 `[미검증]`

**사업자 없이 출시하는 경우** (`faq.md` 원문):
> "사업자가 없어도 앱을 출시할 수 있어요. 다만, 사업자가 없으면 계약 및 정산 등을 위해 일부 기능을 사용하지 못해요.
> 사업자가 필요한 기능: **토스 로그인, 비즈월렛, 프로모션, 인앱 광고, 토스페이, 인앱 결제**"

→ 즉 **사업자가 없으면 수익화 수단이 전부 막힌다.** 게다가 토스 로그인까지 막히므로 사용자 생년월일 스코프도 못 쓴다. 운세 앱은 사실상 **사업자등록 필수**.

### 1.4 앱 등록 시 입력 항목

- **앱 이름(국문)**: 토스 앱에 노출되는 이름. 사후 변경 가능.
- **영문명 규칙**: 15자 이내, 발음하기 쉬운 **명사형**. 명령문/동사구 금지("Book a Taxi" ✗ → "GoRide Taxi" ✓). 일반 단어 단독 사용 금지("Taxi" ✗). 단어 3개 이상/난해한 복합어 회피.
- **appName**: `intoss://` 스킴 ID. **한 번 등록하면 변경 불가** (★). 규칙 위반 시 서버 인증서 발급 실패.
- **앱 유형**: 게임 / 비게임 선택 → 이후 입력 항목이 달라짐.

## 2. 심사 정책 — 운세·사주 콘텐츠 허용 여부

### 2.1 결론

공식 문서 전문(`intro/guide.md`, `intro/caution.md`, `checklist/app-nongame.md`)에 **운세·사주·타로·점술·심리테스트·별자리·MBTI·혈액형 키워드는 0건**이다. 즉 명시적 금지도, 명시적 허용도 없다.

개발자센터 GitBook의 `?ask=` 질의 응답(공식 문서 기반 답변)은 다음과 같이 회신했다:

> "운세, 사주, 타로, 점술 콘텐츠는 **형태에 따라 미니앱으로 출시 검토가 가능**합니다. (…) 이러한 미니앱은 **'엔터테인먼트 제공'으로 설계**하는 것이 효과적입니다. 핵심은 **복권·베팅·투자 유도 같은 금지 요소를 철저히 배제**하는 것입니다."

### 2.2 출시 불가 서비스 8종 (`intro/guide.md` §1) — 운세 앱 적합성 판정

| # | 제한 카테고리 | 원문 요지 | 운세앱 저촉? |
|---|---|---|---|
| 1 | 디지털 자산/가상자산 | NFT 포함 소유·이전·저장·거래·중개·발행. **법적 요건 충족 여부와 관계없이** 불가 | ✗ (NFT 부적 등 굿즈 절대 금지) |
| 2 | 자금세탁 가능성 | 현금/유사 자산의 직접 교환·전환·환불 기능 | ✗ (포인트 현금 환전 금지) |
| 3 | 불법·부정행위 조장 | 신분 조작, 해킹, 불법 문서, 정보 수집 우회 | ✗ |
| 4 | **사행성 및 복권/베팅성** | 재산상 손실·중독 유발·연령 제한 문제 | ⚠ **주의** — "행운의 번호", "로또 번호 추천"은 복권성으로 해석될 수 있음 |
| 5 | 금융 서비스/송금 | 대출·보험·카드·증권. **법적 인허가 여부와 관계없이** 불가 | ⚠ **주의** — "재물운/투자운" 표현 수위 관리 필요 |
| 6 | **투자 자문·리딩방·유료 정보** | 특정 종목 추천, 투자 전략 안내로 개인 투자 의사결정에 영향 | ⚠ **주의** — 재물운을 종목/코인 추천으로 연결 금지 |
| 7 | 의료 관련 | 비대면 진료, 병원 예약, 병원 광고비 수취 | ⚠ **주의** — "건강운"을 진단/치료 조언으로 서술 금지 |
| 8 | 내부 정책상 승인 불가 | 법률 위반 여부와 무관하게 브랜드 신뢰성/UX/리스크 관리 기준 | ⚠ 재량 영역 |

추가 단서 조항 (원문):
- "심사 결과는 내부 정책 및 리스크 검토 절차에 따라 변경될 수 있으며, **사전 등록을 보장하지 않아요**."
- "서비스 특수성, 비즈니스 모델에 따라 **사전 상담 또는 추가 설명 요청**이 있을 수 있어요."
- "**기존 회사 및 서비스를 단순 홍보하기 위해서** 앱인토스 미니앱을 출시할 수 없어요."

### 2.3 ★최대 리스크: 미니앱 어뷰징 방지 정책 (`intro/guide.md` §3)

이 조항이 본 프로젝트에 **가장 직접적인 영향**을 준다.

> "**1) 동일 워크스페이스 내에서 유사한 핵심 기능 기반의 앱을 여러 개 출시할 수 없어요.**
> 핵심 기능이 같다면 **테마나 대상, 주제, 스타일 등만 다르게 구성하더라도 별도의 미니앱으로 인정되지 않아요.** 새로운 기능이나 콘텐츠를 추가하고 싶을 때는 기존 앱을 업데이트 해주세요."
>
> 예시: 동일 파트너사에서 'AI 여자 얼굴 만들기', 'AI 남자 얼굴 만들기' 등과 같이 **주제만 다르고 결과물만 달라지는** 개별 미니앱으로 출시하는 경우

> "**2) 동일한 브랜드를 활용하여 여러 개의 미니앱 출시는 불가해요.** 검색 또는 노출을 과도하게 점유하기 위함 등과 같이 (…) 이름, 로고, 색상 등 브랜드 아이덴티티를 반복하여 여러 개의 미니앱으로 출시하는 것은 허용되지 않아요."

**해석 → 제품 설계 제약:**
- 「오늘의 사주」/「MBTI 궁합」/「별자리 운세」/「혈액형 성격」을 **4개 미니앱으로 쪼개면 100% 반려**된다. 핵심 기능(= 입력값 기반 운세 결과 생성)이 동일하고 주제만 다르기 때문이며, 공식 예시("AI 여자/남자 얼굴 만들기")와 구조가 정확히 일치한다.
- **반드시 1개 미니앱 안에 4개 축을 모두 담아야 한다.** 이는 오히려 본 프로젝트의 "결합" 컨셉과 자연스럽게 맞는다.
- 위반 시 조치: 콘텐츠 수정 요청 → 서비스 미노출 처리 → 반복 위반 시 미니앱 등록·운영 제한.

### 2.4 민감 콘텐츠 등급제 (`intro/caution.md`)

민감 콘텐츠는 **선정성 / 폭력성 / 불법·범죄 조장** 3분류로 관리되며, 3단계 등급표가 있다.

| 항목 | 1단계(경미) | 2단계(주의) | 3단계(출시 불가) |
|---|---|---|---|
| 선정성 | 짧은 노출, 수영복 수준 / 약한 암시 | 신체 부위 강조, 키스·접촉 반복 / 노골적 성적 농담 | 성행위 묘사, 자극적 편집 / 성적 대상화 |
| 폭력성 | 액션·코믹 / 부상 없음 | 타격·고통 묘사, 피 보임 | 유혈·잔혹, 학대·고문 / 폭력 미화 |
| 혐오·차별 | 가벼운 놀림 / 의도 명확한 유머 | 특정 집단 조롱·비하 / 지속 반복 | 인종·성별·장애 등 명시적 혐오 |
| 약물·도박 | 배경 등장 / 실제 섭취 아님 | 음주·흡연 반복 / 도박 행위 등장 | 마약 사용·판매 / 도박 미화·권장 |
| 범죄 조장 | 상황적 설정 | 절도·폭행을 흥미 요소로 | 불법행위 직접 촬영, 모방 유도 |
| 공포·자살·자해 | 긴장감 연출 / 유혈 없음 | 공포 반복 / 자해 언급 등장 | 자살·자해 구체 묘사 / 모방 위험 |
| 기타 부적절 | 도전 영상·밈 경계 사례 | 위험 행동 묘사 | 불법행위 조장 / **허위정보·극단행동 유도** |

**운세 앱 관련 실무 포인트:**
- 민감 콘텐츠로 분류되면 **진입 전 안내 화면(경고 인터스티셜)** 이 강제 노출된다 → 전환율 직격타. 1회 동의 후에는 안 뜬다.
- 등급표 "기타 부적절 3단계"의 **"허위정보·극단행동 유도"** 가 운세 앱의 실질 리스크다. 예: "이번 달 대흉, 이사하지 않으면 큰일 난다" 류의 **공포 마케팅 표현**은 3단계로 판정될 여지가 있다.
- "혐오·차별 2단계 = 특정 집단 조롱·비하 / 지속적 반복 **(출시 불가)**" — **혈액형·MBTI 성격 서술에서 특정 유형을 비하하는 톤은 직접 저촉된다.** (예: "B형은 이기적이다", "ISTJ는 답답하다") → 전 유형에 대해 **긍정/중립 프레이밍 카피 정책**을 코드/콘텐츠 레벨에서 강제해야 한다. 이것이 본 프로젝트의 가장 현실적인 반려 리스크다.
- "미니앱 문구에 비속어, 은어, 과도한 유행어가 포함되지 않아요" (`app-nongame.md`)

### 2.5 생성형 AI 서비스 의무 (`intro/guide.md` §5)

AI로 운세 해석 문구를 생성한다면 **필수 준수 사항**이다.

1. **사전 고지 의무**: 서비스 최초 이용 시점 또는 생성형 AI 기능 최초 사용 시점에, 해당 기능이 생성형 AI를 활용한다는 사실을 사용자가 인지할 수 있도록 고지
2. **표시 의무**: AI가 생성한 결과물은 **라벨·배지·워터마크 등 사람이 즉시 인식 가능한 방식**으로 표시
3. **위반 시 조치**: 관련 법령에 따라 **최대 3,000만 원 과태료**, 관계 기관 자료 제출 요구, 현장 조사, 서비스 중지 또는 시정명령

→ LLM으로 사주 해석문을 생성할 계획이면 결과 화면에 `AI 생성` 배지를 반드시 넣어야 한다.

### 2.6 로그인/결제/광고 연동 제한 (`intro/guide.md` §6) — ★설계 확정 사항

| 구분 | 허용 | 금지 |
|---|---|---|
| 로그인 | **토스 로그인만** | 자사 로그인, 소셜 로그인(카카오/구글/애플), 간편 로그인 일체 |
| 실물 상품 결제 | **토스페이만** | **토스페이먼츠(PG) 포함 기타 모든 결제 수단** |
| 디지털(비실물) 상품 결제 | **인앱결제만** | 그 외 전부 |
| 광고 | 앱인토스 **전면형 / 보상형 / 배너** | **외부 광고 네트워크 직접 연동 일체** |

> **중요 정정**: 흔한 오해와 달리 **토스페이먼츠(PG) 연동은 미니앱에서 명시적으로 금지**다. 운세 결과 열람권·프리미엄 리포트 등은 전부 **디지털 상품 = 인앱결제(IAP)** 로 처리해야 한다. 실물 굿즈(부적 카드 등)를 팔지 않는 한 토스페이는 쓸 일이 없다.

### 2.7 자사 앱 설치 유도 / 외부 링크 제한 (`intro/guide.md` §4)

- 자사 앱 설치 유도 문구·배너·앱마켓 링크·설치 시 혜택 안내 **전면 금지**
- 외부 링크: "자세한 내용은 홈페이지에서 확인하세요", "이동 후 결제를 완료해주세요", "외부 웹사이트에서 가입" 전부 제한 대상
- 공유하기 링크가 **자사 웹사이트로 랜딩되면 위반**
- 허용되는 예외: 법률상 고지/필수 안내, 공공기관·제휴기관 공식 페이지, 단순 정보 확인용 타사 사이트, 제품 추천 후 최저가 구매 플랫폼 이동, 쿠폰 발급 플랫폼 이동
- **"콘솔에 설정한 '앱 내 기능'은 미니앱 내에서 완결적으로 경험"** 되어야 함

### 3.1 인앱결제(IAP) — 디지털 상품

| **앱마켓 수수료** | 공급가 기준 **15%** (현재 적용) / 총 수익 증가 시 **30%** 로 변경 가능 |

| 최대 공급가 | **1,400,000원** |
| 입력 단위 | **10원** 단위 |

| 구독 갱신 주기 | 매주(7일) / 매월(30일) / 매년(365일) |
| 무료 체험 옵션 | 3일 / 1주 / 2주 / 1개월 |

**정산금 계산 예시** (`settlement.md` 원문 표):

애플(App Store)
| 결제 금액(VAT 포함) | (-)앱마켓 수수료(VAT 포함) | (-)토스 수수료 | (-)토스 수수료 부가세 | (=)파트너사 정산금 |
|---|---|---|---|---|
| ₩11,000 | ₩1,650 | ₩550 | ₩55 | **₩8,745** (79.5%) |

구글(Google Play)
| 결제 금액(VAT 포함) | (-)앱마켓 수수료 | (-)토스 수수료 | (-)토스 수수료 부가세 | (=)파트너사 정산금 |
|---|---|---|---|---|
| ₩11,000 | ₩1,500 | ₩550 | ₩55 | **₩8,895** (80.9%) |

**IAP 정산 주기**: 앱마켓(App Store / Google Play)이 토스에 정산한 대금이 **입금된 날로부터 3영업일 내** 지급.
> 예시(원문): 앱마켓이 5월 정산대금을 토스에 지급(6/5) → 토스는 3영업일 내 파트너사에 지급(~6/8)

- 앱마켓 정산금은 **서울 외국환중개소 매매기준율 최초고시환율**, 당월 말일자 환율로 원화 변환
- 애플 수수료 부가세는 **애플 대신 토스가 세금계산서 발행**
- 토스 수수료 부가세는 토스가 **선공제 후 발행**
- 현금영수증 발행/취소는 국세청 일정에 따라 결제일/환불일로부터 **약 3영업일 후** 집계 반영
- USD 지급 시 **한국 구간 송금 수수료는 토스 부담**, 해외 구간은 파트너사 부담

**환불 처리 권한**:
- iOS: **Apple이 전적으로 관리**, 파트너사 권한 없음
- Android: 파트너사가 승인/반려 처리 가능, 최종 결정은 Google Play

> **운세 앱 상품 설계 시사점**: 비게임은 IAP 상품 **최대 30개**. "프리미엄 종합 리포트", "궁합 리포트", "월간 구독" 등으로 압축 설계 필요. 최소 400원이므로 **990원~2,900원 단건 리포트 + 월 구독** 조합이 현실적.

### 3.2 인앱광고(IAA)

**허용 네트워크**: Google AdMob + Toss Ads (미디에이션). **외부 광고 네트워크 직접 연동 금지.**

| 광고 유형 | 노출 빈도 | eCPM | 특징 |
|---|---|---|---|
| 배너 | 가장 많음 | 가장 낮음 | 화면 상단/중앙/하단. **스크롤 가능한 화면에만** 노출 |
| 전면형(Interstitial) | 중간 | 중간 | 화면 전환 시 전체 화면 |
| 리워드(Rewarded) | 낮음 | **가장 높음** | 사용자 선택형 시청 |

수익 계산식 (원문): `예상 수익 = 노출 수 × eCPM ÷ 1,000`
> 예: 100,000회 노출 × 5,000원 eCPM = 500,000원

**광고 수수료 구조** (`settlement.md`):
1. **광고 송출 운영비 약 30% 공제** — "앱인토스는 광고 송출을 위해 외부 미디에이션 플랫폼과 Toss Ads를 사용해요. 이 과정에서 광고 매출의 **약 30% 수준을 운영비로 공제**해요."
   - Toss Ads 송출 시: 광고 매출(부가세 포함)에서 운영비 30% 공제
2. **앱인토스 수수료 15% 추가 공제** — "광고 대행에 대한 비용", **현재 수수료 면제 프로모션 진행 중**

정산 예시표 (원문):
| 광고 수익 | 광고 수익 부가세 | 앱인토스 수수료 | 수수료 부가세 | 파트너사 정산금 |
|---|---|---|---|---|
| ₩14,700 | ₩1,470 | ₩2,205 | ₩221 | **₩13,774** |

**광고 정산 스케줄**:
```
당월 매출 발생
  → 익월 2영업일: 정산 내역 확정 + 토스에서 세금계산서 역발행
  → 익월 2영업일 오후 3시 이내: 승인 요청 메일 발송
  → 익월 4영업일까지: 역발행 세금계산서 승인 (마감)
  → 익월 말일(영업일 기준): 승인된 금액 지급
```
- **최소 정산금액: 5,000원 이하면 다음 달로 이월 누적**
- 일반과세자: 팝빌 **역발행** 방식만 지원 (팝빌 가입 + 공인인증서 등록 필요). **정발행은 지원 종료, 정발행 처리 건은 광고수익 지급 대상에서 제외**
- 간이과세자: 세금계산서 발행 없이 정산금 지급
- 사업자 유형은 콘솔에서 직접 선택, **정산 확정 이후에는 변경 불가**

**광고 운영 제한** (`in-app-ad.md`, `app-nongame.md`):
- "Ad" 표기 유지 필수
- 동일 화면에 동일 포맷 광고 2개 이상 금지
- 광고 클릭과 보상을 직접 연결 금지
- 비정상 트래픽 확인 시 광고 제한 및 **정산 보류**
- 인트로/로딩/컷신/팝업 모달 등 일시적 화면에 노출 금지
- 광고 사전 로딩 필수

**IAA 신청 절차 (3단계)**: ① 사업자 정보 등록 → ② 정산 정보 입력(검토 2~3일) → ③ 광고 그룹 생성 (최대 2시간 후 Google 등록)

### 3.3 토스페이 (실물 상품 전용)

운세 앱은 원칙적으로 불필요하나, 오프라인 상담 연계·굿즈 판매 시 참고.

- **연동 프로세스**: 입점 제한 항목 확인 → 중개 플랫폼 조건 확인 → 입점 심사 → 계약 서류 메일 안내 → **서류 등기 제출** → 서류 검토·심사 → 계약 체결(상점 계정 생성) → 개발 연동 → 오픈
- **키 발급까지 영업일 7~14일**
- **자동결제(정기결제) 수수료**: 기본 **결제금액의 3%**, **최소 건당 100원**

| 결제 금액 | 수수료 |
|---|---|
| 10,000원 | 300원 |
| 5,000원 | 150원 |
| 3,000원 | **100원 (최소 수수료 적용)** |

- 일반 결제 수수료율은 계약 시 개별 협의 `[미검증]`
- `isTestPayment: true` 로 계약(청약) 전에도 샌드박스 결제 테스트 가능 (생성까지만, 실제 승인 미지원)
- **입점 제한 항목** 중 운세 관련 주목: "**사행성 업종(경마, 카지노, 도박, 경륜, 대부업, 환전상, 경매, 유흥 구인구직, 도박 기계 판매업, 성인용 게임장 등)**", "**복권**"(오프라인 판매만 제한적 허용), "**주식정보 제공 서비스(유사투자자문업)**", "**랜덤(럭키)박스 등 민원이 제기될 우려가 있는 상품 및 서비스 일체**"
  - → **랜덤박스형 뽑기 과금(가챠)은 토스페이 입점 제한 항목에 명시**되어 있다. "랜덤 운세 뽑기 유료화"는 리스크.
- 중개 플랫폼 구조로 하위 셀러에게 직접 정산 시: **PG 라이선스 없으면 정산대행 서비스(예: 토스페이먼츠) 계약 필수**. 심사 시 정산대행 계약서, 제3자정산 공문 유형C, KYC 제출 요구.

## 5. 마케팅 · 리워드 도구 (수치)

### 5.1 프로모션 (토스 포인트 지급)

| 항목 | 값 |
|---|---|
| **1인당 지급 한도** | **5,000포인트 미만** (모든 프로모션 유형 원칙 적용, 추첨형은 별도 검토) |
| 비즈 월렛 프로모션 예산 충전 | **최소 30만 원 ~ 최대 3,000만 원** |
| 일반 충전 금액 범위 | **최소 50,000원 ~ 최대 30,000,000원** |
| 비인증 결제 한도 | 하나카드 하루 100만 원, 그 외 카드사 제한 없음 |
| 자동 충전 | 설정 가능 (예: 10만원 남으면 50만원씩 충전) |
| 랜덤 지급 | 최대 금액 설정 시 0~최대 사이 랜덤 (예: 최대 100원 → 0~100원) |
| 테스트 | `TEST_{promotionCode}` 로 실제 포인트 차감 없이 검증 |

허용 예시: 회원가입·접속 보상(예: 신규 가입 시 2,000포인트), 거래·구매 유도형(예: 5,000원 이상 결제 시 500포인트)
**불가 예시**: 재화 환전형 리워드(기프티콘·상품권을 토스 포인트로 전환), 1인당 5,000포인트 초과 지급, **게임 결과나 등수를 기준으로 지급하는 형태**, 사용자가 가진 재화를 토스 포인트로 교환·전환

> ⚠ **한 번 지급한 토스 포인트는 회수 불가.** 조건 설계 신중히.
> 비게임 미니앱은 **Server-to-Server 방식** 포인트 지급 가능 (위·변조 방지). 포인트 지급 API 테스트를 **최소 1회 완료**해야 프로모션 시작 가능.
> 지급 시 사용자 화면 상단에 `{미니앱 이름}에서 {금액}원을 지급했어요` 토스트 노출.

### 5.2 스마트 발송 (푸시/알림)

- 워크스페이스(사업자)당 **10만 건까지** 발송 가능
- 광고 푸시 일일 한도: 워크스페이스 기준 하루 최대 **10만 명**
- 메시지 템플릿 문구 **검수 필요** (광고성 메시지는 자동 검수), 검수 영업일 **2~3일**
- 건당 수수료: **현재 0원** (`settlement.md`) / FAQ상 참고 요율 **9.9원(VAT 포함)**
- 발송 전 `예상 발송 건수 × 건당 수수료`로 비즈월렛 선차감 → 실제 성공 건수 기준 재계산 → 차액 자동 환급
- 정기 발송 지원 (매일 지정 시간 / 매주 요일+시간, 종료일 없음 옵션)
- 세금계산서는 실제 발송 성공 건수 기준, 매월 3영업일까지 발행
- 문구 예시(공식): 좋은 예 `[출석 선물] 블록 게임 3일 출석하면 20원을 드려요.` / 나쁜 예 `[내 이상형] 장원영인가요, 안유진인가요?`

> 운세 앱은 **"오늘의 운세" 데일리 푸시**가 리텐션 핵심인데, 광고성 푸시는 하루 10만 명 한도 + 검수 2~3일이 병목. 정기 발송(매일 지정 시간) 설정으로 운영해야 한다.

### 5.3 공유 리워드

- 연락처 모듈로 토스 사용자 연락처를 불러와 공유 완료 사용자에게 리워드 지급. 공유는 **토스 알림 푸시**로 진행.
- 발송 제한: **하나의 리워드 ID 기준, 한 사용자에게 하루 1회만** 발송 가능. 일 단위 초기화. 리워드 ID가 다르면 제한은 독립 적용.
- 게임/비게임 모두 사용 가능.

| **Apple Mini Apps 파트너 프로그램** | 미니앱 파트너 프로그램 도입, 수수료 **15%** 로 절감 (뉴스 보도 기준) | `[미검증]` — 원문 미확인 |

> 국내 주요 운세 앱들이 App Store/Google Play에서 정상 서비스 중이라는 사실 자체가, 운세 콘텐츠 자체는 플랫폼 차원에서 금지 대상이 아니라는 방증이다. 앱인토스의 실질 게이트는 "운세인가"가 아니라 "**사행성/투자자문/의료/혐오 요소가 섞였는가**"이다.

## 8. 본 프로젝트 실행 체크리스트

### 8.1 반드시 지킬 것 (반려 방지)

- [ ] **미니앱 1개**에 사주·MBTI·혈액형·별자리 4축을 모두 담는다 (§2.3 어뷰징 정책)
- [ ] 로그인은 **토스 로그인만** 구현. 카카오/구글/애플 로그인 코드 일절 없음
- [ ] 유료 상품은 **인앱결제(IAP)** 만. 토스페이먼츠/외부 PG 연동 금지
- [ ] 광고는 **앱인토스 배너/전면형/보상형만**. AdMob 직접 연동 금지
- [ ] 렌더링은 **CSR 또는 SSG**. SSR 절대 금지 (Next.js면 `output: 'export'`)
- [ ] `eval` 등 동적 코드 실행 제거, WebSocket은 `wss://` 만
- [ ] **라이트 모드 전용** 구현 (다크 모드 미지원)
- [ ] LLM으로 운세 문구 생성 시 **AI 생성 배지 + 최초 사용 시점 고지** (과태료 최대 3,000만 원)
- [ ] 혈액형/MBTI 성격 서술을 **전 유형 긍정·중립 톤**으로 통일 (혐오·차별 2단계 = 출시 불가)
- [ ] "이사 안 하면 큰일 난다" 류 **공포·불안 조성 카피 금지** (허위정보·극단행동 유도 = 3단계)
- [ ] "행운의 로또 번호", "재물운 종목 추천" 등 **복권/투자자문 연상 기능 제외**
- [ ] "건강운"은 진단·치료 조언으로 서술하지 않음
- [ ] 토스 로그인 연결 해제 시 **사용자 데이터 완전 삭제** 로직 구현
- [ ] 진입 즉시 바텀시트 자동 오픈 금지, 광고를 로딩/인트로 화면에 넣지 않음
- [ ] 공유 링크는 `intoss://` 스킴 (자사 웹으로 랜딩 금지)
- [ ] 자사 앱/웹 설치·이동 유도 문구 전면 제거
- [ ] 앱 번들 **100MB 이하**, 반응 지연 2초 미만
- [ ] 빌드는 `ait build`, SDK는 최신 버전 유지
- [ ] 앱 이름에 **연속 공백 사용 금지** (techchat 3601 반려 사례)

### 8.2 준비 서류·계정

- [ ] 개인사업자 등록 (사업자등록증 1장이면 충분) — 국세청 신청 후 통상 1일 내 발급 가능 `[미검증 — 커뮤니티 후기]`
- [ ] 팝빌 가입 + 공인인증서 등록 (역발행 세금계산서 승인용, 광고 정산 필수)
- [ ] 일반과세자/간이과세자 선택 (**정산 확정 후 변경 불가**)
- [ ] 정산 계좌 등록
- [ ] 개인정보처리방침 / 이용약관 (토스 로그인 약관 화면 URL 등록 필요)

### 8.3 생년월일 수집 방식 3안

`?ask=` 응답 기준:
- **A. 토스 로그인 스코프**: 콘솔에서 `USER_BIRTHDAY` 스코프 선택 → 약관 동의 자동 포함, 약관 링크 정확히 노출 필요. **사주 계산에 가장 적합** (사용자 입력 마찰 0)
- **B. 유저 정보 연동**: 개인정보 제3자 제공 동의 후 토스 저장 정보 전달받음. 동의 화면 노출 항목 최대 5개
- **C. 원터치 인증(`USER_NONE`)**: 클라이언트에서 개인정보 입력 없이 인증 완료

> ⚠ 사주는 **생시(태어난 시각)** 가 필요한데, 토스 스코프는 생년월일만 제공한다. 생시는 사용자 직접 입력 UI가 필수.
> ⚠ `USER_BIRTHDAY` 스코프 정확한 명칭·응답 포맷은 `documentation/api/toss-login.md` 에서 재확인 필요.

## 9. 남은 확인 사항 (Open Questions)

3. **혜택탭** 노출 조건 및 신청 절차 (referrer 목록에 전용 코드 없음)
4. `home_intelligence`(홈 인텔리) 지면 **입점 조건·비용**
5. 인앱결제 **토스 수수료 5% CBT 면제 종료 시점**
6. 인앱광고 **앱인토스 수수료 15% 면제 프로모션 종료 시점**
7. 스마트 발송 건당 수수료: FAQ 9.9원 vs settlement 0원 — 실제 적용 요율
8. **통신판매업 신고** 필요 여부 (디지털 콘텐츠 유료 판매 시)
9. 토스페이 **일반 결제 수수료율** (자동결제 3%만 공개됨)
10. 카카오/네이버의 운세 콘텐츠 **명문 정책 조항** 원문 확보
