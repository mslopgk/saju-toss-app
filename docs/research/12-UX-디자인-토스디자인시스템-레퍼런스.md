## 1. 앱인토스 미니앱이 반드시 지켜야 하는 UI 규칙

### 1-1. 브랜드 아이덴티티 (콘솔 + `granite.config.ts` 이중 등록)

| 항목 | 규칙 | 설정 위치 |
|---|---|---|
| 로고 | 600×600px, **각진 정사각형**(둥근 모서리 불가), 라이트/다크 양쪽에서 가시성 확보 | 콘솔 업로드 + `brand.icon` |
| 이름 | 특별한 이유 없으면 **한글 사용 권장** | 콘솔 + `brand.displayName` |
| 컬러 | 기존 브랜드 컬러 유지 또는 로고에서 추출. `#3182F6` 형식 | 콘솔 |

> 사주앱 적용: 로고는 정사각 프레임 안에 오행/별자리 심볼을 넣되 모서리 라운딩은 토스가 자동 처리하도록 맡긴다. 브랜드 컬러는 오행 색(청·적·황·백·흑) 중 하나를 대표로 고르기보다 "야간 하늘" 계열 단일 헥스로 고정하는 게 TDS 컬러와 충돌이 적다.

### 1-2. 다크패턴 방지 정책 — 금지 5종 (필수 준수)

1. 서비스 진입 시 **전면 바텀시트** (광고성 팝업, 알림 동의 강요)
2. **뒤로가기 시 인터럽트** (이탈 방지용 추가 화면)
3. **선택지 부재** (거절 옵션 없는 강제 설계)
4. **예상 밖의 광고 노출** (사용 흐름 중 돌연 삽입)
5. **모호한 CTA 버튼** ("다음 행동을 예상할 수 없는 경우")

> 운세앱은 4번·5번에 특히 취약하다. "결과 보기" 버튼이 실제로는 리워드 광고 시청으로 이어지면 4·5번 동시 위반. → CTA 문구를 `광고 보고 결과 열기`처럼 **행위 명시형**으로 써야 한다.

### 1-3. 비게임 미니앱 출시 심사 체크리스트 (총 16항목, 원문 기준)

**내비게이션 바 (10)**
1. 앱인토스 **비게임 내비게이션 바** 사용
2. 좌측 **뒤로가기(<)** 가 모든 화면에서 동작
3. 중앙에 **브랜드 로고·미니앱 이름(국문)** 표시
4. 중앙 홈 버튼 기능 탑재 (선택)
5. 우측에 미니앱 고유 버튼 **최대 1개** 배치 (선택)
6. 토스 뒤로가기와 미니앱 자체 뒤로가기 **동시 노출 X**
7. 더보기(⋯)에서 **토스 공통 기능** 제공
8. **닫기/뒤로가기** 노출 및 동작이 명확
9. 최초 화면에서 뒤로가면 **미니앱 종료**
10. 탭바 사용 시 토스 앱과 동일한 **플로팅 형태**

**UX (6)**
1. 진입하자마자 **바텀시트 자동 노출 X**
2. 화면 전환 시 **바텀시트로 강제 유도 X**
3. 모든 화면에서 **나갈 방법 명확**
4. **CTA 예측 가능**
5. 링크/컴포넌트로 **자사 이동·앱 설치 유도 X**
6. **인앱 광고**가 일시 화면에 노출되지 않기

### 1-4. 탭바/네비게이션 컴포넌트 규칙

- 내비게이션은 **필수 컴포넌트** (게임/비게임 구분 제공)
- 탭바는 토스가 제공하는 **플로팅 형태 필수**, **최소 2개 · 최대 5개**
- Figma 작업 시 **모든 화면 최상단에 `❖ Navigation` 컴포넌트 배치 필수**

`setNavigationBar` 계열 옵션 타입 (앱인토스 문서 원문):

```ts
interface NavigationBarOptions {
  withBackButton?: boolean;          // 좌측 뒤로가기
  withHomeButton?: boolean;          // 비게임 미니앱 전용 홈 버튼
  withTitle?: boolean;               // 좌측 아이콘+미니앱 이름
  transparentBackground?: boolean;   // 배경 투명
  theme?: 'light' | 'dark';          // 내비게이션 바 테마
  initialAccessoryButton?: InitialAccessoryButton;
}

interface InitialAccessoryButton {
  id: string;
  title?: string;
  icon: { name: string };            // 모노톤 아이콘만 지원
}
```

WebView 설정 예시:

```ts
navigationBar: {
  withBackButton: true,
  withHomeButton: true,
  initialAccessoryButton: {
    id: 'heart',
    title: 'Heart',
    icon: { name: 'icon-heart-mono' }
  }
}
```

제약: **액세서리 버튼은 모노톤 아이콘만**, **한 번에 1개만**, 컬러 아이콘·커스텀 UI 미지원, 홈 버튼은 비게임 전용.

> 사주앱 적용: 액세서리 버튼 1개를 `icon-*-mono` 계열로 "내 사주 다시 보기"에 쓸지 "공유"에 쓸지 택1해야 한다. 공유는 더보기(⋯)의 토스 공통 기능에 이미 있으므로 **액세서리 버튼은 "내 프로필/생년월일 수정"에 배정**하는 편이 낫다.

### 1-5. 해상도 & 에셋

| 구분 | 값 |
|---|---|
| 논리 해상도(세로형) | 약 360×640 ~ 420×740 |
| 논리 해상도(가로형) | 약 640×360 ~ 740×420 |
| 트래픽 집중 구간 | 전체 미니앱 트래픽의 **약 70~80%가 가로 800~900 / 세로 360~420** 범위 |
| 에셋 배수 | 1x 기본, **2x 필수 대응**, 3x는 선택 |
| Figma 프레임 폭 | **375px** |
| 앱빌더 기준 기기 | **iPhone 13 mini (375×812)** |

### 1-6. 그래픽 사용 원칙

- 문맥에 부합하는 그래픽만 선택
- **다크모드·라이트모드 동시 고려**
- "부정적이거나 호소하는 감정 표현은 피해주세요"
- **장식 효과(파티클, 과한 그라데이션) 금지**

> 운세앱 치명 포인트: "오늘 운세 최악" 같은 부정 감정 일러스트, 별가루 파티클 연출, 보라~핑크 3-stop 그라데이션 배경이 전부 이 항목에 걸린다. **결과 공개 연출은 파티클 대신 카드 플립/블러 해제/스케일 트랜지션 같은 형태 변화로 설계**해야 한다.

## 2. TDS(Toss Design System) — 공개된 실체

### 2-1. 앱인토스에 실제로 제공되는 TDS 컴포넌트 (11종)

앱인토스 디자인 문서에 명시된 UI Kit 컴포넌트:

`Badge` · `Border` · `BottomCTA` · `Button` · `Asset` · `ListRow` · `ListHeader` · `Navigation` · `Paragraph` · `Tab` · `Top`

> 주의: 이 11종은 **앱인토스 파트너용 축소판**이다. 토스 내부 TDS Mobile은 40+ 컴포넌트 규모(아래 2-2 참조). 각 컴포넌트별 사이즈/variant/개수 제한 상세는 공개 문서에서 확인되지 않았다 `[미검증]`.

Figma 사용 시 문서에 명시된 설계 원칙 5가지:
1. 모든 화면 최상단에 `❖ Navigation` 컴포넌트 필수
2. 속성 조작은 **오른쪽 패널에서만** 실행
3. 화면 기준 **가로 375px**
4. 상단 `❖ Top`, 아래 `❖ ListRow` 구성 권장
5. **TDS 컴포넌트에 기본 패딩 포함 → 별도 gap 불필요**

Figma 배포 파일명(문서 기준): `TDS_Mobile_for_Apps_in_Toss_(2602).fig`

### 2-2. TDS Mobile 전체 컴포넌트 지형 (tossmini-docs 기준, 40+)

| 카테고리 | 컴포넌트 |
|---|---|
| Foundation | Colors, Typography |
| Form | Button, Checkbox, Switch, TextField, TextArea, SplitTextField |
| Navigation | Tab, Segmented Control, Menu |
| Data display | Table Row, Grid List, Board Row, Post |
| Feedback | Toast, Tooltip, Dialog, BottomSheet, Modal, Loader |
| Input 특화 | Keypad variants, NumericSpinner, Slider, Rating |
| 복합 패턴 | ListRow, BottomCTA, Agreement, Chart |
| Hooks | `useDialog`, `useToast`, `useBottomSheet` |

마이그레이션 경로: `@toss-design-system` → TDS v1 → v2

> 사주앱 적용: **SplitTextField**(생년월일 8자리 분할 입력), **NumericSpinner/Keypad**(출생시각), **Rating**(궁합 점수 시각화 대체), **Chart**(오행 밸런스 레이더), **BottomSheet**(음/양력 선택)이 정확히 우리가 필요한 컴포넌트다. 다만 앱인토스 UI Kit 11종에는 포함돼 있지 않으므로 **직접 구현 필요** 가능성이 높다. 부족한 컴포넌트는 채널톡으로 요청 가능(디자인 도구 FAQ).

### 2-3. 타이포그래피 스케일 (TDS React Native `foundation/typography` 원문)

| 토큰 | Font Size | Line Height | 용도 |
|---|---|---|---|
| Typography 1 | 30 | 40 | 매우 큰 제목 |
| Typography 2 | 26 | 35 | 큰 제목 |
| Typography 3 | 22 | 31 | 일반 제목 |
| Typography 4 | 20 | 29 | 작은 제목 |
| Typography 5 | 17 | 25.5 | 본문 |
| Typography 6 | 15 | 22.5 | 작은 본문 |
| Typography 7 | 13 | 19.5 | 부가 정보 |

- `subTypography 1~13`: 중간 사이즈(29 → 11) 보간 토큰
- Weight: **Light / Regular / Medium / Semibold / Bold** (5단계)
- 라인하이트 비율은 대체로 **1.33~1.5** 사이

**접근성(큰 텍스트) 배율** — 문서 원문:
- iOS: 100%, 110%, 120%, 135%, 160%, 190%, 235%, 275%, 310%
- Android: `font_size × NN% × 0.01`
- 문서 지침: *"고정값 하드코딩을 피하고, 사용자가 큰 텍스트 접근성 설정을 켰을 때 동적으로 조정되는 추상화된 토큰을 사용하라"*

> 사주앱 적용: 사주 명식(천간지지 한자)은 **310% 확대 시 8칸 그리드가 깨진다.** 명식 표는 확대 시 그리드 → 세로 리스트로 전환하는 반응형 폴백을 반드시 준비.

### 2-4. 컬러 시스템

**팔레트 (TDS React Native `colors` 원문)**

```js
import { colors } from '@toss/tds-react-native';
<View style={{ backgroundColor: colors.blue500 }} />
```

| 시리즈 | 범위 | 확인된 양 끝값 |
|---|---|---|
| Grey 50~900 | 9단계 | `#f9fafb` → `#191f28` |
| Blue 50~900 | 9단계 | `#e8f3ff` → `#194aa6` |
| Red 50~900 | 9단계 | `#ffeeee` → `#a51926` |
| Orange / Yellow / Green / Teal / Purple | 각 9단계 | 값 미확인 `[미검증]` |
| Grey Opacity | 2%~91% 반투명 | 레이어링용 |

배경 시맨틱 토큰: white / light grey / layered / floating surface

**컬러 시스템 재설계 (toss.tech, 7년 만의 업데이트)**
- **OKLCH 색공간** 도입 — "인지적으로 균일한 색공간"으로 명도 통일. 기존에는 같은 스케일 컬러의 명도가 달라 "리스트에서 같이 썼을 때 얼룩덜룩해 보이는" 문제 발생
- 토큰 계층: **Base → Semantic → Component**
- 네이밍 규칙: `[Target]-[Role]-[Variant]` (예: `fill-brand`, `button-fill-primary`)
- 파이프라인: Figma **Token Studio** → GitHub PR 자동 생성 → 빌드 시점 오류 감지
- 라이트/다크 명도 기준 불일치를 해소하는 것이 업데이트의 주요 목표 중 하나

**비공식 3rd-party 정리(oh-my-design.kr)** — 공식 문서로 교차검증되지 않음 `[미검증]`
- Primary `#3182f6`, Primary Hover `#2272eb`
- Foreground `#191f28`, Body `#4e5968`, Muted `#8b95a1`
- Surface `#f2f4f6`, Border `#e5e8eb`, Danger `#e42939`
- Marketing Weak BG `#e8f3ff` / Weak FG `#1b64da`
- Spacing 4/6/8/16/24/32px, Radius 4/6/8/10/14/16px
- 웹 타이포: H1 36/700/54, H2 30/600/45, H3 24/600/36, H4 22/600/33, Body 16/400/24, Body Small 14/400/21

> `#3182f6`는 앱인토스 UI/UX 가이드의 브랜드 컬러 예시 헥스와 정확히 일치 → 토스 Primary Blue로 신뢰 가능.

### 2-5. TDS의 생산성 효과 (toss.tech 원문 수치)

- TDS 도입 후 **약 3~5배 생산성 향상**
- 동일 제작 시간에 **화면 30개 → 90개**
- "월요일에 제품 개발하고 남은 화수목금은 사용자를 만날 수 있음"
- 메뉴 컴포넌트 개선 근거 데이터: **체크 아이콘이 우측 옵션의 약 50% 사용**, **5자 이상 긴 단어가 전체의 절반 이상**
- 조직 구조: **디자인 플랫폼 팀**(컴포넌트 제작) ↔ **메이커/사일로**(화면·제품 제작)

## 3. 토스 UX 라이팅 규칙 (운세 문구 톤 설계 근거)

### 3-1. 앱인토스 공식 UX 라이팅 원칙 (문서 원문)

| 원칙 | 규칙 | Before → After |
|---|---|---|
| 기본 톤 | "제품 안의 모든 문구는 **해요체**로 써요" | — |
| 능동형 우선 | `~었` 제거로 현재감 강조 | "됐어요" → "했어요" |
| 긍정형 표현 | 에러 메시지도 긍정 프레임 유지 | "없어요" → "있어요" |
| 캐주얼한 경어 | 과공대 제거 | "~시겠어요?" → 제거 / "계시다" → "있다" / "께" → "에게" |
| 문법 단순화 | `{명사}+{명사}` 조합 회피, 한자어 → 동사형 | "생년월일 정보 입력" → "생년월일을 알려주세요" |

### 3-2. 토스의 8가지 라이팅 원칙 (커뮤니티 정리, toss.tech 원문 미확인 `[미검증]`)

1. **Predictable hint** — 다음 화면을 예상할 수 있는 힌트가 있는가?
2. **Weed cutting** — 의미 없는 단어를 모두 제거했는가?
3. **Remove empty sentences** — 의미 없는 문장을 모두 제거했는가?
4. **Focus on key message** — 정말 중요한 메시지만 전달하는가?
5. **Easy to speak** — 이해하기 어려운 용어를 쓰지 않았는가?
6. **Suggest than force** — 특정 행동을 강요하거나 공포감을 주지 않는가?
7. **Universal words** — 모두가 이해할 수 있고 모두에게 무해한가?
8. **Find hidden emotion** — 정보 전달을 넘어 사용자 감정에 공감했는가?

> **6번이 사주앱의 최대 리스크.** "이대로면 올해 큰 손해를 봅니다" 류의 공포 마케팅 문구는 원칙 위반 + 다크패턴 정책 위반 이중 리스크. 흉(凶) 결과는 반드시 **행동 제안형**으로 변환: "올해 3월은 계약을 천천히 검토하면 좋아요."

### 3-3. 에러 메시지 시스템 (toss.tech)

- 핵심 개념: **"Navigating error"** — 에러 메시지는 사용자를 다음 화면으로 **안내**하는 역할
- 상황별로 **제목 / 설명 / 버튼 텍스트**를 분리 설계, 반복 상황 문구는 규격화
- 개발자용: 에러 메시지 라이브러리(컴포넌트 직접 호출) / 디자이너용: Figma 내 템플릿 검색·미리보기

> 사주앱 적용 에러 3종을 미리 규격화: ① 출생시각 미상 ② 만세력 범위 밖 생년월일(1900년 이전 등) ③ 궁합 상대 정보 미입력. 각각 제목/설명/버튼을 3필드로 고정 정의.

## 5. 온보딩 UX: 생년월일·출생시각 입력 설계

### 5-1. 근거 리서치 요약

**NN/g (Date-Input Form Fields)**
- 캘린더 피커: "1년 이내" 이벤트에 적합. 먼 과거(생일)엔 부적합
- 스크롤 데이트 피커: 날짜가 많으면 좌절감 유발
- **드롭다운 분할 필드: 명시적으로 권장하지 않음** (interaction cost 증가)
- **텍스트 입력이 가장 효율적** — 특히 과거 날짜(생일)
- 옵션이 **10개 이하**일 때만 드롭다운, 불가 날짜는 disable
- 구분자(대시/공백/슬래시/점)와 선행 0을 **모두 수용**해야 함
- `11/81/17` 같은 잘못된 날짜에 피드백 제공
- **생년월일은 130년보다 오래된 날짜 선택 차단**
- 국제 사용자 대상이면 월을 **철자로** 표기

**Smashing Magazine (Birthday Picker)**
- 권장 패턴: **3-input(Day/Month/Year) 분리 필드**
- 사용자 멘탈 모델 = "8자리 숫자 문자열"
- 라벨은 **필드 위**에 (플로팅 라벨 X), 입력 예시·설명 포함
- **강제 auto-advance 금지** — 수동 이동 허용, 포커스 스타일 명확히
- 입력 속도: **연속 8타** vs 드롭다운 수십 탭
- 검증은 **필드 단위**로, 구체적 메시지 제공
- Adam Silver / GOV.UK 패턴 인용: *"수년간 테스트했지만 이 방식에서 단 하나의 문제도 발견하지 못했다"*
- **랜덤 기본값 절대 금지** — 생일 입력에서 대량 스크롤 유발

**Mobiscroll 블로그(검색 결과)**: 생년월일 선택에서는 스크롤러 컴포넌트가 UX상 유리하다는 반대 주장도 존재 — 다만 12(월)×31(일)×118(년) 옵션을 훑는 손가락·인지 비용이 크다는 점은 동일하게 지적 `[미검증 — 원문 미열람]`

### 5-2. 사주앱 온보딩 권장 설계 (5단계 퍼널)

```
S0 인트로(1탭)  →  S1 생년월일  →  S2 음/양력  →  S3 출생시각  →  S4 성별
                                                          →  S5 MBTI(선택) → S6 혈액형(선택)
                                                          → 결과 로딩 → 결과
```

| 단계 | 입력 방식 | 이탈 방지 장치 |
|---|---|---|
| S0 인트로 | CTA 1개 (`BottomCTA`) | 진입 즉시 바텀시트 금지 규칙 준수. 정적 화면 |
| S1 생년월일 | **8자리 숫자 키패드 단일 필드**(`YYYYMMDD`) + 실시간 마스킹 `1994.03.21` | 자동 포커스, 8자 입력 완료 시 다음 버튼 활성 |
| S2 음/양력 | **Segmented Control 3분기**: 양력 / 음력(평달) / 음력(윤달) | 기본값 **양력** 선택 상태. "모르면 양력이에요" 헬프 텍스트 |
| S3 출생시각 | **2단 구성**: ① `시간을 몰라요` 큰 토글(상단 배치) ② 12지시(자시~해시) 또는 24시간 휠피커 | **"모름"을 1순위로 노출** — 국내 사용자 상당수가 출생시각 미상 |
| S4 성별 | 2-way Segmented (남/여) | 필수 최소화 |
| S5 MBTI | 4축 × 2택 세그먼트 (E/I, N/S, T/F, J/P) 또는 16그리드 | `모르겠어요 → 간이 진단 4문항` 서브 퍼널 |
| S6 혈액형 | A/B/O/AB 4-chip + `모름` | 선택 스킵 가능 |

**입력 검증 규칙 (NN/g 근거 반영)**
- 연도 하한: **1900년**(만세력 데이터 범위 기준으로 조정) / 상한: 오늘
- 130년 초과 과거 날짜 차단
- 구분자 `.` `-` `/` 붙여넣기 모두 허용, 정규화 후 저장
- 잘못된 날짜(예: `19940231`)는 **필드 하단 인라인 에러**, 상단 토스트 금지

**"시간 모름" 처리 전략**
1. 미상 시 사주 4주 중 **시주(時柱)를 제외한 3주만 계산**하고, 결과 화면에 "시주는 계산하지 않았어요" 뱃지 노출
2. 시주 미상 시 정확도가 떨어지는 항목(직업운·자녀운 등)에 흐린 처리 + "출생시각을 입력하면 볼 수 있어요" CTA → **자연스러운 재입력 유도이자 무료 → 심화 전환 지점**
3. 이 CTA는 다크패턴 3번(선택지 부재)에 걸리지 않도록 **닫기 가능**해야 함

**이탈률 낮추는 단계 설계 원칙**
- 화면당 질문 **1개** (Progressive Disclosure)
- 상단에 **진행 인디케이터**(4/6) — 남은 비용을 명시
- **S1~S4만 필수, S5~S6는 스킵 가능**하게 하여 필수 퍼널 길이를 4로 유지
- 각 단계 응답 즉시 **로컬 저장 + use-funnel 히스토리** → 뒤로가기 시 값 보존
- 마지막 단계에서만 회원 식별/로그인 요구 (있다면)

## 7. 공유·바이럴 설계

### 7-1. 공유 API 실체

**텍스트 공유** (`@apps-in-toss/web-framework` / `@apps-in-toss/framework`)

```ts
function share(message: { message: string }): Promise<void>;
```

```tsx
import { share } from '@apps-in-toss/web-framework';

async function handleShare() {
  await share({ message: '공유할 메시지' });
}
```

**딥링크 + OG 이미지가 붙은 공유 링크 생성**

```ts
function getTossShareLink(url: string, ogImageUrl?: string): Promise<string>;
```

```tsx
const tossLink = await getTossShareLink(
  'intoss://my-app/result?id=abc123',
  'https://cdn.example.com/og/abc123.png',   // 반드시 https:// 절대경로
);
await share({ message: tossLink });
```

- `url`: `intoss://`로 시작하는 딥링크. `intoss://my-app`, `intoss://my-app/about?name=test` 형태
- 반환된 링크는 **토스 앱 설치 시 지정 화면으로 직행**, 미설치 시 앱스토어/플레이스토어로 이동
- **출시 전 테스트 스킴**: `intoss-private://appsintoss?_deploymentId=<ID>` — 쿼리 파라미터 URL-encoding 필수

### 7-2. OG 이미지 규격

| 항목 | 규칙 |
|---|---|
| 사이즈 | **1200 × 600 px** |
| 파일 포맷 | 문서에 명시 없음 (고화질 강조만) `[미검증]` |
| 텍스트 | 과도한 텍스트 금지. "눈길을 과도하게 끄는 크기나 디자인의 텍스트는 사용할 수 없어요". 로고+슬로건은 적절한 크기·위치면 허용 |
| 금지 | 비속어, 은어, 정치적 표현, 민감·부적절 용어 |
| 노출 | "카카오톡 같은 소셜 플랫폼에서 공유될 때" 썸네일로 노출 |

> **중요 제약**: 네비게이션 바 기본 공유 버튼에는 **커스텀 OG 이미지 적용 불가**(공식 답변 확인). 콘솔에서는 로고/썸네일 항목만 지원하고, `getTossShareLink()`의 이미지 파라미터는 **커스텀 공유 링크에만** 작동. 프레임워크에 네비바 공유를 제어하는 훅/설정 없음. 담당자(Dylan)가 내부 논의 예정이라 답했으나 일정 미정.
> → **결론: 결과 화면 안에 자체 "공유하기" 버튼을 반드시 배치**해야 개인화 OG 카드를 태울 수 있다.

### 7-3. 결과 이미지 카드 설계

- 사용자별 동적 OG 생성 필요 (예: `/api/og?score=92&a=ENFP&b=ISTJ`)
- 1200×600 캔버스 안에 **텍스트 최소화** 규칙을 지키려면: 큰 숫자 점수 1개 + 두 사람의 심볼 + 작은 앱 로고 정도가 상한
- 결과 상세 텍스트를 이미지에 다 넣으면 "과도한 텍스트" 반려 리스크
- 카카오톡 공유는 링크를 카톡으로 내보내면 OG가 붙는 구조. **Kakao JS SDK 직접 연동은 외부 링크 이동 정책 및 미니앱 샌드박스 제약과 충돌 가능** `[미검증 — 별도 확인 필요]`

### 7-4. 공유 리워드 (초대 바이럴)

- 정의: "연락처 모듈을 사용해서 토스 사용자의 연락처를 불러오고, 공유 완료 사용자에게 리워드를 제공하는 기능". 게임/비게임 모두 사용 가능, **토스 알림 푸시**로 진행
- **발송 제한: 하나의 리워드 ID당 사용자 1명에게 하루 1회.** 일 단위 초기화. 다른 리워드 ID는 독립 적용
- 콘솔 설정 항목: **리워드 이름**(관리자용) / **리워드 단위**(하트·보석·포인트 등 사용자 인식명) / **수량**

- 연동 SDK: `contactsViral`

> 사주앱 적용: 리워드 단위를 "운세 열쇠" 같은 소모성 재화로 정의 → 친구 초대 1회당 열쇠 1개 → 열쇠로 심화 리포트 1개 해제. 현금성 아님 + 사행성 아님 조건 충족.

## 9. 성과 측정 — 로그 이벤트 설계

앱인토스 Analytics API (문서 원문):

| 함수 | 용도 | 예시 |
|---|---|---|
| `Analytics.screen` | 화면 진입 | `Analytics.screen({ log_name: "checkout_entry" })` |
| `Analytics.impression` | 요소 노출 | `Analytics.impression({ log_name: "banner_impression" })` |
| `Analytics.click` | 클릭 | `Analytics.click({ log_name: "purchase_button" })` |
| `Analytics.log` | 커스텀 | `Analytics.log({ log_name: "completed", params: {...} })` |

**전환 지표 설정**: 콘솔 → 워크스페이스 → 미니앱 → `핵심 지표`. **최대 3개 등록, 대표 전환 1개.** "첫 결제"·"토스페이 결제"·"인앱 상품 구매" 템플릿 제공. 이벤트를 **OR 조건**으로 조합 가능. 처음 생성한 지표가 자동으로 대표 전환.

**사주앱 로그 설계 초안**

```ts
// 온보딩 퍼널 (이탈 지점 특정용)
Analytics.screen({ log_name: 'onb_intro' });
Analytics.screen({ log_name: 'onb_birthdate' });
Analytics.screen({ log_name: 'onb_calendar_type' });
Analytics.screen({ log_name: 'onb_birthtime' });
Analytics.click ({ log_name: 'onb_birthtime_unknown' });   // "시간 몰라요" 비율
Analytics.screen({ log_name: 'onb_gender' });
Analytics.screen({ log_name: 'onb_mbti' });
Analytics.click ({ log_name: 'onb_mbti_skip' });
Analytics.screen({ log_name: 'onb_blood' });

// 결과 & 전환
Analytics.screen    ({ log_name: 'result_main' });
Analytics.impression({ log_name: 'paywall_deep_report' });  // 페이월 도달률
Analytics.click     ({ log_name: 'paywall_cta_purchase' });
Analytics.log       ({ log_name: 'purchase_completed', params: { sku, price } });

// 바이럴
Analytics.click({ log_name: 'share_result_card' });
Analytics.click({ log_name: 'share_compat_invite' });
Analytics.log  ({ log_name: 'invite_reward_granted' });
```

**핵심 지표 3개 후보 (대표 전환 1개 = 결제 완료)**
1. `purchase_completed` (대표)
2. `share_result_card` (바이럴)
3. `result_main` 도달 (온보딩 완주)
