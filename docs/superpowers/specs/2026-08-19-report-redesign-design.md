# 사주믹스 리포트 재설계 — 3D 홈 · AI 해석 · 흐름 개편

작성일 2026-08-19 · 상태: 승인 대기

## 1. 문제

계산 엔진은 정확한데 **그 결과를 못 보여주고 있다.**

현재 결과 화면은 `庚午 庚辰 庚戌 癸未` 표로 시작해 문단 11개가 세로로 쌓인다. 오행 점수는
`목 4.6 화 20.5 토 20.4 금 23 수 11.5` 처럼 숫자로만 나열되고, 십신·신살 한자가 문단마다 등장한다.
**만세력 도구처럼 생겼지, 나를 읽어주는 앱처럼 생기지 않았다.**

참조로 받은 [Jamo](https://apps.apple.com/kr/app/자모-jamo-오늘의-사주/id6759788071) 는 같은 재료로
정반대 선택을 했다 — "복잡한 도표나 어려운 한자 없이", "나의 오행을 닮은 3D 홈 화면".

## 2. 목표 / 비목표

**목표**
- 첫 화면에서 **"나는 어떤 사람인가"가 한눈에** 들어온다
- 계산 결과를 시각으로 보여준다 (오행 분포, 강약)
- AI 가 ① 글을 사람처럼 쓰고 ② 규칙이 못 하는 네 체계 교차 해석을 한다
- **첫 결과까지 10초 이내** (현재 94초)

**비목표 (이번 범위 밖)**
- 한자 노출 정책 변경 — 다음 라운드
- 계산 정확도(墓庫 지장간 등) — 별도 프로젝트
- 결제·광고·로그인
- 런타임 3D(three.js/GLB) — §6 참고

## 3. 흐름

```text
① 입력    자동 프리필(마운트 시) → 남는 필수 입력은 출생시각 하나
② 연출    "여덟 글자를 읽는 중" — AI 요약 대기 (3~8초)
③ 홈      오행 오브젝트 + 한 단어 + 한 문장 + 오행 분포
④ 깊이    카드 6~8장. 탭하면 펼침. 근거 카드는 여기서만
⑤ 상담    자유 질문 → 스트리밍 답변
⑥ 궁합    상대 생년월일 → 관계 해석
```

현재 2단계(`onboarding` → `result`)를 4단계로 늘린다. 라우터는 여전히 넣지 않는다 —
`App.tsx` 의 판별 유니온에 화면을 추가한다(되돌아갈 곳이 선형이고 URL 이 사용자에게 안 보인다).

## 4. 화면 설계

### ③ 홈

세 덩어리다. 위에서부터:

1. **오브젝트** — 가장 강한 오행의 3D 렌더 이미지. 화면 폭 전체, 높이 약 40%
2. **한 단어 + 한 문장** — AI 생성. 예: "버티는 사람" / "정한 방향으로는 곧게 가되, 시작 전에 오래 잽니다"
3. **오행 분포** — 막대 5개. 엔진 점수 그대로, 합 80 고정

숫자를 화면이 다시 계산하지 않는다(C00 §H). 렌더러는 엔진 값을 배치만 한다.

### ④ 깊이 읽기

카드 한 장 = 지금의 섹션 하나. 접힌 상태에서 **제목 + 한 줄 요약**만 보이고, 탭하면 본문과
근거 카드가 펼쳐진다. 카드 목록은 `SECTION_IDS` 를 정본으로 삼아 현재 11섹션 체계를 그대로 쓴다 —
섹션이 늘거나 줄면 카드도 따라간다.

### ⑤ AI 상담

입력창 + 답변. 질문은 **팩트팩 범위 안에서만** 답하도록 시스템 프롬프트가 제한한다(현행 규율 유지).
사주 밖 질문(의료·법률·투자)은 거절 문구로 되돌린다.

## 5. AI 구조 — 94초를 어떻게 없애는가

현재는 한 번의 호출로 3,000자를 뽑아 **93.8초**가 걸린다(실측, opus-5 + effort high).
호출을 쪼갠다.

| 호출 | 출력 | 예상 지연 | 모델/effort |
|---|---|---|---|
| `summary` 한 단어 + 한 문장 | ~100자 | **3~8초** | opus-5 / low |
| `card:<id>` 카드 본문 | 각 ~400자 | 각 10~20초, **병렬** | opus-5 / medium |
| `ask` 상담 답변 | 가변 | **스트리밍** | opus-5 / medium |

### 왜 원가가 크게 안 오르나

시스템 프롬프트 + 팩트팩 + 지식카드가 모든 호출에 공통이다. 프롬프트 캐싱의 브레이크포인트를
그 접두에 걸면 **두 번째 호출부터 입력이 캐시 읽기 단가**(opus-5 기준 $0.50/1M, 원가의 1/10)로 떨어진다.
출력 총량은 분할 전과 비슷하므로 출력 비용은 거의 동일하다.

⚠ 캐시는 프리픽스 일치다. 카드별 호출에서 **지시문이 접두를 바꾸면 캐시가 깨진다** — 카드 id 는
반드시 user 턴 **끝**에 붙인다.

### 폴백

현행 구조를 유지한다. 규칙 기반 리포트가 **먼저 그려지고** AI 결과가 도착하면 갈아끼운다.
서버가 없거나 죽어도 화면은 채워진다. 카드 단위로 쪼개졌으므로 폴백도 **카드 단위**가 된다 —
6장 중 2장만 실패하면 그 2장만 규칙 기반으로 남는다.

### 서버

`server/` 를 blend 서버(156.228.4.156)에 올린다. systemd + Caddy 리버스 프록시.
`ANTHROPIC_API_KEY` 는 `/etc/sajumix/interpret.env` (0600). 상세는 `server/README.md` §배포.

앱은 `VITE_INTERPRET_API_BASE` 로 주소를 받는다. **비어 있으면 서버를 부르지 않는다**(현행).

## 6. 에셋 — Higgsfield

**런타임 3D 를 넣지 않는다.** 초기 청크가 이미 1,341 kB(gzip 424 kB)이고 대부분이 TDS다.
three.js + GLB 를 얹으면 미니앱에서 감당이 안 된다. **3D 렌더 룩의 정지 이미지**를 굽는다 —
보이는 결과는 같고 무게는 한 자릿수 분의 일이다.

| 세트 | 수량 | 용도 | 우선순위 |
|---|---|---|---|
| 오행 오브젝트 | 5종 × 3변형 = 15 | 홈 히어로 | **1** |
| 오행 배경 톤 | 5 | 홈 배경 | **1** |
| 십신 그룹 심볼 | 5 | 카드 아이콘 | 2 |
| 별자리 | 12 | 별자리 카드 | 2 |
| 십이지 | 12 | 일지 띠 | 3 |
| 궁합 상태 | 4 | 관계 화면 | 3 |
| 연출 | 3 | ② 화면 | 2 |
| 합계 | 56 | | |

**우선순위 1(20장)을 먼저 굽고 스타일을 확정한 뒤** 나머지를 진행한다 — 스타일이 틀리면 56장이
통째로 버려진다. 산출물은 `app/src/assets/` 가 아니라 **`docs/store/` 처럼 별도 디렉터리**에 두고
빌드 시 필요한 것만 번들에 넣는다(오행 5종은 전부 필요하지만 십이지 12종은 하나만 쓰인다 —
전부 번들하면 낭비다. 동적 import 또는 CDN 배치를 구현 계획에서 결정한다).

## 7. 코드 구조

| 영역 | 변경 |
|---|---|
| `App.tsx` | 화면 유니온에 `home`·`detail`·`ask` 추가 |
| `pages/` | `HomePage` · `DetailPage` · `AskPage` 신설. `ResultPage` 는 `DetailPage` 로 흡수 |
| `features/report` | 카드 단위 상태 관리(`useInterpretation` 확장) |
| `shared/interpret` | 요청 종류에 `summary` · `card` · `ask` 추가. 프롬프트·스키마·검증 각각 |
| `server/` | 엔드포인트 분화 + 스트리밍(SSE) |
| `shared/assets` | 오행→이미지 매핑 (신설) |

`shared/interpret` 의 기존 규율은 유지한다 — 프롬프트는 서버에서만 만들고, 화면은
`shared/interpret/ui` 에서만 가져온다.

## 8. 검증

- **단위** — 프롬프트 조립·응답 검증·오행→에셋 매핑은 순수함수로 두고 전건 테스트
- **화면** — `npm run ui-smoke` 확장. 오행 5종 홈이 전부 렌더되는지 스윕, 카드 펼침, 상담 입력
- **실호출** — `server/scripts/smoke.ts` 를 호출 종류별로 확장. 분할 후 실제 지연·원가 재측정
- **폴백** — 서버 없이 전 화면이 규칙 기반으로 채워지는지

레이아웃 회귀는 `ui-smoke` 만 잡는다는 사실이 이번 라운드에도 유효하다(휠 높이 버그 참고).

## 10. 위험

- **에셋 스타일 불일치** — AI 생성물 56장의 톤이 안 맞으면 싸구려로 보인다. 우선순위 1 로 먼저 검증
- **분할 호출 원가** — 캐시가 예상대로 안 먹으면 원가가 오른다. 분할 직후 실측으로 확인
- **상담 기능의 검수 위험** — 생성형 AI 자유 입력은 앱인토스 정책 검토 대상일 수 있다.
  구현 전 `apps-in-toss-open-policy-checker` 로 확인한다
- **개인정보처리방침 개정** — 서버 호출이 생기면 현재 "서버로 전송하지 않습니다"가 거짓이 된다.
  **AI 연결과 방침 개정은 같은 배포에 나가야 한다**
